# AI agent kit

An AI coding agent can build a storefront on this SDK quickly, but only from
the real contract. Left alone, it fills gaps with a generic e-commerce pattern:
a client-side total, a hardcoded language list, its own `fetch` to the store
API, or an endpoint that does not exist. This kit gives it the boundaries.

Building an editable theme instead? Use the [Theme SDK agent kit](/sdk/theme/agents)
too: it covers definitions, documents and Wocart Studio.

## Set up in two minutes

```bash
mkdir -p .agents/skills/wocart-storefront
curl -fsSL https://docs.wocart.store/agents/wocart-storefront/SKILL.md \
  -o .agents/skills/wocart-storefront/SKILL.md
```

For Claude Code, copy the same file to `.claude/skills/wocart-storefront/`.
<a href="/agents/wocart-storefront/SKILL.md">Read the skill</a>: the version to
pin, seventeen rules, a build order, the verification commands and when to
stop.

Add a short `AGENTS.md` at the repository root with your store's facts (API
origin variable, languages, which of cart, reviews, OTP and Turnstile are on)
and the three commands; the
<a href="/agents/theme/AGENTS.md">theme template</a> is a starting point. Then give the
agent the documentation index, `https://docs.wocart.store/llms.txt`; every page
is also Markdown at its URL plus `.md`.

## Prompts you can copy

### Start a storefront

```text
Build a storefront in this empty Astro project following
.agents/skills/wocart-storefront/SKILL.md and
https://docs.wocart.store/sdk/storefront/quickstart.md, with exact pins of
@wocart/storefront. Store facts: API origin in COD_SERVER_URL, key in
STORE_API_KEY (server only), languages <ar primary, fr>, cart <on/off>,
reviews <on/off>, OTP <on/off>.

First give me the page map: each page and the SDK reads it uses. After I
approve it, build the shared files (client, middleware with unavailableStoreConfig as the fallback,
routes), then one page at a time, running `npx astro check`, `npx vitest run`
and `npx astro build` after each and showing me the output.
```

### Add the order form

```text
Add the product order form following
https://docs.wocart.store/sdk/storefront/checkout.md: the placeOrder action
with placeOrderInput and executePlaceOrder, runFormAction in the middleware,
the redirect to /thank-you from the product page with Astro.getActionResult,
bindCheckoutKey on the form, and the fields shown according to
config.checkoutForm. A refused order must re-render the form with its error and
the shopper's input kept. Prove it against the running dev server: one refused
and one placed order.
```

### Add the basket and delivery quote

```text
Add a basket drawer, shown only when config.cartEnabled, following
https://docs.wocart.store/sdk/storefront/basket.md and
https://docs.wocart.store/sdk/storefront/delivery.md. The basket is
createBasketStore; the displayed total comes from createQuoter through the
same-origin cart route, never from getSubtotal(). Show the fee and total from
the quote when a destination is chosen, "calculated later" before, and disable
checkout when delivery is not available or a line is blocked.
```

### Audit a storefront

```text
Audit this storefront against .agents/skills/wocart-storefront/SKILL.md and
report with file and line: the key or any server import reaching a browser
script; totals or fees computed in the browser; hardcoded language lists;
internal links not passed through localizeHref; hand-written proxies; reads
whose null or empty result is not handled; a missing 404 for null. Fix nothing
until I approve the list.
```

### Find why something is empty

```text
<Describe the symptom, e.g. "the home page shows no products".> Diagnose it:
check the client's onError output (operation and code), COD_SERVER_URL and the
key, and whether the server is reachable. Report the cause with evidence
before changing anything.
```

## The rules an agent must not guess

| Rule | Why |
| --- | --- |
| The key stays on the server; browser code imports only the root and `/review-media` | A browser key exposes the whole store |
| The server owns money; a basket total is display, the quote is money | `localStorage` is editable by anyone |
| One client per request; one module creates it | Caches and language must not leak between visitors |
| Languages come from `config.locales` and `resolveStoreRequest` | The store, not the theme, decides which exist |
| Every internal link goes through `localizeHref` | Otherwise a French shopper falls back to the primary language |
| `null` on a detail read is a real 404 (`notFound(Astro)`) | A redirect or a blank 200 is a soft 404 for search and ads |
| Routes are the SDK's factories | A hand-written proxy is a second contract that will drift |
| Redirect from the page, never the middleware | An Astro 7 action result lives for one response |
| Fire only the pixel and event `orders.tracking` returns | A wrong event double-counts or misses the sale |
| Pin `@wocart/storefront` 3.0.0 exactly | 3.x reads platform v7; 2.x reads a v7 store as unreadable |
| An unreadable store is `unavailableStoreConfig(…)` | A hand-written config falls behind the config's shape and can look like a working checkout |
| Platform links come from `storefrontPath`; WhatsApp links from `whatsAppContact` | A hand-written path or `wa.me` link ignores the platform's paths and the merchant's number, texts and message rules |
| Images resolve with `config.media` | The store's media host can be ImageKit, Cloudflare or direct; a hard-coded host breaks |
| No store fact in your own words | Delivery reach, hours or a phone number written as copy is false on the next store |

## Check the agent's work

- [ ] `npx astro check` (0 errors), `npx vitest run` (all passing) and
      `npx astro build` (complete) were run and shown. Run them once yourself.
- [ ] No import of `/server` or `/astro` in a `<script>` or island; no key in
      a `PUBLIC_*` variable.
- [ ] No `price * quantity` shown as the amount to be charged.
- [ ] No array like `["ar", "fr"]`; no `if (locale === "ar")` for routing.
- [ ] No `wa.me` link, no `config.whatsapp` read, no hand-written platform
      path; no copy that states a fact about the store.
- [ ] Every read handles `null`, `[]` or `{}`; every detail page answers 404.
- [ ] Every new route is an SDK factory export; every new import exists in the
      declarations.
- [ ] If the agent says an API is missing, check the declarations: either it
      really is (report it) or the agent did not look.

<Callout type="caution" title="Install the skill before the first prompt">
An agent that has not read these pages reconstructs Wocart from other stores
it has seen, and the result looks right and is wrong in exactly the places
that cost money.
</Callout>
