# Build a complete theme

This page continues the project from the [quick start](/sdk/theme/build). By
the end the theme has everything a real store needs from an editable theme:

| Feature | What you add |
| --- | --- |
| A header on every page | An **area**, composed and edited once, reading the store's menu |
| A product page | A **template surface** with a required section, a slot for blocks, and a **fixed** order form |
| Ordering | An Astro action that places a cash-on-delivery order, with errors shown in place |
| The order confirmation | The **thank-you surface**, with the store's WhatsApp through `whatsAppContact` |
| Colors and spacing | Store **settings** with color schemes, and a **style** field |
| Wocart Studio preview | The preview route, its bridge and its security headers |
| Publishing | The revalidation route Studio calls after a publish |
| Proof | Render tests and tests for every fallback the docs promise |

Every file below is complete: create it, or replace the quick start's version
with it. The finished project type-checks, its tests pass, and it builds for
Cloudflare and for Vercel.

## 2. The product template

A **template** surface renders every resource of its kind with one document:
one `product` document renders every product page. Its sections read the
product named by the URL through `context.params`.

First, one helper that reads the route's product through the page's read cache,
so every section that needs it shares a single request:

```ts title="src/theme/product.ts"
import type { LoadContext } from "@wocart/theme";

export function loadProduct({ storefront, context, reads }: LoadContext) {
  const handle = context.params?.handle;
  if (handle === undefined) return Promise.resolve(null);
  return reads.get(`product:${handle}`, () => storefront.products.get(handle));
}
```

The product section draws the product, places the blocks of its `details`
slot, and places its fixed order form:

```astro title="src/theme/components/product/ProductMain.astro"
---
import Block from "@wocart/theme/astro/Block.astro";
import Blocks from "@wocart/theme/astro/Blocks.astro";
import { hasBlocks, type BlocksHandle } from "@wocart/theme/astro";
import { formatMoney, type Product } from "@wocart/storefront";

interface Props {
  product: Product | null;
  blocks: BlocksHandle;
}

const { product, blocks } = Astro.props;
const store = Astro.locals.store;
---
{product && (
  <section class="product">
    <h1>{product.name}</h1>
    <p>{formatMoney(product.price, { symbol: store.config.currencySymbol, locale: store.locale })}</p>
    {hasBlocks(blocks, "details") && (
      <div class="product__details"><Blocks of={blocks} slot="details" /></div>

```

A block a merchant may add to that slot — formatted text:

```astro title="src/theme/components/product/ProductText.astro"
---
import { richTextToHtml, type InferProps } from "@wocart/theme";
```

`richTextToHtml` escapes every text and attribute and drops any unsafe link,
so its output is safe for `set:html`. Passing `href: store.href` keeps an
internal link in the shopper's language.

The order form. It posts the product to the `placeOrder` action (step 3),
shows the store's wilayas, and fills the communes in the browser:

```astro title="src/theme/components/product/ProductOrder.astro"
---
import { actions, isInputError } from "astro:actions";
import { WILAYAS, type Product } from "@wocart/storefront";

interface Props {
  product: Product | null;
  submitLabel: string;
}

const { product, submitLabel } = Astro.props;
const store = Astro.locals.store;
const t = store.content;
const result = Astro.getActionResult(actions.placeOrder);
const failed = result?.error !== undefined;
const fieldErrors = result?.error && isInputError(result.error) ? result.error.fields : {};
const wilayaName = (wilaya: (typeof WILAYAS)[number]) => (store.locale === "ar" ? wilaya.nameAr : wilaya.name);
---
{product && (
  <form method="POST" action={actions.placeOrder} class="order-form" data-order-form>
    <input type="hidden" name="productId" value={product.id} />
    <input type="hidden" name="productName" value={product.name} />
    <input type="hidden" name="pricePerUnit" value={product.price} />
    <input type="hidden" name="quantity" value="1" />
    <label>{t.fullName}<input name="customerName" required minlength="2" autocomplete="name" aria-invalid={"customerName" in fieldErrors} /></label>
    <label>{t.phone}<input name="phone" type="tel" required autocomplete="tel" dir="ltr" aria-invalid={"phone" in fieldErrors} /></label>
    <label>{t.wilaya}
      <select name="wilayaId" required data-wilaya>
        <option value=""></option>
        {WILAYAS.map((wilaya) => <option value={wilaya.id}>{wilaya.id} - {wilayaName(wilaya)}</option>)}
      </select>
    </label>
    <label>{t.commune}<select name="communeId" required data-commune data-arabic={store.locale === "ar" ? "" : undefined}></select></label>
    {failed && <p role="alert">{t.orderFailed}</p>}
    <button type="submit">{submitLabel}</button>
  </form>
)}

<script>
  import { communesForWilaya } from "@wocart/storefront";
  import { bindEach } from "@wocart/theme/lifecycle";

  bindEach<HTMLFormElement>("[data-order-form]", (form) => {
    const wilaya = form.querySelector<HTMLSelectElement>("[data-wilaya]")!;
    const commune = form.querySelector<HTMLSelectElement>("[data-commune]")!;
    const arabic = commune.hasAttribute("data-arabic");
    const fill = () => {
      commune.replaceChildren(
        ...communesForWilaya(wilaya.value).map((entry) => new Option(arabic ? entry.nameAr : entry.name, entry.id)),
      );
    };
    wilaya.addEventListener("change", fill);
    return () => wilaya.removeEventListener("change", fill);
  });
</script>
```

- **`pricePerUnit` is required for a single-product order**, and display-only:
  the server prices every order from the catalog. Leave it out and the action
  refuses the order as malformed.
- The browser script imports only from `@wocart/storefront`'s root entry and
  `@wocart/theme/lifecycle`, both browser-safe. Never import
  `@wocart/storefront/server` or the theme SDK's root entry in a `<script>`.
- `bindEach` binds each form once — on load, after Astro swaps a page, and
  after Studio's preview swaps the section in — and runs the teardown when the
  form leaves.
- The **checkout's rules are not the theme's**. Which fields a store asks for
  (address, email, custom fields), OTP and bot protection are the merchant's
  settings, enforced by the server. A production form reads
  `store.config.checkoutForm`; see
  [Checkout and OTP](/sdk/storefront/checkout).

```ts title="src/theme/components/product/product.def.ts"
  fixed: [{ name: "order", type: "product-order", label: { ar: "نموذج الطلب", fr: "Formulaire de commande", en: "Order form" } }],
  load: async (context) => ({ product: await loadProduct(context) }),
});
```

| Rule in the definition | What it guarantees |
| --- | --- |
| `role: "order-form"` | This component places orders |
| `fixed: [{ name: "order", … }]` | Every `product-main` renders an order form where its code puts `<Block name="order">`; a merchant edits its button text but can never remove, move or hide it |
| `slots: [{ name: "details", allow, max }]` | Merchants add up to four text blocks there, and nothing else |
| `placement` | `product-main` only at the top level; the others only inside a slot |
| `capabilities` | Studio never offers `product-main` for insertion, and only on the product page |
| Both `load`s read `product:<handle>` | One request per page, however many sections need the product |

`load` returns `product`, and the renderer merges it over the field values, so
the component receives it as a prop. Keep `load`'s keys out of `fields`: a
loaded value wins over a field of the same name.

## 3. Placing the order and confirming it

```ts title="src/actions/index.ts"
import { ActionError, defineAction } from "astro:actions";
import { executePlaceOrder, placeOrderInput } from "@wocart/storefront/astro";
import { getStoreClient } from "../theme/sdk";

export const server = {
  placeOrder: defineAction({
    accept: "form",
    input: placeOrderInput,
    handler: async (input, context) => {
      const result = await executePlaceOrder(input, context.request, getStoreClient());
      if (!result.success) {
        throw new ActionError({
          code: result.errorKind === "shape" ? "BAD_REQUEST" : "UNPROCESSABLE_CONTENT",
          message: result.error,
        });
      }
      return result.data;
    },
  }),
};
```

`placeOrderInput` is the SDK's whitelist of order fields; `executePlaceOrder`
enforces "a basket or a product", forwards the shopper's IP, user agent and
referer, and creates the order. The theme never trusts a price or a total from
the browser: the server computes them.

The product route reads the product, answers a real 404 for an unknown one,
and redirects to the thank-you page after a placed order:

```astro title="src/pages/products/[handle].astro"
---
import { actions } from "astro:actions";
import { notFound } from "@wocart/storefront/astro";
import { storefrontPath } from "@wocart/storefront";
import { createReadCache } from "@wocart/theme/astro";
import StoreLayout from "../../theme/layouts/StoreLayout.astro";
import Sections from "../../theme/sections/Sections.astro";
import { theme } from "../../theme/theme";

const placed = Astro.getActionResult(actions.placeOrder);
if (placed?.data) {
  const query = new URLSearchParams({ order: placed.data.orderNumber });
  return Astro.redirect(`${Astro.locals.store.href(storefrontPath("thankYou"))}?${query}`, 303);
}

const store = Astro.locals.store;
const handle = Astro.params.handle!;
const reads = createReadCache();
const product = await reads.get(`product:${handle}`, () => store.client.products.get(handle));
if (product === null) return notFound(Astro);

const saved = await store.client.pageData.get("product");
---
<StoreLayout title={product.name}>
  <Sections theme={theme} surface="product" document={saved} params={{ handle }} reads={reads} />
</StoreLayout>
```

- The route reads the product **into the same cache** it hands to the
  sections, so the page makes one product request, not three.
- `notFound(Astro)` renders `/404` with status 404 and turns caching off for
  that response: a product published a minute later must not stay hidden.
- A placed order answers `303` to `/thank-you?order=…`; a refused one
  re-renders the form from the same POST with its error in place. The
  middleware's form-action step ([step 7](#7-preview-and-revalidation)) is
  what makes both work.
- `storefrontPath("thankYou")` is `/thank-you`. Never write a platform page's
  path by hand: `storefrontPath` and `STOREFRONT_PAGE_PATHS` are the one list.

### The thank-you page is a surface

The thank-you page is one of the platform's page types (`thankYou`), so the
merchant composes it in Studio like the home page. Its main section shows the
order number and a button that opens the store's WhatsApp with a message
about this order.

A theme reads the store's WhatsApp in **one** place, with its own words for
every text the merchant left empty:

```ts title="src/theme/whatsapp.ts"
import { whatsAppContact, type WhatsAppContact, type WhatsAppPage } from "@wocart/storefront";
import type { StoreContext } from "./store";

export function storeWhatsApp(store: Pick<StoreContext, "config" | "content">, page: WhatsAppPage): WhatsAppContact | null {
  const t = store.content;
  return whatsAppContact(store.config, page, {
    launcher: null,
    caption: null,
    welcome: null,
    cta: t.whatsappCta,
    orderButton: t.whatsappOrderButton,
    messages: { general: t.whatsappGeneral, product: t.whatsappProduct, order: t.whatsappOrder },
  });
}
```

- `whatsAppContact` answers `null` when the store has no WhatsApp: the
  merchant has not set up the WhatsApp button App, or the store cannot be
  read. Render nothing then.
- Every text is the merchant's when they wrote one in the page's language,
  else your word. The message is the page's own template (the merchant's
  product or order message), else the merchant's general one, else yours for
  that kind of page. Your messages may use `{store}`, `{product}`, `{url}` and
  `{order}`.
- `href` is the `wa.me` link with the message in it, already cut to 900
  characters at a word, with ad-click parameters removed from `{url}`. Never
  write a `wa.me` link yourself.


```json title="src/theme/documents/header.area.json"
  "surface": "area:header",
  "sections": [{ "id": "header", "type": "header" }]

```

- A **`menu`** field stores a menu handle; `load` reads the menu. `load`
  receives `props` typed from the fields, so `props.menuHandle` is a `string`
  (it has a default). The loaded value is named `menu`, not `menuHandle`, so it
  does not collide with the field.
- Menu items' `href`s are store paths without a language prefix, or the
  merchant's absolute URL; `store.href` localizes the first and leaves the
  second alone.
- **`colorScheme`** stores a scheme id; **`style`** stores spacing and layout
  *steps*. Neither is CSS. `schemeClass` and `styleClasses` turn them into
  classes from the stylesheet you publish in [step 5](#5-colors-and-spacing).

## 7. Preview and revalidation

Wocart Studio shows a merchant's unsaved draft on the real storefront, in a
frame. It opens `THEME_PREVIEW_PATH` (`/wocart-preview`) with a signed token,
and re-renders by posting the draft back as JSON. After a publish, the platform
posts a different signed token to `REVALIDATE_PATH` (`/wocart-revalidate`).
Both tokens are verified with the deployment's public key,
`WOCART_PREVIEW_KEY`. Without it, both routes answer 404.

The final SDK seam adds the two readers:

```ts title="src/theme/sdk.ts"
import {
  createStoreClient,
  readPreviewRequest,
  readRevalidateRequest,
  type StoreClient,
} from "@wocart/storefront/server";
import { COD_SERVER_URL, STORE_API_KEY, WOCART_PREVIEW_KEY } from "astro:env/server";
import { THEME_KEY } from "./key";

export const storeServerUrl = (): string => COD_SERVER_URL ?? "";

export function getStoreClient(locale?: string): StoreClient {
  return createStoreClient({
    serverUrl: storeServerUrl(),
    apiKey: STORE_API_KEY ?? "",
    theme: THEME_KEY,
    ...(locale === undefined ? {} : { locale }),
    onError: (error) => {
      console.warn(`[my-theme] degraded read: ${error.operation} (${error.code})`);
    },
  });
}

export function readThemePreview(request: Request) {
  return readPreviewRequest(request, { publicKey: WOCART_PREVIEW_KEY, theme: THEME_KEY });
}

export function readThemeRevalidation(request: Request) {
  return readRevalidateRequest(request, { publicKey: WOCART_PREVIEW_KEY, theme: THEME_KEY });
}
```

The final middleware handles the preview route, skips the revalidation route
(it needs no store), and runs a form-posted action before the page renders:

```ts title="src/middleware.ts"
import { defineMiddleware } from "astro:middleware";
import { getActionContext } from "astro:actions";
import { REVALIDATE_PATH } from "@wocart/storefront/server";
import { runFormAction } from "@wocart/storefront/astro";
import { THEME_PREVIEW_PATH } from "@wocart/theme";
import { readThemePreview } from "./theme/sdk";
import { resolvePreviewStore, resolveStoreRequest } from "./theme/store";

export const onRequest = defineMiddleware(async (context, next) => {
  if (context.isPrerendered || context.url.pathname === REVALIDATE_PATH) return next();

  if (context.url.pathname === THEME_PREVIEW_PATH) {
    const preview = await readThemePreview(context.request);
    if (!preview.ok) {
      return new Response(null, { status: preview.status, headers: { "Cache-Control": "no-store" } });
    }
    context.locals.store = await resolvePreviewStore(preview.draft);
    context.locals.preview = { claims: preview.claims, draft: preview.draft, token: preview.token };
    return next();
  }

  const request = await resolveStoreRequest(context.url, context.request.headers.get("Referer"));
  if (request.kind === "redirect") return context.redirect(request.location, request.status);
  context.locals.store = request.store;

  const { action, setActionResult, serializeActionResult } = getActionContext(context);
  await runFormAction({
    action: action && { calledFrom: action.calledFrom, name: action.name, handler: action.handler },
    setActionResult,
    serializeActionResult,
  });

  return request.rewrite === null ? next() : next(request.rewrite);
});
```

```ts title="src/env.d.ts"
/// <reference types="astro/client" />

import type { PreviewClaims, PreviewDraft } from "@wocart/storefront/server";
import type { StoreContext } from "./theme/store";

declare global {
  namespace App {
    interface Locals {
      store: StoreContext;
      preview?: { claims: PreviewClaims; draft: PreviewDraft; token: string };
    }
  }
}
```

- `resolvePreviewStore` renders the store **as the draft would leave it**: the
  draft's settings and text edits over the saved ones, in the draft's language,
  with the Meta pixel off — a preview is not a visit.
- `runFormAction` must run in the middleware, and the page must do the
  redirect: an Astro 7 action result exists only for the response being
  rendered.

The preview route asks the SDK what to show — `previewTarget` picks the surface,
the resource a template previews, and the document — and sets the security
headers:

```astro title="src/pages/wocart-preview.astro"
---
import { previewResponseHeaders } from "@wocart/storefront/server";
import { previewTarget } from "@wocart/theme/astro";
import PreviewBridge from "../theme/components/PreviewBridge.astro";
import StoreLayout from "../theme/layouts/StoreLayout.astro";
import Sections from "../theme/sections/Sections.astro";
import { theme } from "../theme/theme";

export const prerender = false;

const preview = Astro.locals.preview;
const refuse = () => new Response(null, { status: 404, headers: { "Cache-Control": "no-store" } });
if (preview === undefined) return refuse();

const target = await previewTarget(theme, preview.draft, Astro.locals.store.client);
if (target === null) return refuse();

for (const [name, value] of Object.entries(previewResponseHeaders(preview.claims))) {
  Astro.response.headers.set(name, value);
}
---
<StoreLayout>
  <Sections
    theme={theme}
    surface={target.surface}
    document={target.document}
    params={target.params}
    preview={target.area === null}
  />
  <PreviewBridge editor={preview.claims.editor} token={preview.token} />
</StoreLayout>
```

| Header from `previewResponseHeaders` | Effect |
| --- | --- |
| `Cache-Control: private, no-store` | No browser or CDN keeps a draft |
| `Content-Security-Policy: frame-ancestors <editor>` | Only the editor named in the token can frame the page |
| `X-Robots-Tag: noindex, nofollow` | A preview is never indexed |
| `Referrer-Policy: same-origin` | The address, which carries the token, never leaks |

With `preview` set, `InstanceView` brackets every instance with
`<!--wocart:start …-->` / `<!--wocart:end …-->` comments the bridge reads. A
shopper's page carries none. While Studio edits the header, the page's own
sections render unmarked and the header's are marked, so only the area being
edited is selectable.

The revalidation route:

```ts title="src/pages/wocart-revalidate.ts"
import type { APIRoute } from "astro";
import { readThemeRevalidation } from "../theme/sdk";

export const prerender = false;

export const POST: APIRoute = async ({ request }) => {
  const revalidation = await readThemeRevalidation(request);
  if (!revalidation.ok) {
    return new Response(null, { status: revalidation.status, headers: { "Cache-Control": "no-store" } });
  }
  return new Response(null, { status: 204, headers: { "Cache-Control": "no-store" } });
};
```

This theme caches nothing, so a valid revalidation has nothing to drop and
answers `204`. A theme that caches rendered pages drops them here — Theme-00
tags every cached route and calls `context.cache.invalidate({ tags })` — so a
publish shows at once. A preview token is refused on this route and a
revalidation token is refused on the preview route: each is signed for one use.

## 10. Deploy

1. **Build once per host.** `npm run build` is the Cloudflare build: the
   Worker in `dist/server`, with the runtime it was built for in
   `dist/server/wrangler.json`, and the files in `dist/client`.
   `npm run build:vercel` is the Vercel build, a Build Output in
   `.vercel/output`. Wocart Cloud runs both from the same commit, so a release
   must pass both, and the Vercel output must carry no symlinks and no native
   binaries built for another system. Each build serves any store; the store is
   chosen per request by its API key and config.
2. **Read exactly these runtime variables.** They are the storefront runtime
   contract: Wocart Cloud sets them on every storefront it deploys, on
   Cloudflare and on Vercel, whatever the theme.

   | Variable | Value |
   | --- | --- |
   | `COD_SERVER_URL` | The store's API origin |
   | `STORE_API_KEY` | The store's storefront key (a secret) |
   | `WOCART_PREVIEW_KEY` | The preview public key, when preview is configured |

   Images need no variable: the store's config carries its media delivery.
   Hosting it yourself, put them in your host's secret store
   (`wrangler secret put` on Cloudflare, the project's environment variables on
   Vercel). `COD_SERVER_URL`
   must be an origin the deployment can reach: a deployed server cannot reach
   `localhost`.
3. **Verify the deployment**: `/wocart-theme.json` validates, the stylesheet is
   served as `text/css`, a product page renders in every published language,
   and one test order reaches the dashboard.

store depends on the theme, and give your AI agent the
[agent kit](/sdk/theme/agents) before it changes anything.
