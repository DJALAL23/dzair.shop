# AI agent kit

AI coding agents — Claude Code, Cursor, Codex, Copilot, Windsurf — build
Wocart themes quickly, as long as they work from the real contract instead of
guessing it. This kit gives them the contract in the form they read best.

| Piece | What it is | Who reads it |
| --- | --- | --- |
| [The skill](#1-install-the-skill) | A procedure file: rules, workflows, verification | The agent, before every theme task |
| [`AGENTS.md`](#2-add-agentsmd-to-the-theme) | Your theme's facts and commands, at the repo root | The agent, every time it opens the repo |
| [`llms.txt`](#3-give-it-the-docs) | This documentation, indexed for agents | The agent, when it needs detail |
| [Prompts](#prompts-you-can-copy) | Ready-made instructions for common jobs | You paste them |
| [Review checklist](#check-the-agents-work) | How to tell real work from confident output | You |

## Set up in two minutes

### 1. Install the skill

```bash
mkdir -p .agents/skills/wocart-theme
curl -fsSL https://docs.wocart.store/agents/wocart-theme/SKILL.md \
  -o .agents/skills/wocart-theme/SKILL.md
```

For Claude Code, put the same file where it discovers skills:

```bash
mkdir -p .claude/skills/wocart-theme
cp .agents/skills/wocart-theme/SKILL.md .claude/skills/wocart-theme/SKILL.md
```

<a href="/agents/wocart-theme/SKILL.md">Read the skill</a>. It holds the
versions to pin, twenty-one must and never rules each with the command that
checks it, the shape of a theme, five workflows (new theme, change a section,
make a design editable, review, upgrade), the verification commands, and when
to stop and report instead of improvising.

### 2. Add `AGENTS.md` to the theme

```bash
curl -fsSL https://docs.wocart.store/agents/theme/AGENTS.md -o AGENTS.md
```

Then edit its table: your theme key, languages and versions. Claude Code reads
`CLAUDE.md`; make it one line — `@AGENTS.md` — so both tools read the same
file.

### 3. Give it the docs

| URL | Contents |
| --- | --- |
| `https://docs.wocart.store/llms.txt` | The index of every page, for agents |
| `https://docs.wocart.store/llms-full.txt` | Every page in one file |
| `https://docs.wocart.store/sdk/theme/build.md` | Any page as Markdown: its URL plus `.md` |

Most agents fetch a URL when you paste it. Paste the index once at the start
of a session, or the specific page the task needs.

## Prompts you can copy

Each prompt names the skill, the pages to read, the result, and the proof you
expect. Replace the parts in angle brackets.

### Start a new theme

```text
Create a new Wocart theme in this empty folder, following
.agents/skills/wocart-theme/SKILL.md (workflow A) and exactly the files of
https://docs.wocart.store/sdk/theme/build.md, then
https://docs.wocart.store/sdk/theme/tutorial.md.

Theme key: <my-theme>. Languages: ar (primary), fr, en.
Design: <describe it, or attach screenshots>.

Build the home surface end to end first and run `npx astro check`,
`npx vitest run` and `npx astro build`. Show me their output before you add the
product page. Do not invent any API: check each import in node_modules/@wocart.
```

### Add a section

```text
Add a "<testimonials>" section to the home page of this Wocart theme. Follow
workflow B of .agents/skills/wocart-theme/SKILL.md.

A merchant must be able to change: <the heading, up to 6 quotes each with a name
and a photo, the color scheme, the spacing>. Put every default string in all
three content packs. Add it to the home page's default document. Add a render
test. Then run check, test and build and show me the results.
```

### Turn a design into an editable section

```text
Here is a design for a section: <screenshot or HTML>. Rebuild it as a Wocart
theme section following workflow C of .agents/skills/wocart-theme/SKILL.md.

Every text, image, link, number and choice a merchant would reasonably change
becomes a field (https://docs.wocart.store/sdk/theme/fields.md). Use CSS
logical properties so it mirrors in Arabic. Images are media keys resolved with
pictureOf and the store's config.media. No default text may state a fact about
a store. List the fields you chose and why before writing code.
```

### Wire the product page and ordering

```text
Add the product page to this Wocart theme following section 2 and 3 of
https://docs.wocart.store/sdk/theme/tutorial.md: a product template surface
that requires a product section with a fixed order form (role "order-form"),
the placeOrder action, the 404 for unknown products and the thank-you redirect.
Read store.config.checkoutForm to decide which fields to show
(https://docs.wocart.store/sdk/storefront/checkout.md).
Prove it: validateThemeDefinition is [], and with the dev server running a
refused order re-renders with its error and a valid one redirects.
```

### Audit languages and right-to-left

```text
Audit this Wocart theme for language and RTL problems. Report, with file and
line: hardcoded shopper-facing strings, pack keys missing from any language,
plural messages built with string replace, internal links not passed through
the store's href, and CSS using left/right instead of logical properties.
Run pluralFormIssues over every pack. Fix nothing until I approve the list.
```

### Review a change before merging

```text
Review the current diff of this Wocart theme with workflow D of
.agents/skills/wocart-theme/SKILL.md. Answer each of the eight questions with
evidence (file:line or command output). Run diffThemeManifests between the
manifest on main and this branch and list every breaking change.
```

### Upgrade the SDKs

```text
Upgrade @wocart/theme and @wocart/storefront in this theme to <versions>,
following workflow E of .agents/skills/wocart-theme/SKILL.md. Read both
CHANGELOG.md files for every version crossed and list what affects us before
changing code. Then bump both exact pins, fix every new issue, and show check,
test and build output.
```

### Find why a page is empty or wrong

```text
<Describe the symptom: "the home page shows no store name, no menu and no
products".> Diagnose it with https://docs.wocart.store/sdk/theme/troubleshooting.md.
Start from the first-symptoms table, read the client's onError output and the
resolveSurfaceDocument issues, and tell me the cause with evidence before
changing anything.
```

## The rules an agent must not guess

The skill carries every rule with its check. In short:

**An agent must**

- pin `@wocart/theme` 4.0.0 and `@wocart/storefront` 3.0.0 exactly, and find
  every export it uses in `node_modules/@wocart/*/dist/*.d.ts`;
- create the store client in one module, per request, with `theme: THEME_KEY`;
- fall back to `unavailableStoreConfig` when the store cannot be read;
- compose every platform page type as a surface with one required main
  section, and guarantee an order form on product and landing surfaces;
- render saved data only through `resolveSurfaceDocument` and
  `resolveThemeSettings`;
- put every shopper-facing word in every language's pack, counts through
  plural keys;
- build platform links with `storefrontPath` and the store's `href`, and the
  store's WhatsApp only through `whatsAppContact` in one module;
- take colours from schemes, images from media keys with `config.media`, and
  write CSS with logical properties;
- call a change done only when check, test and build passed, and quote them.

**An agent must never**

- rename the theme key, a component `type`, a field `key` or a shipped `id`;
- write a document, setting or merchant text: Wocart Studio is the only writer;
- state a fact about a store in a theme word (delivery reach, hours, phone,
  address);
- import Zod, a schema or a server entry in browser code;
- compute a price, fee or total in the browser;
- work around a missing API with a deep import, copied SDK code or
  `@ts-ignore`: it stops and reports.

## Check the agent's work

Before you accept a change:

- [ ] The agent showed `npx astro check` (0 errors), `npx vitest run` (all
      passing) and `npx astro build` (complete) — run them yourself once.
- [ ] `validateThemeDefinition(theme)` is `[]` (it is in the contract test).
- [ ] No new import outside the published entry points; no `@ts-ignore` over
      an SDK type.
- [ ] No shopper-facing string outside the packs; each new key exists in every
      language; no pack value states a fact about a store.
- [ ] No `wa.me` link, no `config.whatsapp` read and no hand-written platform
      path outside the one WhatsApp module and `storefrontPath`.
- [ ] The page renders in Arabic with `dir="rtl"` and in each other language.
- [ ] No renamed key, type, field or id; `diffThemeManifests` shows only the
      breaking changes you intended.
- [ ] If the agent said an API was missing, check the declarations: either it
      really is (report it upstream) or the agent did not look.

<Callout type="caution" title="Agents follow the docs they are given">
An agent that never read these pages will reconstruct Wocart from patterns it
has seen elsewhere — Shopify's Liquid, a generic React store — and the result
will look right and be wrong. Install the skill before the first prompt.
</Callout>
