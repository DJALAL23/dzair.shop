# Actions et routes Astro

Le navigateur ne transporte jamais la clé de la boutique. Chaque écriture passe
par une route de même origine dans votre application Astro, et cette route
appelle le SDK côté serveur.

Le SDK fournit deux adaptateurs :

- `createStorefrontRoutes` — les routes dont toute vitrine a besoin.
- `createProxyEndpoint` — une route validée pour votre propre point de
  terminaison.

Les deux se trouvent dans `@wocart/storefront/astro`, un point d'entrée réservé
au serveur.

## Un client par requête

Le client de la route doit être celui de la requête, non un singleton de
module :

```ts
// src/theme/sdk.ts
import { createStoreClient, type StoreClient } from "@wocart/storefront/server";
import { COD_SERVER_URL, STORE_API_KEY } from "astro:env/server";

export function getStoreClient(locale?: string): StoreClient {
  return createStoreClient({
    serverUrl: COD_SERVER_URL,
    apiKey: STORE_API_KEY,
    ...(locale ? { locale } : {}),
    theme: "theme-00",
  });
}
```

`serverUrl` et `apiKey` viennent de l'environnement serveur dans un vrai thème,
jamais de variables `PUBLIC_*`. Un client partagé transporterait la langue et le
cache d'un visiteur dans la requête d'un autre.

## La fabrique de routes

```ts
// src/theme/api-routes.ts
import type { APIContext } from "astro";
import { createStorefrontRoutes } from "@wocart/storefront/astro";
import { getStoreClient } from "./sdk";

export const routes = createStorefrontRoutes<APIContext>({
  client: (context) => {
    const locale = context.locals.store?.locale;
    return getStoreClient(locale);
  },
});
```

Chaque gestionnaire exporté tient en une ligne :

```ts
// src/pages/api/cart/validate.ts
import { routes } from "../../../theme/api-routes";
export const POST = routes.cartValidate;
```

## Les routes

| Fichier | Export | Requête | Réponse |
| --- | --- | --- | --- |
| `api/otp/send.ts` | `routes.otpSend` | `POST { phone }` | `{ data: OtpSendResult }` |
| `api/otp/verify.ts` | `routes.otpVerify` | `POST { phone, requestId, code }` | `{ data: OtpVerifyResult }` |
| `api/cart/validate.ts` | `routes.cartValidate` | `POST` panier ou produit + options de devis | `{ success: true, data: CartValidation }` |
| `api/abandoned/index.ts` | `routes.abandonedUpsert` | `POST AbandonedCheckoutInput` | `204` |
| `api/abandoned/convert.ts` | `routes.abandonedConvert` | `POST { sessionId, orderId, orderNumber }` | `204` |
| `api/communes/[wilayaId].ts` | `routes.communes` | `GET` paramètre de chemin | `{ data: Commune[] }` |
| `api/product-reviews/[productId].ts` | `routes.reviewsList` | `GET` + `limit`/`offset` | `{ data: Review[], total }` |
| `api/review-eligibility.ts` | `routes.reviewEligibility` | `POST { orderNumber, phone, turnstileToken? }` | `{ data: ReviewEligibility }` |
| `api/review-upload.ts` | `routes.reviewUpload` | `PUT` corps de fichier + en-tête `X-Review-Grant` | `201 { data: ReviewUpload }` |
| `api/submit-review.ts` | `routes.reviewSubmit` | `POST ReviewInput` | `201 { success: true, data }` |

La fabrique gère déjà :

- la vérification d'origine croisée sur chaque POST/PUT ;
- la transmission du `User-Agent`, de l'IP et du `Referer` de l'acheteur au
  serveur ;
- les bornes d'entrée (longueur du panier, limites d'avis, plage de wilaya) ;
- les envois d'avis en flux, sans mettre le fichier en tampon ;
- le statut d'erreur impliqué par le `domainError` du serveur.

N'enveloppez pas ces gestionnaires dans un composant et ne réimplémentez pas
leurs vérifications.

<Callout type="caution" title="Imports réservés au serveur">
`@wocart/storefront/astro` et `@wocart/storefront/server` ne doivent jamais
atteindre un bundle navigateur. Un import côté client expose la clé de la
boutique ou casse la compilation avec des modules réservés à Node. Gardez-les
dans les fichiers de route `.ts`, les actions et le middleware.
</Callout>

## Un point de terminaison personnalisé

Pour votre propre appel serveur, utilisez le même proxy afin que la validation
et la correspondance des erreurs restent identiques :

```ts
// src/pages/api/availability.ts
import { z } from "zod";
import { createProxyEndpoint } from "@wocart/storefront/astro";
import { getStoreClient } from "../../theme/sdk";

const input = z.object({ productId: z.string().min(1).max(200) });

export const POST = createProxyEndpoint({
  method: "POST",
  inputSchema: input,
  csrfProtection: true,
  client: (body) => getStoreClient().products.get(body.productId),
});
```

Pour un GET avec des paramètres de chemin :

```ts
export const GET = createProxyEndpoint({
  method: "GET",
  pathParams: { wilayaId: "number" },
  client: ({ wilayaId }) => getStoreClient().geo.communes(wilayaId),
});
```

Options utiles :

| Option | Rôle |
| --- | --- |
| `inputSchema` | Valider le corps JSON avant l'appel au serveur |
| `queryParams` | Lire des paramètres de requête nommés pour un GET |
| `pathParams` | Lire et convertir les paramètres de chemin |
| `readInput` | Construire l'entrée à partir d'un flux ou d'une requête personnalisée |
| `forwardAttribution` | Transmettre les en-têtes du visiteur |
| `successBody` | Reformater l'enveloppe de succès |
| `successStatus` | Changer le statut de succès (201 pour une ligne créée) |
| `noContent` | Répondre 204 sans corps |

Laissez `errorStatus` non défini. La valeur par défaut associe un refus de
validation à 400, un refus métier à 422, une limite de débit à 429, un délai
dépassé à 504 et une défaillance amont inattendue à 502.

## Actions de formulaire et PRG

Les actions Astro appelées depuis un formulaire HTML ont besoin d'une étape de
middleware. Le SDK la fournit pour que chaque thème stocke le résultat de la
même manière :

```ts
// src/middleware.ts
import { defineMiddleware } from "astro:middleware";
import { getActionContext } from "astro:actions";
import { runFormAction } from "@wocart/storefront/astro";

export const onRequest = defineMiddleware(async (context, next) => {
  const { action, setActionResult, serializeActionResult } =
    getActionContext(context);

  await runFormAction({
    action: action && {
      calledFrom: action.calledFrom,
      name: action.name,
      handler: action.handler,
    },
    setActionResult,
    serializeActionResult,
  });

  return next();
});
```

`runFormAction` exécute l'action et stocke son résultat pour **cette** réponse.
Il ne fait rien pour un appel JSON ou une requête simple.

<Callout type="caution" title="Ne redirigez pas depuis le middleware">
Astro 7 ne conserve le résultat d'une action que pour la réponse en cours de
rendu. Une redirection dans le middleware arrive à la page suivante sans
résultat : une commande réussie n'atteint jamais la page de remerciement, et une
commande refusée n'affiche aucun message. Redirigez depuis la page après avoir
lu `getActionResult()`.
</Callout>

Le gestionnaire de page prend la décision :

```astro
---
import { getActionResult } from "astro:actions";
import { actions } from "astro:actions";

const result = getActionResult(actions.placeOrder);
if (result && !result.error) {
  return Astro.redirect(thankYouHref(result.data));
}
---
```

## Services liés à la requête

Les routes ont besoin du client de boutique, qui peut à son tour avoir besoin de
la langue de la requête. Certains thèmes ont aussi besoin de la configuration
résolue de la boutique dans `locals` :

```ts
// src/middleware.ts
context.locals.store = await resolveStoreRequest(context);
```

Définissez `locals` avant `next()` et avant l'exécution de toute route. Une
route qui appelle `context.locals.store` sans cela échoue sur un accès indéfini,
pas sur une erreur utile.

## Liste de contrôle du câblage

- La fabrique de client est appelée par requête, jamais au niveau supérieur du
  module.
- `COD_SERVER_URL` et `STORE_API_KEY` sont des valeurs d'environnement serveur.
- Chaque fichier de route exporte le gestionnaire, pas un wrapper.
- La route d'envoi d'avis est `PUT`, pas `POST`.
- `communes` est un GET avec `[wilayaId]` dans le chemin.
- `runFormAction` est appelé pour les actions de formulaire et ne redirige
  jamais.
- `getActionResult` est lu dans la page rendue après le POST.
- Un point de terminaison personnalisé utilise `createProxyEndpoint`, pas un
  proxy écrit à la main.
