# Argent, images, WhatsApp et événements Meta

Ces fonctions utilitaires servent à la présentation. Ils ne changent ni ce qui est facturé
à l'acheteur, ni l'image choisie par le marchand, ni la conversion enregistrée
par le serveur.

## Argent

`formatMoney(amount, { symbol, locale, decimals })` est le formateur unique :

```ts
import { formatMoney } from "@wocart/storefront";

formatMoney(product.price, {
  symbol: config.currencySymbol,
  locale: config.locale,
});
```

Il formate le nombre selon la locale, puis place le symbole :

| Locale | Résultat |
| --- | --- |
| `ar-DZ` | `5.000 دج` (suffixe, chiffres occidentaux) |
| `fr-FR` | `DA 5 000` (préfixe, espace insécable fine) |
| `en-US` | `DA 5,000` |

Par défaut, il n'y a aucune décimale ; les prix en DZD sont des entiers. Ne
passez `decimals: 2` que si la boutique utilise réellement des montants
fractionnaires.

Passez toujours `config.locale` et `config.currencySymbol`, jamais un `"DZD"`
codé en dur ni la langue principale. Un acheteur français sur une boutique
arabe doit voir un formatage français.

`amount` est exprimé dans l'unité monétaire entière de la boutique. Ne divisez
pas par 100.

## Images

### L'image représentative du produit

`productImageSource(product)` choisit la couverture du marchand, ou la première
image utilisable de la galerie, ou `null` :

```ts
import { productImageSource } from "@wocart/storefront";

const src = productImageSource(product);
```

`coverImage` est souvent nul même lorsqu'un produit a des photos. Le lire
directement laisse des carrés vides dans les cartes et les paniers.

### Redimensionner sur le domaine média

Cloudflare Image Resizing s'exécute sur le domaine média ; l'URL conserve cet
hôte :

```ts
import { getCardImage, getGalleryImage } from "@wocart/storefront";

const card = src ? getCardImage(src, mediaDomain) : null;
const full = src ? getGalleryImage(src, mediaDomain) : null;
```

Les assistants renvoient l'URL d'origine lorsqu'ils ne peuvent pas construire
d'URL de redimensionnement — pas de domaine média, ou une image hébergée
ailleurs. C'est grâce à ce repli qu'une boutique sans domaine média s'affiche
quand même.

Les préréglages sont :

| Assistant | Taille | Utilisation |
| --- | --- | --- |
| `getCardImage` | 400×400 | Cartes de grille |
| `getGalleryImage` | 800×800 | Galerie produit |
| `getThumbnailImage` | 80×80 | Vignettes de galerie |
| `getHeroImage` | 1200×600 | Bannières hero |
| `getCategoryImage` | 300×200 | Tuiles de catégorie |
| `getLogoImage` | 200×80 | Logo de l'en-tête, contenu dans le cadre |

`IMAGE_SIZES` expose les préréglages bruts.

### Lier le domaine une seule fois

```ts
import { createImageHelpers } from "@wocart/storefront";

const images = createImageHelpers(mediaDomain);

images.getCardImage(src);
images.getGalleryImage(src);
images.generateSrcSet(src, 400, 400);
```

`createImageHelpers` est la forme recommandée dans un thème : chaque appel
porte le domaine configuré, de sorte qu'aucun appel n'envoie
silencieusement une image non optimisée.

### Images responsives

```ts
const srcset = images.generateSrcSet(src, 400, 400);
// "… 1x, … 1.5x, … 2x"
```

Passez la même largeur et la même hauteur que celles utilisées par la mise en
page et définissez-les sur le `<img>`. Réserver la boîte évite les décalages de
mise en page :

```astro
<img
  src={images.getCardImage(src)}
  srcset={images.generateSrcSet(src, 400, 400)}
  width="400"
  height="400"
  alt={product.name}
  loading="lazy"
/>
```

La première image d'une galerie peut utiliser `loading="eager"` et une priorité
plus élevée ; les vignettes restent en chargement différé.

### Clés d'image

Un réglage de thème peut stocker une clé d'objet comme
`products/3f2a9c.webp`. Transformez-la en URL publique avec
`mediaUrl(key, mediaDomain)`, puis redimensionnez-la :

```ts
import { mediaUrl, mediaImageUrl } from "@wocart/storefront";

const url = mediaUrl("products/3f2a9c.webp", mediaDomain);
const resized = url ? mediaImageUrl(url, { width: 1200, quality: 85 }, mediaDomain) : null;
```

`mediaUrl` rejette les clés vides, les segments vides ou `.`/`..`, les espaces,
les caractères de contrôle, les barres obliques inverses, `?`, `#` et les clés
trop longues. Ne concaténez pas un domaine et une clé à la main.

`mediaImageUrl` ne réécrit que les URL sur l'origine média ; tout le reste
revient à `null`, et `optimizeImage` renvoie l'original.

## WhatsApp

`config.whatsapp` est la configuration résolue du widget, ou `null`. Son `href`
est le lien WhatsApp du marchand ; ne construisez pas vous-même une URL
`wa.me`.

### Faut-il l'afficher

```ts
import { showsWidgetOn } from "@wocart/storefront";

if (
  config.whatsapp &&
  showsWidgetOn(config.whatsapp.surfaces, Astro.url.pathname)
) {
  renderWhatsAppLauncher(config.whatsapp);
}
```

Les surfaces sont `home`, `catalog`, `product`, `pages`, `thankYou`, `checkout`
et `landing`. `showsWidgetOn` utilise le comparateur de chemins : une URL de
produit se résout en `product` même avec un préfixe de langue.

Un widget `null` signifie désactivé. N'affichez pas de lanceur de secours.

### Résoudre le préremplissage

Le modèle du marchand contient `{store}`, `{product}`, `{url}` et `{order}` :

```ts
import { buildWhatsAppHref, resolvePrefillText } from "@wocart/storefront";

const template =
  pageType === "product"
    ? config.whatsapp.prefillProduct
    : config.whatsapp.prefillGeneral;

const text = resolvePrefillText({
  template: template ?? "",
  storeName: config.name,
  productName: product?.name,
  url: Astro.url.href,
  orderNumber: pageType === "thankYou" ? orderNumber : undefined,
});

const href = buildWhatsAppHref(config.whatsapp.href, text);
```

Règles prises en charge par l'assistant :

- `{product}` revient au nom de la boutique lorsqu'il n'y a pas de produit.
- `{order}` se résout en rien lorsqu'il n'y a pas de commande.
- `{url}` est dépouillée des paramètres `utm_*`, `*clid` et `fbclid`. Un
  acheteur arrivant d'une publicité ne remet pas au marchand un lien chargé de
  suivi.
- Le résultat est limité à `MAX_RESOLVED_PREFILL_LENGTH` (900 caractères), sur
  une limite de mot.
- Un espace réservé inconnu est laissé tel quel ; c'est le compteur du tableau
  de bord qui repère une faute de frappe du marchand.

`buildWhatsAppHref` ajoute `text=` après `&` lorsque le href de base possède
déjà une requête, afin qu'un lien marchand avec un numéro ou une source
préremplis les conserve.

Sur la surface de remerciement, utilisez `prefillThankYou` et passez le numéro
de commande :

```ts
const text = resolvePrefillText({
  template: config.whatsapp.prefillThankYou ?? "",
  storeName: config.name,
  url: Astro.url.href,
  orderNumber,
});
```

La position, l'accent, la légende et l'état d'attention du lanceur sont déjà
résolus sur l'objet widget. Utilisez-les ; n'inventez pas de valeurs par défaut
différentes de celles du tableau de bord.

## Événements navigateur Meta

Le SDK construit les charges utiles Meta et enveloppe la fonction pixel :

```ts
import {
  buildMetaAddToCartPayload,
  buildMetaViewContentPayload,
  createMetaPixelTracker,
} from "@wocart/storefront";

const pixel = createMetaPixelTracker({
  getPixel: () =>
    typeof window.fbq === "function" ? (window.fbq as never) : null,
});

pixel.track(
  "ViewContent",
  buildMetaViewContentPayload(product.id, view.basePrice),
);

const addToCart = buildMetaAddToCartPayload(basket.getLines());
if (addToCart) pixel.track("AddToCart", addToCart);
```

Une charge utile produit porte `content_ids`, `content_type: "product"`,
`value` et `currency: "DZD"`. Une charge utile de panier ajoute `contents` et
`num_items`.

Les assistants sont purs et renvoient `null` pour un panier vide :

```ts
const payload = buildMetaAddToCartPayload(basket.getLines());
if (payload) pixel.track("AddToCart", payload);
```

`buildMetaInitiateCheckoutPayload(lines, value)` a la même forme avec la valeur
de la commande.

Utilisez `trackSingle(pixelId, event, params, { eventID })` lorsque la vente
appartient à un seul pixel. L'événement **Purchase** est différent : son pixel
et son événement relèvent de la décision du serveur. Lisez-les dans
`orders.tracking` et n'envoyez rien lorsque la valeur est `null` — voir
[Commande et OTP](/fr/sdk/storefront/checkout).

<Callout type="caution" title="Un événement navigateur n'est pas la conversion">
L'événement navigateur et l'événement Conversions API du serveur sont les deux
moitiés d'une même conversion. Ils doivent porter le même `eventID` et aller au
même pixel. N'inventez ni pixel, ni nom d'événement, ni identifiant d'événement
sur la page de remerciement.
</Callout>

## Liste de contrôle de la présentation

- Les prix utilisent `config.locale` et `config.currencySymbol`.
- Les images de produit viennent de `productImageSource`, pas de `coverImage`
  seul.
- Les assistants de redimensionnement sont liés une fois au domaine média.
- `<img>` porte width, height et `alt`.
- Le widget WhatsApp n'est affiché que si `config.whatsapp` existe et que la
  surface est activée.
- Le préremplissage passe par `resolvePrefillText` et `buildWhatsAppHref`.
- Les charges utiles Meta viennent des constructeurs ; Purchase vient de
  `orders.tracking`.
