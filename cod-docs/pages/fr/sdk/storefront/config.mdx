# Configuration et langues

`config.get()` est la première lecture de la plupart des pages. Elle renvoie les
réglages publics de la boutique ou `null` lorsqu'ils ne peuvent pas être lus.

```ts
import { getStore } from "../theme/store";

const store = getStore();
const config = await store.config.get();

if (config === null) {
  return new Response("Store unavailable", { status: 503 });
}
```

Une configuration nulle est un vrai échec, pas une boutique vide. Utilisez votre
mise en page de secours ou une page d'erreur ; n'inventez pas un nom de boutique
et une devise pour continuer comme si la lecture avait réussi.

## Contenu de la configuration

| Groupe | Champs | Utilisation |
| --- | --- | --- |
| Identité | `name`, `domain`, `logoUrl`, `themeId` | Titre de page, en-tête, partage |
| Marque | `primaryColor`, `accentColor`, `bgColor`, `fontFamily` | Anciennes valeurs de thème ; voir la note ci-dessous |
| Langues | `lang`, `locale`, `locales` | `<html lang>` et `dir`, sélecteur, liens |
| Devise | `currency`, `currencySymbol` | `formatMoney` |
| SEO | `metaTitle`, `metaDescription`, `ogImage` | Métadonnées de l'en-tête |
| Fonctionnalités | `reviewsEnabled`, `cartEnabled`, `otpEnabled`, `turnstileEnabled`, `turnstileSiteKey` | Faut-il afficher une surface ; la clé publique du widget |
| Panier | `freeShippingThreshold`, `cartShippingMode` | Texte et affichage uniquement ; le devis possède les frais |
| Commande | `checkoutForm` | Quels champs afficher et lesquels sont requis |
| Suivi | `pixelId`, `conversionEvent` | Installation du pixel Meta et choix de l'événement |
| Pages | `pages` | Liens de pied de page et de consentement |
| Légal | `legalContact` | Coordonnées publiques et délai de livraison |
| WhatsApp | `whatsapp` | Réglages du lanceur et activation par surface |
| Thème | `themeSettings`, `contentOverrides` | Thèmes éditables |

<Callout type="caution" title="Les couleurs de la configuration sont l'ancienne méthode">
`primaryColor`, `accentColor`, `bgColor`, `fontFamily` et `announcementBar`
sont des valeurs dépréciées enregistrées avant les réglages de thème. Un thème
éditable déclare ses couleurs, sa police et son annonce dans
`defineTheme({ settings })` et lit `themeSettings`. Ne construisez pas un
nouveau thème sur les champs dépréciés.
</Callout>

## Interrupteurs de fonctionnalités

N'affichez une fonctionnalité que si la boutique la possède :

```astro
---
const { cartEnabled, reviewsEnabled, otpEnabled, turnstileSiteKey } = config;
---

{cartEnabled && <CartDrawer />}
{reviewsEnabled && <ProductReviews productId={product.id} />}
{otpEnabled && <OtpStep />}
{turnstileSiteKey && <div class="cf-turnstile" data-sitekey={turnstileSiteKey} />}
```

Une boutique avec `cartEnabled: false` ne doit livrer aucun markup de panier.
Ce n'est pas cosmétique : l'interrupteur est le chemin de rollback du panier.

La même règle s'applique aux avis, à l'OTP et au widget WhatsApp. Leurs réglages
existent pour qu'une boutique puisse désactiver la surface sans déploiement.

## Politique de commande

`checkoutForm` est la politique de formulaire du marchand, déjà résolue :

```ts
type CheckoutFormPolicy = {
  address: "required" | "optional" | "hidden";
  notes: "optional" | "hidden";
  email: "required" | "optional" | "hidden";
  deliveryOptions: { home: boolean; stopDesk: boolean };
  customFields: Array<{
    id: string;
    label: string;
    type: "text" | "textarea" | "number" | "select";
    required: boolean;
    options?: string[];
  }>;
};
```

Lisez-la ; ne la redécidez pas. En particulier :

- `hidden` signifie ne rendre aucun input, pas un input désactivé ou vide.
- `customFields` sont rédigés par le marchand. Affichez `label` comme texte,
  jamais comme HTML.
- Envoyez les réponses dans `customFieldResponses`, indexées par l'`id` généré
  par le serveur pour le champ.
- Le serveur valide la même politique à la création de la commande. Un
  raccourci côté client ne peut pas rendre un champ requis facultatif.

```ts
const answers = config.checkoutForm.customFields.map((field) => ({
  id: field.id,
  value: formData.get(`custom:${field.id}`)?.toString() ?? "",
}));
```

L'action de commande accepte un seul champ JSON pour ces réponses, afin qu'un
marchand puisse ajouter un champ personnalisé sans déployer le thème.

## Langues

Une boutique possède une langue principale (`lang`) et une liste de langues
publiées (`locales`) :

```ts
const config = await getStore().config.get();

config?.locales;
// [
//   { code: "ar", nativeName: "العربية", direction: "rtl" },
//   { code: "fr", nativeName: "français", direction: "ltr" },
// ]
```

`locales` est ordonné avec la langue principale en premier. C'est la seule
autorité sur les langues existantes ; ne codez pas une liste de langues en dur
dans votre thème.

`servedLanguage(config, code)` donne l'objet de langue pour `<html lang>` et
`dir` :

```astro
---
import { servedLanguage } from "@wocart/storefront";

const language = servedLanguage(config, config.locale);
---
<html lang={config.locale} dir={language?.direction ?? "ltr"}>
```

### Forme des URL

La langue principale n'a pas de préfixe. Chaque autre langue publiée en a un :

```text
/products/robe          primary (Arabic, for example)
/fr/products/robe       French
/ar/products/robe       301 to /products/robe
```

Les assistants qui implémentent cela sont purs :

```ts
import {
  alternateLinks,
  localeRouting,
  localizeHref,
  resolveLocalePath,
} from "@wocart/storefront";

const routing = localeRouting(config);

resolveLocalePath("/fr/products/robe", routing);
// { kind: "page", locale: "fr", pathname: "/products/robe" }

localizeHref("/products/robe", "fr", routing);
// "/fr/products/robe"

alternateLinks("/products/robe", routing, "https://shop.example");
// hreflang entries, primary first, plus x-default
```

`resolveLocalePath` ne traite un premier segment comme une langue que si la
boutique la publie. Un préfixe inconnu est un chemin ordinaire et renvoie
normalement un 404.

### Un client par langue

Le texte marchand est traduit par le serveur. Demandez une langue via le client ;
ne traduisez pas les noms de produits dans le navigateur.

```ts
const primaryClient = getStore();
const primaryConfig = await primaryClient.config.get();

const routing = localeRouting(primaryConfig!);
const path = resolveLocalePath(Astro.url.pathname, routing);
if (path.kind === "redirect") return Astro.redirect(path.location, 301);

const client =
  path.locale === routing.primary ? primaryClient : getStore(path.locale);
const config = (await client.config.get()) ?? primaryConfig;
```

Gardez un client par langue. Chaque client possède sa propre configuration,
ses catégories et ses communes en cache.

Si la boutique cesse de publier la langue demandée, la configuration revient
dans la langue principale. `config.locale` indique la langue réellement reçue ;
redirigez si elle ne correspond plus à l'URL.

### Liens et liens alternatifs

Chaque lien interne doit passer par `localizeHref`, y compris les liens renvoyés
par les menus :

```astro
<a href={localizeHref(item.href, config.locale, routing)}>{item.label}</a>
```

Dans l'en-tête, émettez un lien alternatif par langue publiée :

```astro
---
const alternates = alternateLinks(Astro.url.pathname, routing, Astro.url.origin);
---
{alternates.map((link) => (
  <link rel="alternate" hreflang={link.hreflang} href={link.href} />
))}
```

## Texte et réglages du thème

Deux champs ne contiennent des données que si le client est créé avec une clé de
thème :

```ts
const store = createStoreClient({
  serverUrl,
  apiKey,
  theme: "theme-00",
});

const config = await store.config.get();
config?.contentOverrides;
// { ar: { heroTitle: "..." }, fr: { heroTitle: "..." } }
config?.themeSettings;
// { primaryColor: "#...", layout: "wide" }
```

- `contentOverrides[locale]` contient les modifications du marchand aux textes
  de votre thème dans cette langue. Fusionnez uniquement la table de cette
  langue sur vos propres textes.
- `themeSettings` contient les valeurs enregistrées par le marchand, exactement
  telles quelles. Dans un thème éditable, résolvez-les avec la déclaration du
  thème via `resolveThemeSettings` de `@wocart/theme`.
- Sans `theme`, les deux sont vides/absents. Une vitrine personnalisée simple
  peut les ignorer et utiliser ses propres textes et styles.

Lisez le [SDK Theme](/fr/sdk/theme) si vous construisez un thème éditable.

## Pages et détails légaux

`config.pages` liste les pages publiées qui ont choisi d'apparaître dans le pied
de page :

```ts
config.pages.map((page) => ({
  title: page.title,
  href: `/pages/${page.slug}`,
  kind: page.kind, // terms | privacy | refund | shipping | custom
}));
```

Utilisez `kind` lorsqu'une règle nomme une page — « vous acceptez les Conditions »
désigne le type `terms`, pas un slug `/pages/terms` codé en dur. Un marchand peut
renommer un slug.

`config.legalContact` est le bloc de contact public :

```ts
config.legalContact;
// {
//   contactEmail: "help@shop.example",
//   contactPhone: "0555 12 34 56",
//   deliveryMinDays: 2,
//   deliveryMaxDays: 5,
// }
```

Il vaut `null` tant que le marchand n'a pas enregistré de profil légal. N'inventez
pas d'adresse ni de promesse de livraison lorsqu'il est nul.

## WhatsApp

`config.whatsapp` est le widget résolu, ou `null` lorsque le marchand l'a
désactivé. Lorsqu'il existe, `showsWidgetOn(config.whatsapp.surfaces, pathname)`
vous indique s'il est activé sur cette surface.

```ts
import { showsWidgetOn } from "@wocart/storefront";

if (
  config.whatsapp &&
  showsWidgetOn(config.whatsapp.surfaces, Astro.url.pathname)
) {
  // Render the launcher and its prefill.
}
```

Les règles de href et de préremplissage sont couvertes dans [Argent, images,
WhatsApp et événements Meta](/fr/sdk/storefront/presentation).
