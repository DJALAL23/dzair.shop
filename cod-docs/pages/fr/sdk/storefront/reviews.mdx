# Avis

Les avis sont des données produit. Ils sont lus sur le serveur et écrits via un
petit parcours navigateur qui prouve que l'acheteur a acheté le produit.

Une boutique peut désactiver les avis avec `config.reviewsEnabled`. Lorsque
c'est désactivé, n'affichez pas la section d'avis et n'appelez pas les écritures
d'avis.

## Lire les avis

```ts
const { rows, total } = await store.products.reviews.list(product.id, {
  limit: 20,
  offset: 0,
});
```

`rows` est une page d'avis, `total` est le nombre complet. Les deux viennent
d'une seule enveloppe ; ne déduisez pas le total de la longueur de la page.

Une lecture échouée donne `{ rows: [], total: 0 }`. Affichez l'état vide, pas
une page d'erreur, lorsqu'un produit n'a pas d'avis ou que la lecture est
brièvement dégradée.

Un avis contient :

```ts
type Review = {
  id: string;
  customerName: string;
  rating: number;              // 1–5
  title: string | null;
  body: string;
  createdAt: string;
  verified: boolean;           // the order reached the customer
  media: ReviewMedia[];        // photos first, then a voice note
};
```

`verified: true` signifie que l'avis repose sur une commande livrée. Affichez-le
comme un achat vérifié. N'utilisez pas le nom complet du client comme
identifiant.

`media` peut être vide sur les anciens serveurs. Un élément média est :

```ts
type ReviewMedia = {
  id: string;
  kind: "image" | "audio";
  url: string;
  thumbUrl: string | null; // photos only
  width: number | null;
  height: number | null;
  durationMs: number | null; // voice only
};
```

`url` et `thumbUrl` sont déjà des URL publiques. Ne construisez pas une URL de
média à partir d'une clé d'objet.

## Le parcours d'avis

Écrire un avis comporte quatre étapes :

1. **Trouver l'achat.** L'acheteur saisit le numéro de commande et le téléphone
   utilisés pour la commande.
2. **Choisir un produit.** La commande éligible liste ses produits, chacun
   marqué comme déjà évalué ou non.
3. **Joindre des médias (facultatif).** Les photos et un message vocal sont
   téléversés avant l'envoi de l'avis.
4. **Envoyer l'avis.** Le serveur décide s'il est publié maintenant ou s'il
   attend la vérification de la boutique.

Le serveur possède les règles : la commande doit être livrée, le téléphone doit
correspondre, un produit ne peut être évalué qu'une fois, et la modération de la
boutique décide de la visibilité.

## 1. Prouver l'achat

```ts
const response = await fetch("/api/review-eligibility", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    orderNumber,
    phone,
    ...(turnstileToken ? { turnstileToken } : {}),
  }),
});

const eligibility = await response.json();
if (!eligibility.success) {
  // ORDER_NOT_FOUND or REVIEW_ORDER_NOT_DELIVERED
  return;
}

eligibility.data;
// {
//   orderNumber,
//   customerName,
//   products: [{ productId, name, imageSrc, reviewed }],
//   media: {
//     maxPhotos,
//     voiceMaxSeconds,
//     grant,
//     expiresAt,
//   } | null,
// }
```

`media: null` signifie texte uniquement. N'affichez jamais un sélecteur de
photos ni un bouton d'enregistrement lorsque le grant est absent.

`grant` est de courte durée. Envoyez-le avec chaque téléversement et avec
l'avis. S'il expire, demandez à l'acheteur de prouver à nouveau l'achat ; ne
réutilisez pas un ancien grant.

Si la boutique active Turnstile, passez le jeton du widget dans
`turnstileToken`. Le serveur le vérifie avec le reste de la requête.

## 2. Afficher ce qui peut être évalué

```ts
for (const product of eligibility.data.products) {
  renderProductChoice({
    name: product.name,
    image: product.imageSrc,
    disabled: product.reviewed,
  });
}
```

Un produit déjà évalué reste visible mais ne peut pas être évalué à nouveau. Ne
le supprimez pas silencieusement ; l'acheteur doit voir que l'avis existe.

## 3. Téléverser des médias

Les médias sont téléversés **avant** l'envoi de l'avis. Chaque téléversement
répond avec un `uploadId` ; l'avis les porte tous.

### Photos

`prepareReviewPhoto` est réservé au navigateur et vit sur son propre point
d'entrée :

```ts
import { prepareReviewPhoto } from "@wocart/storefront/review-media";

const prepared = await prepareReviewPhoto(photoFile);
```

Elle dessine la photo dans la bonne orientation, limite son plus grand côté à
1 600 px et la réencode en WebP (ou JPEG). Si le navigateur ne peut pas le faire,
elle renvoie le fichier d'origine ; le serveur le convertit quand même et
supprime l'EXIF.

Téléversez le fichier préparé tel quel :

```ts
const uploaded = await fetch("/api/review-upload", {
  method: "PUT",
  headers: {
    "Content-Type": prepared.type,
    "X-Review-Grant": grant,
  },
  body: prepared,
});

const { data } = await uploaded.json();
// { uploadId, kind: "image", bytes }
```

N'envoyez pas de chaîne base64 ni de data URL. La route transmet le fichier en
flux, et le serveur lit son type depuis ses octets.

### Messages vocaux

```ts
import {
  canRecordVoice,
  createVoiceRecorder,
} from "@wocart/storefront/review-media";

const media = eligibility.data.media;
if (canRecordVoice() && media?.voiceMaxSeconds) {
  const recorder = createVoiceRecorder({
    maxSeconds: media.voiceMaxSeconds,
    onTick: (elapsedMs) => updateTimer(elapsedMs),
    onLimit: (voice) => uploadVoice(voice),
  });

  await recorder.start();
  const voice = await recorder.stop();
  await uploadVoice(voice);
}
```

L'enregistreur enregistre un audio mono à environ 32 kb/s et s'arrête à la
limite de la boutique. Le téléversement envoie le fichier et sa durée :

```ts
async function uploadVoice(voice: { blob: Blob; durationMs: number; mimeType: string }) {
  const response = await fetch("/api/review-upload", {
    method: "PUT",
    headers: {
      "Content-Type": voice.mimeType,
      "X-Review-Grant": grant,
      "X-Media-Duration-Ms": String(voice.durationMs),
    },
    body: voice.blob,
  });
  return response.json();
}
```

`canRecordVoice()` renvoie false sur les navigateurs sans enregistrement au
microphone ; masquez le bouton d'enregistrement plutôt que d'en afficher un qui
ne peut pas fonctionner.

Une photo est conservée par le serveur en WebP ; cette conversion est aussi ce
qui supprime ses données EXIF et GPS. N'ajoutez pas une seconde étape côté
client pour « retirer les métadonnées ».

## 4. Envoyer

```ts
const response = await fetch("/api/submit-review", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    orderNumber,
    phone,
    productId,
    rating,               // 1–5
    title: title || undefined,
    body,
    grant,
    uploads: uploadIds,   // every uploadId, or omit for text only
  }),
});

const result = await response.json();
if (!result.success) {
  if (result.domainError?.category === "validation") {
    // Show result.domainError.fieldIssues.
  }
  return;
}

result.data;
// { id, visibility: "published" | "after_review" }
```

La route est celle de même origine montrée ci-dessous ; le navigateur n'importe
jamais le client serveur. `visibility` peut être absent sur les anciens serveurs.
Traitez l'absence comme « la modération normale de la boutique », pas comme la
preuve que l'avis est public.

Ne videz pas le formulaire en cas d'échec. L'acheteur doit pouvoir corriger le
corps, la note ou les pièces jointes et réessayer.

## Les routes de même origine

Le navigateur ne détient pas la clé de la boutique. Liez une fois les routes
d'avis du SDK :

```ts
// src/theme/api-routes.ts
import type { APIContext } from "astro";
import { createStorefrontRoutes } from "@wocart/storefront/astro";

export const routes = createStorefrontRoutes<APIContext>({
  client: (context) => context.locals.store.client,
});
```

Puis exportez les gestionnaires dont vous avez besoin :

```ts
// src/pages/api/review-eligibility.ts
import { routes } from "../../theme/api-routes";
export const POST = routes.reviewEligibility;
```

```ts
// src/pages/api/review-upload.ts
import { routes } from "../../theme/api-routes";
export const PUT = routes.reviewUpload;
```

```ts
// src/pages/api/submit-review.ts
import { routes } from "../../theme/api-routes";
export const POST = routes.reviewSubmit;
```

Et pour la liste :

```ts
// src/pages/api/product-reviews/[productId].ts
import { routes } from "../../../theme/api-routes";
export const GET = routes.reviewsList;
```

Les routes ajoutent la vérification d'origine croisée, les limites d'entrée, l'en-tête
`X-Review-Grant` et la gestion des flux. Ne les réimplémentez pas dans un
composant.

<Callout type="caution" title="Les médias d'avis sont du code navigateur">
`@wocart/storefront/review-media` touche au canvas, au microphone et au DOM.
Ne l'importez jamais depuis le frontmatter d'une page, un middleware, une action
ou une route API.
</Callout>

## États vides et indisponibles

- `reviewsEnabled: false` — n'affichez aucune interface d'avis et n'appelez aucun
  point de terminaison d'avis.
- `rows: []` — « Aucun avis pour le moment » ; le formulaire peut encore être
  disponible.
- `media: null` — formulaire d'avis texte uniquement.
- `maxPhotos: 0` — aucun sélecteur de photos.
- `voiceMaxSeconds: null` — aucun enregistreur vocal.
- `reviewed: true` — affichez le produit, désactivez l'action.
- `eligibility.success === false` — gardez le formulaire et affichez la raison
  du serveur.

Ne transformez pas un mauvais numéro de commande en « aucun avis ». C'est un
refus de la preuve, pas une liste d'avis vide.
