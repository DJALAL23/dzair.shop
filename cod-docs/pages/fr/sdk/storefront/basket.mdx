# Panier et devis

Le panier est l'intention d'un acheteur. Il vit dans le navigateur, jamais dans
D1. Le serveur possède les prix.

La vitrine n'a donc qu'une règle à retenir : **le panier du navigateur sert à
l'affichage et à l'interaction ; `cart.validate` fait foi pour l'argent**.

## Le panier du navigateur

```ts
import { createBasketStore } from "@wocart/storefront";

const basket = createBasketStore();

basket.addLine({
  productId: product.id,
  productName: product.name,
  variantId: variant?.id ?? null,
  variantLabel: variantLabel(variant),
  quantity: 1,
  unitPrice: view.basePrice, // display only
  href: `/products/${product.handle}`,
  ...(cardImageUrl ? { image: cardImageUrl } : {}),
});
```

`createBasketStore` utilise `localStorage` lorsqu'il est disponible, un adaptateur
en mémoire en SSR ou dans les tests, et échoue en douceur lorsque le stockage est
bloqué. Un navigateur qui ne peut rien stocker dispose quand même d'un panier en
mémoire pour la page courante ; `isPersistent()` indique s'il survit à un
rechargement.

Les méthodes sont :

| Méthode | Résultat |
| --- | --- |
| `getLines()` | Lignes actuelles |
| `getCount()` | Quantité totale |
| `getSubtotal()` | Sous-total d'affichage optimiste |
| `addLine(line)` | Fusionne par produit + variante |
| `setQuantity(key, quantity)` | Plafonnée ; `<= 0` supprime |
| `removeLine(key)` | Supprime une ligne |
| `clear()` | Vide le panier |
| `toOrderItems()` | `items[]` prêt pour le serveur |
| `subscribe(listener)` | Changements locaux et entre onglets |
| `isPersistent()` | Indique si le stockage survit à un rechargement |

Les limites sont `MAX_BASKET_LINES` (20) et `MAX_BASKET_LINE_QUANTITY` (100).
L'identité d'une ligne est produit + variante : le même produit en deux variantes
occupe donc deux lignes.

`unitPrice` n'est que ce que le tiroir affiche en attendant le devis. Ne l'envoyez
pas comme prix et n'utilisez pas `getSubtotal()` comme total de la commande.

### S'abonner une fois

```ts
const unsubscribe = basket.subscribe((lines) => {
  renderBadge(lines.reduce((total, line) => total + line.quantity, 0));
  scheduleQuote();
});
```

Le store du panier notifie les changements locaux et relit le stockage lorsqu'un
autre onglet modifie le panier. Gardez l'écouteur léger ; le devis est temporisé
séparément.

### Choisir une offre

Si le produit affiche des paliers de quantité ou « Achetez X, obtenez Y »,
conservez
le choix de l'acheteur sur la ligne :

```ts
basket.addLine({
  // …
  offerId: selectedTier.offerId,
});
```

Un choix explicite ultérieur le remplace ; un ajout simple conserve le choix
existant. Le serveur n'applique toujours l'offre que si la quantité y donne
droit.

### Construire la ligne depuis un produit

```ts
import { getProductView, productImageSource } from "@wocart/storefront";

const view = getProductView(product);
const image = productImageSource(product);

basket.addLine({
  productId: product.id,
  productName: product.name,
  variantId: view.defaultVariant?.id ?? null,
  variantLabel: view.defaultVariant
    ? Object.values(view.defaultVariant.variations).join(" / ")
    : null,
  quantity,
  unitPrice: view.basePrice,
  href: `/products/${product.handle}`,
  ...(image ? { image } : {}),
  ...(offerId ? { offerId } : {}),
});
```

### Une offre choisie pièce par pièce

Une offre de plusieurs pièces peut laisser l'acheteur choisir une variante pour
chacune — trois pyjamas en deux tailles. Ajoutez ce choix tel que le formulaire
de commande le porte : un seul appel, une ligne par variante avec ses pièces,
chaque ligne portant l'offre, et tout ou rien — un panier sans place pour toutes
les nouvelles lignes n'ajoute rien.

```ts
basket.addSelections(
  { productId, productName, unitPrice, offerId, href, image },
  [
    { variantId: "6m", variantLabel: "6 mois" },
    { variantId: "12m", variantLabel: "12 mois" },
    { variantId: "6m", variantLabel: "6 mois" },
  ],
);
```

### Ce qu'un ajout a mis

`addedLines(before, after)` est ce qu'un appui a mis dans le panier : chaque
ligne qui a augmenté, de ce dont elle a augmenté. Envoyez cela comme l'événement
Meta `AddToCart` — jamais le panier entier — et lisez une réponse vide comme un
panier plein, ce qu'il faut dire à l'acheteur.

```ts
import { addedLines, buildMetaAddToCartPayload } from "@wocart/storefront";

const before = basket.getLines();
const added = addedLines(before, basket.addLine(line));
if (added.length === 0) showBasketFull();
else tracker.track("AddToCart", buildMetaAddToCartPayload(added));
```

## Demander un devis pour le panier

Le devis est une lecture serveur. Dans le navigateur, demandez-le par votre
route de même origine avec `createQuoter` : il envoie les lignes avec ce que
l'acheteur a déjà saisi et ne garde que la dernière réponse, si bien qu'une
réponse lente à un appui précédent ne remplace jamais une plus récente.

```ts
import { createQuoter } from "@wocart/storefront";

const quoter = createQuoter({ endpoint: "/api/cart/validate" });

const result = await quoter.quote({ items: basket.toOrderItems() }, { destination, couponCode, phone });
if (result.status === "fresh") show(result.quote);
// "stale": a newer question was asked meanwhile — keep what is shown.
// "failed": no usable answer — keep the optimistic basket.
```

Le formulaire de commande d'un produit demande de la même façon, avec un seul
produit tel que le formulaire l'envoie (`{ productId, productName, quantity,
variantSelections, offerId }`). La réponse est lue sans Zod (`readCartQuote`) :
aucun schéma n'atteint le navigateur de l'acheteur.

Sur le serveur, le même appel est `cart.validate` :

```ts
const result = await store.cart.validate(items, {
  destination: {
    wilayaId: 16,
    communeId: "c-16-001",
    deliveryType: "home",
  },
  couponCode: "RAMADAN10",
});

if (!result.success) {
  // The quote is read-only; show the reason or keep the optimistic basket.
  return;
}

result.data;
```

`cart.validate` est en lecture seule : rien n'est écrit et aucun stock n'est
réservé. Un échec peut être affiché sans risque tout en conservant le panier.

Pour un formulaire de commande produit qui n'est pas encore entré dans le panier,
utilisez plutôt `cart.quote`. Il accepte soit un panier, soit un produit tel que
le formulaire le transmet :

```ts
const result = await store.cart.quote({
  productId: product.id,
  productName: product.name,
  quantity: 3,
  variantSelections: [{ variantId: variant.id, variantLabel }],
  offerId,
});
```

Le devis et la commande appliquent les mêmes règles de construction des lignes :
un devis correspond donc à ce que la commande devrait coûter.

## Ce que renvoie le devis

```ts
type CartValidation = {
  lines: CartValidationLine[];
  subtotal: number;
  rewards: CartReward[];
  freeDelivery: {
    fromOffer: boolean;
    threshold: number | null;
    qualified: boolean;
    remaining: number;
  };
  delivery?: { available: true; fee: number; total: number }
    | { available: false; fee: null; total: null };
  coupon?: CouponOutcome | null;
};
```

### Lignes

Chaque ligne porte la réponse actuelle du catalogue :

```ts
type CartValidationLine = {
  productId: string;
  variantId: string | null;
  variantLabel: string | null;
  productName: string;
  quantity: number;
  unitPrice: number;
  lineTotal: number;       // offers and coupon share applied
  offerId?: string | null;
  offerName?: string | null;
  discount?: number | null;
  maxQuantity: number | null;
  blocker: "missing" | "unlisted" | "out_of_stock" | null;
};
```

Une ligne bloquée est exclue du sous-total, des offres et du calcul de livraison
gratuite. Affichez la raison et désactivez la commande tant qu'une ligne est
bloquée. Ne supprimez pas la ligne pour l'acheteur, sauf si votre interface
propose explicitement cette action.

`maxQuantity` vaut `null` lorsque le produit n'a pas de suivi de stock.

### Récompenses

`rewards` liste les cadeaux obtenus par le panier. Ce ne sont pas des lignes du
panier ; affichez-les sur une ligne distincte « cadeau gratuit ».

### Livraison gratuite

```ts
const free = quote.freeDelivery;
if (free.qualified) {
  // Delivery is free: from the threshold or an offer.
} else if (free.threshold !== null) {
  // free.remaining is how much more the subtotal needs.
}
```

Le seuil est un réglage de la boutique ; le devis reste l'autorité, car une offre
peut rendre la livraison gratuite avant le seuil.

### Livraison

`delivery` n'est présent que lorsque le devis a reçu une destination :

```ts
if (quote.delivery?.available) {
  showDelivery(quote.delivery.fee, quote.delivery.total);
} else if (quote.delivery) {
  showNotDeliverable();
}
```

Lorsqu'il est absent, n'inventez pas de frais. Les tarifs par défaut de
[Livraison et géographie](/fr/sdk/storefront/delivery) ne sont qu'une valeur provisoire ;
c'est le devis qui fixe ce que la commande facture.

## Coupons

Le devis porte le résultat du code :

```ts
type CouponOutcome =
  | { code: string; applied: true; discount: number; freeShipping: boolean }
  | { code: string; applied: false; reason: string; shortBy?: number; startsAt?: string };
```

Affichez la remise et la livraison gratuite appliquées, ou la raison. `reason`
est ouvert ; une raison que votre interface ne reconnaît pas doit être remplacée
par une phrase générique.

Un lien partageable peut porter le code :

```ts
import { couponFromUrl } from "@wocart/storefront";

const code = couponFromUrl(new URL(location.href));
```

Le navigateur peut aussi lire une valeur de devis reçue sans exécuter le schéma :

```ts
import { readCouponOutcome } from "@wocart/storefront";

const coupon = readCouponOutcome(value);
```

Utilisez-le lorsqu'une page est mise en cache séparément de ses scripts et peut
contenir la forme d'une autre version. N'utilisez pas de schéma dans le
navigateur.

### Un indice ou un refus

Certains refus portent sur le code — inconnu, hors de ses dates, épuisé, pas
pour cet acheteur — et d'autres sur le panier, qui ne remplit pas encore le
code : un minimum non atteint, un produit sous une autre offre, un téléphone
encore à saisir. `couponRefusalTone(reason)` les distingue, pour qu'un thème
formule un indice avec douceur et un refus clairement :

```ts
import { COUPON_REFUSAL_REASONS, couponRefusalTone } from "@wocart/storefront";

const tone = couponRefusalTone(outcome.reason); // "hint" or "refused"
```

Typez vos formulations sur `COUPON_REFUSAL_REASONS` (un `Record` sur la liste),
pour qu'une raison ajoutée par la plateforme fasse échouer votre vérification
de types au lieu d'arriver chez l'acheteur sous la phrase générale.


## Visibilité du panier

`config.cartEnabled` est l'interrupteur :

```astro
{config.cartEnabled && <CartDrawer />}
```

Une boutique dont le panier est désactivé ne doit livrer aucun balisage de panier,
aucune île Astro de panier et aucune requête de panier. Le formulaire de commande
directe du produit fonctionne toujours ; le panier est une surface
supplémentaire.

## Une boucle de tiroir sûre

1. Affichez immédiatement `getLines()`, avec le sous-total optimiste.
2. Temporisez un devis après la modification d'une ligne.
3. Remplacez l'affichage par les lignes, récompenses et totaux du serveur
   lorsque la réponse arrive.
4. Conservez la vue optimiste si le devis échoue ; la commande redemandera un
   devis.
5. Désactivez la commande tant qu'une ligne est bloquée ou que la livraison est
   indisponible.
6. Envoyez `basket.toOrderItems()` avec la commande, jamais un prix construit à
   la main.

<Callout type="caution" title="Un total du navigateur n'est pas un total de commande">
N'importe qui peut modifier `localStorage` et changer `unitPrice`. Le tiroir peut
afficher ce nombre de façon optimiste, mais le serveur recalcule le prix de
chaque ligne et résout à nouveau la livraison à la création de la commande.
N'affichez jamais un total calculé côté client comme montant à facturer.
</Callout>
