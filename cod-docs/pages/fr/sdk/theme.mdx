# SDK Theme

Un thème CodFlow est une vitrine Astro. `@wocart/storefront` lui fournit les
produits, les collections, les paniers et la commande. `@wocart/theme` est une
couche facultative qui permet aussi à un marchand de modifier les textes, les
images, les styles et l'ordre des sections du thème sans toucher au code.

Vous n'avez **pas** besoin de `@wocart/theme` pour construire un thème. Utilisez-le
lorsque vous voulez que le thème soit modifiable, réutilisable ou prêt à partager
avec d'autres boutiques.

C'est un petit paquet utilitaire, pas un framework. Votre projet Astro, vos
composants et votre CSS restent les vôtres ; le SDK ajoute les règles qui
rendent les modifications enregistrées des marchands sûres à lire et à rendre.

## Deux façons de construire

| | Une vitrine sur mesure | Un thème modifiable |
| --- | --- | --- |
| Qui modifie le design | Vous, dans le code | Vous dans le code ; un marchand modifie le contenu et la mise en page |
| Ce que vous écrivez | Des pages et des composants Astro | Des composants Astro, plus des définitions et des documents par défaut |
| Ce dont vous avez besoin | `@wocart/storefront` | `@wocart/storefront` et `@wocart/theme` |
| Où vivent les réglages | Votre code ou l'environnement | Des réglages enregistrés et des documents de page JSON |
| Bon pour | Une boutique au design figé | Des thèmes réutilisés entre boutiques, ou vendus comme produit |

Une vitrine sur mesure est le choix le plus simple. Un thème modifiable demande
plus de configuration parce que chaque choix modifiable doit être déclaré,
stocké et validé. Le reste de ce guide porte sur ce second parcours.

<Callout type="info" title="Une boutique, ou plusieurs ?">
Si le thème appartient à une seule boutique et que vous contrôlez chaque
modification dans le code, une vitrine Astro sur mesure suffit. Vous n'avez pas
besoin d'éditeur, de manifeste ni d'aperçu.

Si une autre boutique utilisera le thème — par la place de marché, un client, ou
un marchand qui le modifie dans CodFlow Studio — suivez le parcours modifiable.
C'est ce qui rend le thème portable sans que vous changiez son code pour chaque
boutique.
</Callout>

## Les mots que vous verrez

Ces mots apparaissent partout dans le guide. Vous n'avez pas besoin de les
mémoriser maintenant ; revenez-y lorsqu'une page en utilise un.

| Mot | Sens simple |
| --- | --- |
| **Composant** | Une pièce réutilisable d'une page, comme une section hero, une grille de produits ou un pied de page |
| **Champ** | Une chose qu'un marchand peut modifier dans un composant, comme un titre, une image ou une limite |
| **Instance** | Une copie d'un composant placée sur une page, avec ses propres valeurs enregistrées |
| **Document** | La liste ordonnée de sections et de blocs qui compose une page |
| **Surface** | Un endroit qu'un document remplit : la page d'accueil, un gabarit de produit, l'en-tête |
| **Slot** | Un espace nommé dans un composant où des blocs enfants peuvent être placés |
| **Réglage** | Un choix pour toute la boutique, comme une police ou les jeux de couleurs |
| **Manifeste** | Une description JSON de tout ce que le thème rend modifiable |
| **Clé de thème** | L'identifiant permanent d'un thème ; les modifications de marchand enregistrées sont stockées sous cette clé |

Dans un thème modifiable, une page n'est pas un fichier Astro figé. Astro rend un
**document** — des données qui indiquent quels composants apparaissent et quelles
valeurs ils portent. Le thème fournit les composants et leurs valeurs par défaut.

## Les deux moitiés

Le SDK sépare ce que seul le code peut savoir de ce qu'une boutique peut
enregistrer.

| | Qui appartient au code | Qui appartient aux données |
| --- | --- | --- |
| Ce que c'est | Définitions de composants, champs, valeurs par défaut, slots, fonctions `load` facultatives | Documents de page JSON et réglages de la boutique |
| Qui l'écrit | Le développeur du thème | Un marchand, un éditeur, une CLI ou un assistant |
| Quand c'est vérifié | À la compilation et au chargement du thème | À chaque lecture d'un document enregistré |
| Ce qui le lit | Le moteur de rendu et le manifeste | `parsePageData` et `validatePageData` |

Le **manifeste** relie les deux. Il transforme la moitié code en JSON simple, afin
qu'un outil puisse afficher les bons champs sans exécuter Astro ni le code du
thème.

## Ce que le paquet vous apporte

- **Un catalogue de composants typé.** Définissez un composant une fois ;
  obtenez ses types de champs et ses props depuis la même définition.
- **Des lectures sûres.** Un document enregistré endommagé ou obsolète est réparé
  lorsque c'est possible, signalé lorsque ce n'est pas possible, et ne fait jamais
  tomber toute la page.
- **Des règles de mise en page.** Les slots, les blocs requis, les blocs fixes et
  les limites sont appliqués lors de la modification d'un document, et non
  laissés à chaque composant.
- **Un seul moteur de rendu.** `InstanceView.astro` applique les valeurs par
  défaut, exécute les hooks `load` facultatifs côté serveur, rend les blocs
  enfants et appelle votre composant `.astro`.
- **Un manifeste JSON.** Les éditeurs et autres outils peuvent lire le thème
  sans importer de fichiers `.astro`.
- **La plomberie de l'édition.** Opérations sur les documents, marqueurs
  d'aperçu, pont d'aperçu, texte enrichi, réglages et traductions.

## Ce qu'il ne fait pas

Le paquet ne récupère pas de données de commerce (catalogue, commandes), ne téléverse pas d'images,
n'écrit pas dans la base de données et ne remplace pas Astro. Il valide et rend
ce qu'on lui donne. Les lectures commerciales viennent de
[`@wocart/storefront`](/fr/sdk/storefront) ; la persistance appartient à la
plateforme.

<Callout type="info" title="C'est le contrat du thème, pas le moteur de la vitrine">
Pour les lectures du catalogue, les paniers, la commande, les avis et le
contexte de la boutique, utilisez
[`@wocart/storefront`](/fr/sdk/storefront). Un hook `load` reçoit le
`StoreClient` côté serveur de ce paquet.
</Callout>

## Installation

```bash
npm install @wocart/theme @wocart/storefront
```

`@wocart/storefront` est un pair obligatoire : le contexte de rendu utilise son
`StoreConfig`, et les hooks `load` reçoivent son `StoreClient`. Astro 7 est un
pair facultatif, nécessaire uniquement pour le moteur de rendu `./astro`. Le
paquet est ESM uniquement et nécessite Node 22.12 ou plus récent pour
l'outillage.

<Callout type="caution" title="Choisissez la clé de thème avec soin">
`defineTheme({ key })` identifie un thème auprès du serveur. Les modifications de
texte des marchands sont stockées sous cette clé, et une vitrine ne les reçoit
que lorsque son client SDK transmet la même clé. La renommer rend orphelines toutes les
modifications de marchand effectuées sous l'ancien nom.
</Callout>
