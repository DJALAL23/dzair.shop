# Pages et rendu

Une **surface** est un endroit où un document peut être utilisé. `home` remplit
la page d'accueil, `product` remplit chaque page produit, et `area:header`
remplit l'en-tête de chaque page. Vous n'avez pas besoin de toutes en même temps ;
la plupart des thèmes commencent par `home` et `product`.

Chaque surface possède un **document** : une liste JSON des sections que cette
surface affiche et des valeurs que ces sections contiennent. Le thème livre un
document par défaut ; une boutique peut enregistrer le sien. Le SDK choisit celui
qui est rendu et répare les parties qui ne correspondent plus au thème.

## Surfaces

```ts
const productSurface: SurfaceSpec = {
  key: "product",
  label: "Product",
  pageType: "product",
  document: productDocument,
  required: [{ type: "product-main", min: 1, max: 1 }],
};
```

| Champ | Signification |
| --- | --- |
| `key` | La clé de surface stockée dans le document |
| `label` | Nom destiné à l'éditeur |
| `pageType` | Le type de page de la plateforme que la surface rend |
| `document` | La valeur par défaut livrée avec le thème |
| `required` | Sections de premier niveau qui doivent exister |
| `max` | Au plus ce nombre de sections de premier niveau (jusqu'à 50) |

Les types de page sont `home`, `catalog`, `category`, `collection`, `product`,
`page`, `landing`, `checkout` et `thankYou`.

### Gabarits

Un type de page avec une ressource — `product`, `category`, `collection`, `page`,
`landing` — fait de la surface un gabarit. Un seul document rend chaque produit,
catégorie ou page de ce type. La route lit d'abord la ressource et transmet les
paramètres de route :

```ts
const context: ThemeRenderContext = {
  // …
  params: { handle: "robe-kabyle" },
};
```

Les sections lisent la ressource via `context.params` et une clé de lecture qui
l'inclut, afin que la page et ses sections partagent une seule lecture.

### Variantes

Une surface peut être une variante d'une autre : `product.compact` est une
seconde mise en page produit. Sa base (`product`) doit être déclarée et rendre le
même type de page. `capabilities.surfaces: ["product"]` couvre aussi la variante.

## Zones

Une zone est une partie que chaque page partage — l'en-tête, le pied de page.
Elle est composée de sections comme une page et se modifie une fois pour toute la
boutique.

```ts
areas: [
  {
    key: "header",
    label: "Header",
    document: headerDocument,
    required: [{ type: "header", max: 1 }],
    max: 4,
  },
  { key: "footer", label: "Footer" },
],
```

Le document d'une zone est la surface `area:<key>` ; `areaSurface("header")`
construit cette chaîne. Un composant reste dans l'en-tête en déclarant
`capabilities: { surfaces: ["area:header"] }`.

## Le document

Un document de page est du JSON :

```json
{
  "version": 1,
  "surface": "home",
  "sections": [
    { "id": "hero-1", "type": "hero", "props": { "title": "Bienvenue" } },
    { "id": "faq-1", "type": "faq", "hidden": true }
  ]
}
```

`version` vaut `1`. `surface` est la clé de surface ou de zone. `sections` est le
niveau supérieur. Une instance possède `id`, `type`, et éventuellement `props`,
`children`, `slots`, `fixed` et `hidden`.

Un document peut aussi nommer sa provenance :

```json
{ "theme": { "key": "my-theme", "version": "1.0.0" } }
```

Un document qui nomme un autre thème est signalé (`theme-mismatch`) et la valeur
par défaut livrée est rendue à la place.

Les clés **de premier niveau** inconnues sont conservées telles quelles. Les clés
inconnues à l'intérieur d'une instance sont supprimées. L'enveloppe est compatible
avec les versions futures ; l'instance ne l'est pas.

## Ce qui est rendu

`resolveSurfaceDocument(theme, surface, saved, scope)` applique la politique :

| État enregistré | Rendu |
| --- | --- |
| Aucun document enregistré | La valeur par défaut livrée avec le thème |
| Enveloppe invalide (`page: null`) | La valeur par défaut livrée |
| La surface ou le thème ne correspond pas | La valeur par défaut livrée |
| Aucune section enregistrée ne correspond à un type du catalogue | La valeur par défaut livrée |
| Chevauchement partiel | Ce qui correspond ; les types inconnus ne rendent rien |
| Document enregistré vide | Vide — le marchand l'a vidé |

Il renvoie le document, sa source et la raison d'un repli :

```ts
const { page, source, reason, issues } = resolveSurfaceDocument(
  theme,
  "home",
  await store.client.pageData.get("home"),
  { content: store.content, locales: [store.locale, ...store.fallbackLocales] },
);
```

Le résultat est complété avec les blocs requis et fixes (`completePage`), afin
que ce que vous rendez soit ce que le contrat exige.

## Rendre une page

Un `InstanceView` par section, un cache de lecture par rendu de page :

```astro
---
import type { ThemeRenderContext } from "@wocart/theme";
import InstanceView from "@wocart/theme/astro/InstanceView.astro";
import { createReadCache } from "@wocart/theme/astro";
import { resolveSurfaceDocument } from "@wocart/theme";
import { theme } from "../theme/theme";

const store = Astro.locals.store;
const { page } = resolveSurfaceDocument(
  theme,
  "home",
  await store.client.pageData.get("home"),
  { content: store.content, locales: [store.locale, ...store.fallbackLocales] },
);
const context: ThemeRenderContext = {
  store: store.config,
  content: store.content,
  locale: store.locale,
  fallbackLocales: store.fallbackLocales,
  isRTL: store.isRTL,
  url: store.pathname,
};
const reads = createReadCache();
---
{page.sections.map((section) => (
  <InstanceView
    instance={section}
    theme={theme}
    context={context}
    storefront={store.client}
    reads={reads}
  />
))}
```

`InstanceView` est le moteur de rendu de référence. Pour une instance, il :

1. ignore une instance masquée,
2. trouve la définition par `type`,
3. résout les valeurs par défaut, les traductions, les champs et la composition,
4. exécute le hook `load` facultatif,
5. rend le composant du thème avec `props` et un handle `blocks`.

Un type inconnu ne rend rien ; le reste de la page survit. Un `load` qui lève une
exception est signalé comme `load-failed` et les props de base sont tout de même
rendues.

## Problèmes

Une page possède deux canaux de signalement :

- **Problèmes de données de page** issus de l'analyse et de la résolution :
  `unknown-type`, `unknown-prop`, `invalid-prop`, `missing-required-prop`,
  `unknown-slot`, `disallowed-child`, `duplicate-id`, `limit-exceeded`,
  `theme-mismatch` et d'autres.
- **Problèmes du moteur de rendu** ajoutent `missing-component`, `load-failed` et
  `multiple-slots-unsupported`.

Passez `onIssue` pour les collecter dans les tests ou les journaux :

```astro
<InstanceView
  instance={section}
  theme={theme}
  context={context}
  storefront={store.client}
  reads={reads}
  onIssue={(issue) => issues.push(issue)}
/>
```

Le rapporteur par défaut est `console.warn` avec un préfixe stable. Un problème
est une dégradation avec un rapport, pas une erreur levée.

## Un seul slot nommé par instance

Le moteur de rendu de référence remplit au plus **un slot nommé** par
instance. Le compilateur Astro ne peut extraire que le premier attribut
de slot dynamique dans l'objet des slots. Un second slot
nommé avec du contenu est signalé comme `multiple-slots-unsupported` et n'est pas
rendu. Un composant peut déclarer plusieurs slots ; il peut aussi
transférer les slots propres à Astro en son sein lorsqu'il a besoin d'en
remplir plus d'un.
