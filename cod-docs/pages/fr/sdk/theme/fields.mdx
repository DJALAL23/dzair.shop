# Champs

Un **champ** est un contrôle dans l'éditeur : une zone de texte, un sélecteur
d'image, un nombre, un sélecteur de couleur. Si quelque chose n'est pas un champ, un
marchand ne peut pas le modifier depuis les données enregistrées.

La définition du composant déclare le champ. Le manifeste le montre à l'éditeur.
Le document de page enregistre sa valeur. La valeur est vérifiée à nouveau à la
lecture de la page, donc un document enregistré ne peut pas contourner les
règles.

La plupart des thèmes commencent par `text`, `image`, `number` et `select`.
Ajoutez les autres types lorsque le composant en a besoin.

## Champs scalaires et textuels

| Type | Valeur enregistrée | Remarques |
| --- | --- | --- |
| `text`, `textarea` | chaîne ou table par langue | L'un de `default` ou `contentKey`, jamais les deux |
| `number` | nombre fini | `min`, `max` facultatifs ; avec `step`, les valeurs se situent sur une grille partant de `min` ou 0 |
| `boolean` | booléen | |
| `select` | l'une des `options` | `default` doit être une option ; `optionLabels` nomme chaque option |
| `url` | cible de lien sûre | Chemin du site, `#fragment`, `?query`, `http(s)://`, `mailto:` ou `tel:` ; les astuces de script et d'URL relative au protocole sont rejetées |
| `color` | `#rgb` ou `#rrggbb` | Un nom de couleur ou `url(…)` est rejeté |

`display` change la façon dont l'éditeur affiche un champ, jamais ce qui est
enregistré :

```ts
{
  key: "align",
  kind: "select",
  label: "Alignment",
  options: ["start", "center", "end"],
  optionLabels: { start: "Start", center: "Center", end: "End" },
  default: "center",
  display: "segmented",
}
```

## Références de boutique

Ces champs enregistrent un handle ou une clé, pas une copie des données.

| Type | Valeur enregistrée | Lire avec |
| --- | --- | --- |
| `menu` | handle de menu (`main-menu`) | `storefront.menus.get(handle)` |
| `collection` | handle de collection (`best-sellers`) | `storefront.products.list({ collection })` |
| `product` | handle de produit | `storefront.products.get(handle)` |
| `category` | slug de catégorie | `storefront.categories.list()` |
| `image` | clé d'objet média, jamais une URL | `mediaUrl(key, MEDIA_DOMAIN)` |
| `productList` | handles de produits ordonnés | `storefront.products.get(handle)` par élément |
| `collectionList` | handles de collections ordonnés | `storefront.collections.get(handle)` par élément |

`productList` et `collectionList` sont limités à 50 ; leurs handles doivent être
distincts. Un produit ou une collection supprimé se lit comme absent, pas comme
une erreur.

## Champs structurés

| Type | Valeur enregistrée | Remarques |
| --- | --- | --- |
| `richtext` | `{ type: "doc", version: 1, content }` ou un par langue | Forme fixe ; `formats` la restreint ; rendez avec `richTextToHtml` |
| `list` | `[{ id, props }]` | Champs d'élément de tout type sauf `list` et `colorSchemes` ; `itemLabel` nomme le champ de titre |
| `style` | `{ spacing?, layout?, size? }`, par point de rupture | Étapes et choix, jamais du CSS ; voir [Style et couleur](/fr/sdk/theme/style) |
| `colorScheme` | un identifiant de jeu de couleurs | La boutique doit posséder ce jeu |
| `colorSchemes` | `[{ id, name, colors }]` | Un réglage de thème, au plus un ; au plus 24 jeux |

Un document de texte enrichi contient des paragraphes, des titres 2–4, des listes
à puces et ordonnées, des sauts de ligne, du gras, de l'italique, du souligné, du
barré et des liens sûrs. Rien d'autre n'est représentable, donc une valeur
enregistrée ne peut pas contenir de balisage ni de scripts.

```astro
---
import { richTextToHtml } from "@wocart/theme";
const { body } = Astro.props;
---
{body && <div set:html={richTextToHtml(body, { href: store.href })} />}
```

`richTextToPlainText` donne les mots pour une méta-description ou un
`aria-label`. Un champ avec `inline: true` tient sur une ligne : un seul
paragraphe avec des marques de mise en forme et des liens, rendu sans élément de bloc.

L'`id` d'un élément de liste est unique dans sa liste, donc la réorganisation ne
change jamais l'identité des éléments. Les champs d'élément ne peuvent pas
utiliser `contentKey` : chaque élément lirait la même clé. Une valeur par défaut
de liste porte ses propres ids.

## Options de champ partagées

| Option | S'applique à | Ce qu'elle fait |
| --- | --- | --- |
| `key` | chaque champ | Le nom exact de la prop que reçoit le composant |
| `label` | chaque champ | Nom visible dans l'éditeur ; une chaîne ou une table par langue |
| `description` | chaque champ | Texte d'aide de l'éditeur |
| `required` | chaque champ | La valeur doit exister après le repli sur le contenu/la valeur par défaut |
| `visibleIf` | chaque champ | Condition réservée à l'éditeur, sur les champs voisins |
| `default` | la plupart des champs | Valeur à la création ; les images n'en ont pas |
| `contentKey` | `text`, `textarea` | Texte hérité du pack de contenu du thème |
| `optionLabels` | `select` | Mots de l'éditeur pour chaque option |
| `min`, `max`, `step` | `number`, listes | Bornes et grille / longueur de liste |
| `display` | `select`, `number` | `dropdown`, `radio`, `segmented`, `input` ou `slider` |
| `formats` | `richtext` | Mises en forme et blocs autorisés |
| `inline` | `richtext` | Mode une ligne |
| `itemLabel` | `list` | Champ d'élément que l'éditeur affiche comme titre |

`visibleIf` est une petite condition JSON fixe, pas une expression :

```ts
{
  key: "picked",
  kind: "productList",
  label: "Picked products",
  visibleIf: { field: "source", equals: "picked" },
}
```

Les conditions acceptent `{ field, equals }`, `{ field, in }`, `{ all }`,
`{ any }` et `{ not }`, imbriquées sur quatre niveaux au maximum. Le moteur de
rendu ignore la condition, et un champ masqué conserve sa valeur.

## Comment une valeur se résout

Pour un champ sur une instance, l'ordre est :

1. la valeur enregistrée de l'instance,
2. `content[contentKey]` pour les champs textuels,
3. le `default` du champ,
4. omis — la valeur par défaut de la prop du composant s'applique.

Une traduction manquante n'est pas une erreur. Une table malformée est
`invalid-prop` ; une clé inconnue est `unknown-prop` ; un champ requis sans valeur
est `missing-required-prop`.

Le côté écriture peut vérifier une valeur avant l'enregistrement :

```ts
import { checkFieldValue } from "@wocart/theme";

const result = checkFieldValue(field, value);
if (!result.ok) console.error(result.message);
```

La vérification côté écriture est plus stricte que celle côté lecture : une
référence d'image ou un élément de liste avec une clé non déclarée est refusé ici,
tandis que la lecture l'ignore.

## Props typées

Dérivez les props du composant depuis sa définition. Ne les écrivez pas deux fois.

```astro
---
import type { InferProps } from "@wocart/theme";
import type { bestSellers } from "./best-sellers.def";

const { products = [], limit } = Astro.props as InferProps<typeof bestSellers>;
---
```

`InferProps` :

- rend toujours présent un champ doté d'un `default`,
- rend tous les autres champs facultatifs,
- restreint un `select` à ses littéraux d'options,
- transforme `image` en `ResolvedImage` (avec `alt` déjà dans la langue rendue),
- transforme `list` en `{ id }` plus les champs d'élément,
- fusionne tout ce que `load` renvoie par-dessus les champs.

Le moteur de rendu fait la même fusion à l'exécution :
`{ ...resolved.props, ...loaded }`. Si le composant d'une définition lit une prop
depuis `load`, gardez ce nom hors de `fields`.

## Images et listes en pratique

Un champ image n'a pas de valeur par défaut car le thème ne peut pas connaître
les médias d'une boutique. Le composant rend son propre repli lorsqu'aucune image
n'a été choisie.

```astro
---
import type { InferProps } from "@wocart/theme";
const { image } = Astro.props as InferProps<typeof banner>;
---
{image && <img src={mediaUrl(image.key, MEDIA_DOMAIN)} alt={image.alt ?? ""} />}
```

Une valeur d'image porte aussi `width`, `height` et `focal` facultatifs (un point
de 0 à 1 sur chaque axe). Voir [Images](/fr/sdk/theme/images) pour le domaine des
médias et le service d'images Astro.

Une liste reçoit `[{ id, ...fields }]`. Le lecteur écarte un élément cassé ou
répété et garde le reste, jusqu'à `max`.
