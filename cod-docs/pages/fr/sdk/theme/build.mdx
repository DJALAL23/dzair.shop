# Construire un thème

Cette page vous mène d'un projet Astro à une section modifiable rendue sur une
page. C'est l'exemple complet le plus court ; les pages suivantes expliquent les
champs, la composition et l'intégration à la vitrine plus en détail.

## Ce que vous construisez

Un thème CodFlow est toujours un projet Astro. Vous écrivez des composants
`.astro` normaux. `@wocart/theme` vous demande d'ajouter une petite
**définition** à côté de chaque composant que vous voulez rendre modifiable par un
marchand.

Une définition répond à cinq questions :

| Question | Propriété de la définition |
| --- | --- |
| Comment ce composant est-il nommé dans les données enregistrées ? | `type` |
| Quel composant Astro le rend ? | `component` |
| Que peut modifier un marchand ? | `fields` |
| Peut-il contenir des blocs enfants ? | `slots` |
| A-t-il besoin de données supplémentaires du serveur ? | `load` |

La page que voit un acheteur est construite à partir d'un **document** : du JSON
qui indique quels composants apparaissent et quelles valeurs ils portent. Votre
code fournit les composants et leurs valeurs par défaut ; le document fournit les
choix du marchand.

<Callout type="info" title="Besoin seulement d'un design figé ?">
Si une seule boutique possède le thème et que personne ne le modifiera depuis un
tableau de bord, vous n'avez pas besoin de définitions, de documents ni de
manifeste. Construisez des pages Astro normales avec
[`@wocart/storefront`](/fr/sdk/storefront) et ignorez le reste de cette page.
</Callout>

## Installation

```bash
npm install @wocart/theme @wocart/storefront
```

Astro 7 est nécessaire pour le moteur de rendu et les composants `.astro`. Le
cœur est neutre vis-à-vis du framework, mais `InstanceView.astro`,
`ThemeStyles.astro` et les utilitaires sous `@wocart/theme/astro` sont spécifiques
à Astro.

## 1. Définir un composant

Une définition enveloppe un vrai composant. Les champs sont la surface
modifiable ; le hook `load` est un enrichissement côté serveur facultatif.

```ts
// src/theme/components/best-sellers.def.ts
import { defineComponent } from "@wocart/theme";
import BestSellers from "./BestSellers.astro";

export const bestSellers = defineComponent({
  type: "best-sellers",
  component: BestSellers,
  label: "Best sellers",
  fields: [
    {
      key: "collection",
      kind: "collection",
      label: "Collection",
      default: "best-sellers",
    },
    {
      key: "limit",
      kind: "number",
      label: "Number of products",
      default: 8,
      min: 1,
      max: 24,
    },
  ],
  load: async ({ storefront, props }) => ({
    products: await storefront.products.list({
      collection: props.collection,
      limit: props.limit,
    }),
  }),
});
```

`defineComponent` conserve les clés de champ, les types de champ (« kinds ») et les options de
sélection comme littéraux. Les props du composant sont dérivées de la même
définition :

```astro
---
// src/theme/components/BestSellers.astro
import type { InferProps } from "@wocart/theme";
import type { bestSellers } from "./best-sellers.def";

const { products = [] } = Astro.props as InferProps<typeof bestSellers>;
---
```

Un champ avec un `default` est toujours présent dans `props` ; un champ sans
valeur par défaut est facultatif. Tout ce que `load` renvoie est fusionné
par-dessus les valeurs des champs.

## 2. Assembler le catalogue

Le catalogue est l'unité que consomment le moteur de rendu et le validateur. Les
clés des composants doivent être égales à leur `type`, car les documents se
réfèrent au type.

```ts
// src/theme/theme.ts
import { defineTheme, type PageData, type SurfaceSpec } from "@wocart/theme";
import { bestSellers } from "./components/best-sellers.def";

const homeDocument = {
  version: 1,
  surface: "home",
  sections: [{ id: "best-sellers-1", type: "best-sellers" }],
} satisfies PageData;

const home: SurfaceSpec = {
  key: "home",
  label: "Home",
  pageType: "home",
  document: homeDocument,
};

export const theme = defineTheme({
  key: "my-theme",
  version: "1.0.0",
  surfaces: [home],
  components: { "best-sellers": bestSellers },
});
```

Le `document` d'une surface est la valeur par défaut livrée avec le thème.
`resolveSurfaceDocument` l'utilise lorsque la boutique n'a rien enregistré, ou
lorsque le document enregistré ne peut pas être rendu.

## 3. Valider le catalogue

Les définitions sont du code ; le validateur est donc un test à l'assemblage, pas
une garde à l'exécution.

```ts
import { validateThemeDefinition } from "@wocart/theme";
import { theme } from "./theme/theme";

const issues = validateThemeDefinition(theme);
if (issues.length > 0) {
  throw new Error(issues.map((issue) => `${issue.path}: ${issue.message}`).join("\n"));
}
```

Exécutez-le dans la suite de tests du thème. Il vérifie l'accord clé/type, les
règles des champs, les déclarations de slots, les blocs fixes, les blocs requis,
les préréglages, les clés de contenu et les documents par défaut.

## 4. Rendre la surface

Un `InstanceView` par section, un cache de lecture par rendu de page.

```astro
---
// src/pages/index.astro
import { resolveSurfaceDocument, type ThemeRenderContext } from "@wocart/theme";
import InstanceView from "@wocart/theme/astro/InstanceView.astro";
import { createReadCache } from "@wocart/theme/astro";
import { theme } from "../theme/theme";

const store = Astro.locals.store;
const saved = await store.client.pageData.get("home");
const { page } = resolveSurfaceDocument(theme, "home", saved, {
  content: store.content,
  locales: [store.locale, ...store.fallbackLocales],
});

const context: ThemeRenderContext = {
  store: store.config,
  content: store.content,
  locale: store.locale,
  fallbackLocales: store.fallbackLocales,
  isRTL: store.isRTL,
  url: store.pathname,
};

const reads = createReadCache();
---
{page.sections.map((section) => (
  <InstanceView
    instance={section}
    theme={theme}
    context={context}
    storefront={store.client}
    reads={reads}
  />
))}
```

Le cache de lecture est limité à **un rendu de page**. Les hooks `load` qui lisent
la même ressource partagent une requête ; un rejet est partagé aussi, donc une
lecture échouée ne réessaie pas une fois par section.

## 5. Émettre le manifeste

Les éditeurs et les outils de publication lisent le manifeste, pas le thème compilé.
Un endpoint prérendu le place à `/wocart-theme.json`.

```ts
// src/pages/wocart-theme.json.ts
import { themeManifestEndpoint } from "@wocart/theme/astro";
import { theme } from "../theme/theme";

export const prerender = true;
export const GET = themeManifestEndpoint(theme);
```

L'endpoint dérive et valide le manifeste au chargement du module. Un manifeste
invalide fait échouer la compilation au lieu d'être livré.
