# Réglages et textes

Un **réglage** est un choix pour toute la boutique — une police, le menu de
l'en-tête, les schémas de couleurs. Un **champ** est un choix pour une section.
Les deux utilisent les mêmes types de champs ; les réglages vivent dans des
groupes nommés et sont stockés à plat par clé.

## Déclarer un réglage

```ts
const theme = defineTheme({
  // …
  settings: [
    {
      key: "appearance",
      label: { en: "Appearance", fr: "Apparence" },
      fields: [
        {
          key: "headingFont",
          kind: "select",
          label: "Heading font",
          options: ["sans", "serif"],
          optionLabels: { sans: "Sans", serif: "Serif" },
          default: "sans",
        },
        {
          key: "colorSchemes",
          kind: "colorSchemes",
          label: "Color schemes",
          default: [/* … */],
        },
      ],
    },
  ],
});
```

| Règle | Effet |
| --- | --- |
| `key` du groupe | En kebab-case minuscule, unique dans le thème |
| `key` du champ | Unique dans **tous** les groupes ; c'est la clé stockée |
| `colorSchemes` | Au plus un dans le thème ; voir [Style et couleur](/fr/sdk/theme/style) |
| Réglages | Lus à plat : `values.headingFont`, pas `values.appearance.headingFont` |

## Lire les réglages d'une boutique

```ts
import { resolveThemeSettings } from "@wocart/theme";

const { values, issues } = resolveThemeSettings(theme, store.settings, {
  content: store.content,
  locales: [store.locale, ...store.fallbackLocales],
});
```

La priorité est :

1. la valeur du marchand,
2. la valeur par défaut du thème — ou son pack de contenu, pour un réglage
   textuel,
3. absente.

La lecture ne lève jamais d'exception. Une valeur que la déclaration n'accepte
plus est signalée (`invalid-setting` ou `missing-required-setting`) et la valeur
par défaut s'applique. Une clé que le thème ne déclare plus est signalée
(`unknown-setting`) et ignorée. Un objet stocké qui n'est pas un objet est signalé
(`invalid-settings`) et toutes les valeurs par défaut s'appliquent.

`InferSettings<typeof theme>` type le résultat : un réglage avec une valeur par
défaut est toujours présent ; tout autre peut être absent.

La couche d'écriture vérifie avant l'enregistrement :

```ts
import { checkThemeSettings } from "@wocart/theme";

const issues = checkThemeSettings(theme, candidate);
if (issues.length > 0) console.error(issues);
```

Elle vérifie aussi que chaque réglage `colorScheme` nomme un schéma que la
boutique possède réellement.

## Texte

Un champ texte peut prendre sa valeur initiale dans le **pack de contenu** du
thème :

```ts
{ key: "heroTitle", kind: "text", label: "Title", contentKey: "heroTitle" }
```

La valeur est résolue dans cet ordre :

1. la valeur enregistrée de l'instance,
2. `context.content[contentKey]`,
3. le `default` du champ,
4. omise — la valeur par défaut de la prop du composant s'applique.

`contentKey` et `default` s'excluent mutuellement. Un élément de liste ne peut pas
utiliser `contentKey` : chaque élément lirait la même chaîne. Un champ de texte
enrichi ne peut pas l'utiliser non plus, car un pack de contenu contient du texte
brut.

## Packs de contenu

Le thème possède ses textes et sa taxonomie. Le SDK ne modélise pas de système de
contenu ; il lit le pack résolu que la requête lui remet :

```ts
content: {
  en: { heroTitle: "Welcome", viewAll: "View all" },
  fr: { heroTitle: "Bienvenue", viewAll: "Tout voir" },
  ar: { heroTitle: "مرحبا", viewAll: "عرض الكل" },
}
```

- Le pack est un `Record<string, string>` **opaque et plat**. Toute structure de
  clés est le choix du thème.
- `ThemeRenderContext.content` est le pack **pour la langue courante**, avec les
  surcharges de la boutique déjà fusionnées.
- Déclarer des packs rend la vérification plus forte : `validateThemeDefinition(theme)`
  signale un `contentKey` absent d'un pack (`unknown-content-key`), et chaque
  langue déclarée doit avoir un pack.
- Si le thème ne déclare pas de packs, vérifiez par rapport à son propre ensemble
  de clés avec `validateThemeDefinition(theme, { contentKeys })`.
- Le thème peut aussi lire le pack entier et superposer ses propres valeurs
  résolues. Le SDK ne livre délibérément aucun assistant pour cela : cela ferait
  du modèle de textes d'un thème une API de plateforme.

Les modifications de texte sont indexées par la **clé du thème**. Une vitrine ne
les reçoit que lorsque son client SDK transmet le thème. Renommer la clé du thème
orpheline chaque modification de marchand enregistrée sous l'ancienne clé.

## Libellés communs à la boutique

Le pack est aussi l'endroit où vivent les libellés communs à la boutique —
« Ajouter au panier », « Épuisé », « Tout voir ». Un marchand peut les surcharger
dans CodFlow Studio. Dans un composant, lisez le libellé via un champ
`contentKey`, ou lisez le pack :

```ts
const labels = Astro.locals.store.content;
const addToCart = formatMessage(labels, "addToCart", {}, { locale });
```

Gardez une clé de libellé pour un seul sens. Si deux composants utilisent la même
clé avec un texte différent, une surcharge modifie les deux.

## Messages, pluriels et espaces réservés

`formatMessage` est l'unique règle de message du SDK. Elle suit le modèle des
fichiers de langue sur les données CLDR :

```ts
formatMessage(pack, "cartItems", { count: 3 }, { locale: "ar" });
```

| Règle | Exemple |
| --- | --- |
| Espaces réservés `{name}` | `"مرحبا {name}"` → la valeur est insérée, les nombres sont formatés pour la langue |
| Espace réservé inconnu | Reste visible (`{name}`), ne disparaît jamais |
| Pluriels | Clés plates par forme CLDR : `cartItems_one`, `cartItems_few`, `cartItems_other` |
| `_zero` | Utilisé pour un nombre de 0 dans toute langue, lorsqu'il existe |
| Clé manquante | Rend la clé elle-même, afin que le manque soit visible |

Ne construisez jamais un message avec `.replace("{n}")`. Une langue peut avoir
besoin d'une forme que les autres n'ont pas ; l'arabe en a six.
`pluralFormIssues(pack, locale)` liste les formes qu'un pack omet ou contient sans
jamais les utiliser. Exécutez-la sur chaque pack dans un test.
`messageForms(pack, key)` collecte les clés d'un message pour un script
navigateur.

## Langue et direction

`ThemeRenderContext` donne à une section ce dont elle a besoin :

| Valeur | Signification |
| --- | --- |
| `locale` | La langue rendue, première dans la chaîne de repli |
| `fallbackLocales` | La chaîne de repli de la boutique après elle |
| `isRTL` | Si la langue se lit de droite à gauche |
| `content` | Le pack résolu pour `locale` |

Une valeur traduite essaie `locale`, puis chaque entrée de `fallbackLocales`, puis
le pack de contenu, puis la valeur par défaut. Une traduction manquante n'est pas
une erreur.

`localize(value, [locale, ...fallbackLocales])` de `@wocart/theme` choisit la
première langue où une valeur existe, ou `undefined` lorsqu'elle n'en a aucune. Le
SDK applique la même chaîne aux valeurs de champ.

Les langues prises en charge par la plateforme et leur direction vivent dans
`cod-shared/i18n/locales.ts` ; un thème ne duplique jamais cette liste. Rendez
`dir={context.isRTL ? "rtl" : "ltr"}` sur le document, et utilisez des propriétés
CSS logiques pour que la mise en page suive.

<Callout type="caution" title="La clé du thème est son identité">
Les surcharges de texte du marchand sont indexées par `defineTheme({ key })`.
Changer la clé renomme le thème pour la plateforme et laisse les anciennes
surcharges derrière. Traitez cela comme un changement incompatible.
</Callout>
