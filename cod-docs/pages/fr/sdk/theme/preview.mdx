# Aperçu

L'aperçu permet à un marchand de modifier dans CodFlow Studio et de voir le
résultat sur la vraie vitrine : les mêmes composants, les mêmes données de
boutique et le même CSS qu'un client reçoit. Le marchand change une valeur ; la
page dans le cadre est rendue à nouveau.

Un thème s'y inscrit avec `preview: true` et sert une route à
**`/wocart-preview`**. Le manifeste indique à CodFlow Studio que la route existe.

Si votre thème est un design Astro figé et que personne ne le modifie depuis un
tableau de bord, vous n'avez pas besoin de cette page.

## Les trois parties

### 1. La requête

CodFlow Studio encadre :

```text
GET /wocart-preview?token=…&surface=home&locale=fr
```

`readPreviewRequest` de `@wocart/storefront/server` vérifie le jeton signé de
CodFlow Studio et renvoie le brouillon : quelle surface et quelle langue afficher,
et — une fois que Studio en envoie un — le document, les réglages et les
modifications de texte. Tout ce que le brouillon omet est rendu comme enregistré.

La route répond avec `previewResponseHeaders`, afin que seul Studio puisse
l'encadrer et qu'aucune réponse ne soit stockée. Aucune règle de route ne peut la
mettre en cache.

```ts
// src/middleware.ts
import { readPreviewRequest } from "@wocart/storefront/server";

const preview = await readPreviewRequest(context.request, {
  publicKey: WOCART_PREVIEW_KEY,
  theme: THEME_KEY,
});
if (!preview.ok) {
  return new Response(null, {
    status: preview.status,
    headers: { "Cache-Control": "no-store" },
  });
}
context.locals.preview = preview;
```

```astro
---
// src/pages/wocart-preview.astro
import { previewResponseHeaders } from "@wocart/storefront/server";

export const prerender = false;
const { claims, token } = Astro.locals.preview;
for (const [name, value] of Object.entries(previewResponseHeaders(claims))) {
  Astro.response.headers.set(name, value);
}
---
```

Le thème du jeton doit correspondre au thème qui sert la route ; un aperçu pour un
autre thème est refusé. Sans clé d'aperçu configurée, l'aperçu est désactivé et
chaque requête de ce type répond `404`.

### 2. Les marqueurs

`<InstanceView preview …>` encadre les nœuds de chaque instance avec deux
commentaires HTML :

```html
<!--wocart:start id=hero-1 type=hero-->
<section>…</section>
<!--wocart:end id=hero-1-->
```

Des commentaires, pas des éléments enveloppants, afin qu'une grille ou un
sélecteur `> *` se dispose exactement comme pour un client. Une instance masquée
garde ses marqueurs sans rien entre eux. La page d'un client n'en porte aucun.

Les assistants sont `previewStartMarker`, `previewEndMarker` et
`parsePreviewMarker`.

### 3. Le pont

`startPreviewBridge({ editorOrigin, token })` de `@wocart/theme/preview` s'exécute
sur la page d'aperçu. Il :

- signale chaque instance marquée à CodFlow Studio,
- transforme les clics en sélections en mode édition,
- rend à nouveau les brouillons que Studio envoie,
- remplace uniquement les sections dont le balisage a changé.

Il ne dessine rien. Les contours, barres d'outils et panneaux appartiennent à
Studio.

```astro
---
// src/pages/wocart-preview.astro
export const prerender = false;
const { claims, token } = Astro.locals.preview;
---
<Layout>
  {sections.map((instance) => (
    <InstanceView preview {instance} {theme} {context} {storefront} {reads} />
  ))}
  <wocart-preview-bridge data-editor={claims.editor} data-token={token} hidden />
</Layout>
<script>
  import { startPreviewBridge } from "@wocart/theme/preview";
  const host = document.querySelector<HTMLElement>("wocart-preview-bridge")!;
  startPreviewBridge({ editorOrigin: host.dataset.editor!, token: host.dataset.token! });
</script>
```

CodFlow Studio envoie un nouveau brouillon en le renvoyant à la route en JSON —
jamais un formulaire intersite, afin que `checkOrigin` d'Astro reste activé.

## Le protocole

Chaque message est `{ source, version, type, … }`. La page envoie
`source: "wocart-preview"` ; Studio envoie `source: "wocart-editor"`. Les deux
côtés publient avec l'origine exacte de l'autre et vérifient `event.origin` et
`event.source` avant de lire un message.

`PREVIEW_PROTOCOL_VERSION` vaut `1`.

| L'éditeur envoie | La page répond |
| --- | --- |
| — | `ready` avec chaque instance : `{ id, type, parent, hidden, rect }` |
| `render` `{ draft, revision? }` | `rendered` `{ revision, instances }`, ou `error` `{ revision, reason }` |
| `patch` `{ patches }` | la modification immédiatement, puis `layout` |
| `mode` `"edit"` ou `"interactive"` | en `edit`, les clics sélectionnent l'instance la plus interne ; en `interactive`, les liens et formulaires fonctionnent |
| `scroll-to` `{ id }` | l'instance défile dans la vue |
| `token` `{ token }` | le prochain rendu l'utilise |
| — | `hover` `{ id \| null }` pendant que le pointeur bouge ; `layout` après un défilement ou un redimensionnement |

La réponse à un rendu arrivée après un rendu plus récent — ou après un patch — est ignorée. Le
brouillon le plus récent l'emporte toujours.

## Patches

Un patch est une indication qui permet à la page de montrer un changement avant
l'arrivée du rendu lent. La page applique ce qu'elle trouve et laisse le reste au
rendu, qui est la vérité de la page. Un éditeur envoie toujours aussi le rendu ;
une page antérieure à 1.6.0 ignore les patches et montre quand même chaque
changement un instant plus tard.

| Patch | Ce qu'il montre |
| --- | --- |
| `move` `{ id, index, parent? }` | Une instance à un index parmi ses frères |
| `duplicate` `{ id, ids }` | Une copie juste après ; `ids` associe chaque id d'origine à sa copie |
| `remove` `{ id }` | L'instance et tout ce qu'elle contient ont disparu |
| `restore` `{ id, index, parent? }` | Ce qu'un remove a retiré, à un index |
| `hide` `{ id, hidden }` | L'instance affichée ou désactivée |
| `text` `{ id, from, to }` | Le texte à l'intérieur d'une instance a changé |

## Comportement navigateur dans une section

Les scripts d'une section remplacée ne s'exécutent pas à nouveau ; le
navigateur n'exécute jamais un script inséré par le balisage. Liez le
comportement d'une section avec `bindEach` de `@wocart/theme/lifecycle` : il lie
chaque élément correspondant une seule fois — au chargement, après que le
routeur d'Astro remplace la page, et après que l'aperçu insère une section — et
exécute le démontage renvoyé quand l'élément s'en va :

```ts
import { bindEach } from "@wocart/theme/lifecycle";

bindEach<HTMLElement>("[data-countdown]", (element) => {
  const timer = setInterval(() => tick(element), 1000);
  return () => clearInterval(timer);
});
```

Quand le pont remplace toute la page, il fait ce que fait le routeur d'Astro
après une navigation — un nouveau `<body>`, les attributs de l'élément racine,
le titre — et déclenche `astro:page-load`, si bien que le comportement d'une
page monté avec `onEachPage` se remonte comme là-bas. Les feuilles de style
modifiées sont remplacées sur place ; celles qui n'ont pas changé ne se
rechargent jamais. Un thème n'écoute jamais lui-même les événements de
remplacement.

## Ce que montre un aperçu

`previewTarget(theme, draft, client)` le décide une fois pour tous les thèmes.
Un modèle prévisualise la ressource que nomme le `path` du brouillon
(`/products/robe`), sinon le premier produit, la première catégorie, la première
collection par défaut ou la première page de texte de la boutique — et une
boutique qui n'en a aucun prévisualise quand même, le modèle vide pour qu'on
puisse en disposer les sections. Une zone (l'en-tête, le pied de page) se
prévisualise sur la page que nomme son `path` quand le thème compose cette page,
sinon sur l'accueil. La ressource est choisie par le `pageType` de la surface, si
bien qu'un modèle alternatif se prévisualise comme sa base. Une surface que le
thème ne déclare pas donne `null` : répondez 404.

```astro
---
import { createReadCache, previewTarget } from "@wocart/theme/astro";

const target = await previewTarget(theme, Astro.locals.preview.draft, Astro.locals.store.client);
if (!target) return new Response(null, { status: 404, headers: { "Cache-Control": "no-store" } });
---
<Sections surface={target.surface} params={target.params} document={target.document} preview={target.area === null} reads={createReadCache()} />
```

## Sécurité

| Contrôle | Effet |
| --- | --- |
| Jeton signé et expirant | Seule une vraie session d'éditeur peut ouvrir un aperçu |
| `previewResponseHeaders` | Seul cet éditeur peut l'encadrer ; il n'est pas stocké |
| POST avec JSON pour un nouveau brouillon | Pas de formulaire intersite ; `checkOrigin` reste activé |
| `editorOrigin` exact | Le pont ne publie nulle part ailleurs |
| Vérifications de `event.origin` et `event.source` | Seul l'éditeur qui encadre est entendu |
| Vérifications de `source` et `version` | Un message ancien ou étranger est ignoré |
| Marqueurs uniquement en aperçu | La page d'un client ne contient aucune métadonnée d'aperçu |

Un aperçu n'est jamais mis en cache. Il peut contenir un brouillon non enregistré,
un prix brouillon ou un produit brouillon qu'un client ne doit pas voir.
