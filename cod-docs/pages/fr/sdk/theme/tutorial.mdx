# Construire un thème complet

[Construire un thème](/sdk/theme/build) s'arrête à une section affichée. Cette
page va jusqu'au bout : un projet Astro vide devient un thème avec un layout
partagé, une page d'accueil éditable, un gabarit produit, une route produit
capable de renvoyer un 404, sa feuille de style, un manifeste, des tests de
contrat et un build déployable.

Tout ce qui suit est le contrat publié de `@wocart/theme` 2.1.0 et
`@wocart/storefront` 1.19.0. Là où Theme-00 fait un autre choix,
[l'analyse de l'implémentation de référence](/sdk/theme/reference-implementation)
le dit.

<Callout type="info" title="Une vitrine sur mesure reste le chemin court">
Si une seule boutique possède le thème et que vous le modifiez dans le code,
sautez cette page et écrivez des pages Astro classiques avec
[`@wocart/storefront`](/sdk/storefront). La composition, les documents et le
manifeste existent pour qu'un marchand puisse éditer le thème sans vous.
</Callout>

## Ce que vous obtenez

```text
my-theme/
├─ astro.config.mjs
├─ src/
│  ├─ theme/
│  │  ├─ sdk.ts                     un client serveur par appel
│  │  ├─ theme.ts                   defineTheme(...) — le catalogue
│  │  ├─ content.ts                 le texte du thème, par langue
│  │  ├─ components/
│  │  │  ├─ Hero.astro
│  │  │  ├─ ProductMain.astro
│  │  │  └─ ProductOrder.astro
│  │  ├─ definitions/
│  │  │  ├─ hero.def.ts
│  │  │  ├─ product-main.def.ts
│  │  │  └─ product-order.def.ts
│  │  ├─ documents/
│  │  │  ├─ home.page.json
│  │  │  └─ product.page.json
│  │  ├─ layouts/StoreLayout.astro
│  │  └─ sections/Sections.astro
│  └─ pages/
│     ├─ index.astro
│     ├─ products/[handle].astro
│     ├─ wocart-theme.json.ts
│     └─ wocart-styles.css.ts
└─ src/theme/__tests__/contract.test.ts
```

Les définitions sont du code, les documents du JSON, et les deux vivent à côté
des composants qu'ils décrivent. Rien en dehors de `src/theme/` n'a besoin de
savoir comment le SDK fonctionne.

## 1. Créer le projet

```sh
npm create astro@latest my-theme -- --template minimal --typescript strict
cd my-theme
npm install @wocart/theme @wocart/storefront
npx astro add node          # ou l'adaptateur de votre hébergeur ; Theme-00 utilise Cloudflare
npm install -D vitest @astrojs/check typescript
```

`@wocart/storefront` est un peer obligatoire de `@wocart/theme`, `zod` est son
propre peer, et npm installe les deux pour vous. Astro 7 est nécessaire pour le
moteur de rendu. Les paquets sont ESM uniquement et demandent Node 22.12 ou plus
pour l'outillage.

## 2. Deux valeurs serveur

```js
// astro.config.mjs
import { defineConfig, envField } from "astro/config";

export default defineConfig({
  env: {
    schema: {
      COD_SERVER_URL: envField.string({ context: "server", access: "secret" }),
      STORE_API_KEY: envField.string({ context: "server", access: "secret" }),
    },
  },
});
```

Aucune des deux n'est une variable `PUBLIC_*`. La clé est un secret de boutique ;
seuls les modules serveur la lisent.

## 3. Une seule couture SDK

Chaque thème a exactement un endroit qui construit le client. Les pages jamais.

```ts
// src/theme/sdk.ts — serveur uniquement
import { createStoreClient } from "@wocart/storefront/server";
import { COD_SERVER_URL, STORE_API_KEY } from "astro:env/server";
import { THEME_KEY } from "./theme";

export function getStoreClient(locale?: string) {
  return createStoreClient({
    serverUrl: COD_SERVER_URL,
    apiKey: STORE_API_KEY,
    theme: THEME_KEY,
    ...(locale === undefined ? {} : { locale }),
    onError: (error) => {
      console.warn(`[theme] degraded read: ${error.operation} (${error.code})`);
    },
  });
}
```

Trois détails comptent. `theme` est la clé déclarée par `defineTheme`, donc les
éditions de texte et les documents de page de ce thème arrivent ; sans elle, ils
n'arrivent pas. `locale` n'est renseigné que pour une langue autre que la
principale. `onError` est le seul endroit où un thème voit une lecture dégradée,
parce que les lectures ne lèvent jamais.

## 4. Un composant, une définition

```astro
---
// src/theme/components/Hero.astro
import type { InferProps } from "@wocart/theme";
import type { hero } from "../definitions/hero.def";

const { title, subtitle } = Astro.props as InferProps<typeof hero>;
---
<section class="hero">
  <h1>{title}</h1>
  {subtitle && <p>{subtitle}</p>}
</section>
```

```ts
// src/theme/definitions/hero.def.ts
import { defineComponent } from "@wocart/theme";
import Hero from "../components/Hero.astro";

export const hero = defineComponent({
  type: "hero",
  component: Hero,
  label: { ar: "الواجهة", fr: "Bannière", en: "Hero" },
  fields: [
    { key: "title", kind: "text", label: { ar: "العنوان", fr: "Titre", en: "Title" }, contentKey: "heroTitle" },
    { key: "subtitle", kind: "text", label: { ar: "العنوان الفرعي", fr: "Sous-titre", en: "Subtitle" }, contentKey: "heroSubtitle" },
  ],
});
```

`contentKey` nomme une clé du pack de contenu du thème : le marchand édite une
chaîne par langue plutôt qu'une copie stockée par instance. Un champ sans
`contentKey` ni `default` est absent de `props` — le composant doit gérer sa
propre valeur de repli.

## 5. Le thème et son texte

```ts
// src/theme/content.ts
export const content = {
  ar: { heroTitle: "توصيل لكل الولايات", heroSubtitle: "الدفع عند الاستلام" },
  fr: { heroTitle: "Livraison partout en Algérie", heroSubtitle: "Paiement à la livraison" },
  en: { heroTitle: "Delivered across Algeria", heroSubtitle: "Cash on delivery" },
};
```

```ts
// src/theme/theme.ts
import { defineTheme, type SurfaceSpec } from "@wocart/theme";
import { hero } from "./definitions/hero.def";
import { productMain } from "./definitions/product-main.def";
import { productOrder } from "./definitions/product-order.def";
import { content } from "./content";
import homeDocument from "./documents/home.page.json";
import productDocument from "./documents/product.page.json";

export const THEME_KEY = "my-theme";
export const THEME_VERSION = "1.0.0";

const home: SurfaceSpec = { key: "home", label: "Home", pageType: "home", document: homeDocument as never };
const product: SurfaceSpec = {
  key: "product",
  label: "Product",
  pageType: "product",
  document: productDocument as never,
  required: [{ type: "product-main", max: 1 }],
};

export const theme = defineTheme({
  key: THEME_KEY,
  version: THEME_VERSION,
  locales: ["ar", "fr", "en"],
  content,
  surfaces: [home, product],
  components: { hero, "product-main": productMain, "product-order": productOrder },
});
```

Chaque clé du catalogue égale toujours le `type` de sa définition — un document
référence le type, et le manifeste est indexé de la même façon. Les fichiers
`documents/*.json` sont du JSON simple (Astro active `resolveJsonModule`), donc
un document livré se lit, se diff et se relit comme n'importe quel fichier. Les
casts `as never` ci-dessus ne servent qu'à cause du typage lâche d'un module JSON
importé ; `parsePageData` vérifie réellement le document à l'étape 8.

## 6. La surface produit garde un formulaire de commande

Une surface dont le `pageType` est `product` doit garantir un formulaire de
commande, sinon l'assemblage échoue avec `order-form-not-guaranteed`. La
garantie se compte sur les entrées `required` de la surface : la section qui
place le formulaire doit donc y figurer — et son bloc fixe (ou une entrée de slot
requise) doit atteindre le composant dont le `role` est `order-form`. C'est
pourquoi `product` déclare plus haut `required: [{ type: "product-main", max: 1 }]`.

```ts
// src/theme/definitions/product-order.def.ts
import { defineComponent } from "@wocart/theme";
import ProductOrder from "../components/ProductOrder.astro";

export const productOrder = defineComponent({
  type: "product-order",
  component: ProductOrder,
  role: "order-form",
  label: { ar: "نموذج الطلب", fr: "Formulaire de commande", en: "Order form" },
  fields: [{ key: "submitLabel", kind: "text", label: "Button", default: "Order now" }],
});
```

```ts
// src/theme/definitions/product-main.def.ts
import { defineComponent } from "@wocart/theme";
import ProductMain from "../components/ProductMain.astro";

export const productMain = defineComponent({
  type: "product-main",
  component: ProductMain,
  label: { ar: "المنتج", fr: "Produit", en: "Product" },
  fixed: [{ name: "order", type: "product-order", label: "Order form" }],
});
```

Les *champs* du formulaire de commande ne sont pas ceux du thème : le formulaire
de commande d'une boutique est défini dans le tableau de bord marchand et imposé
par le serveur. Le thème fournit le balisage et envoie le panier ou le produit
(§10).

## 7. Les documents

`src/theme/documents/home.page.json` :

```json
{
  "version": 1,
  "surface": "home",
  "sections": [{ "id": "home-hero", "type": "hero" }]
}
```

`src/theme/documents/product.page.json` :

```json
{
  "version": 1,
  "surface": "product",
  "sections": [{ "id": "product-main", "type": "product-main" }]
}
```

L'`id` est unique dans le document et stable : l'édition d'un marchand est
stockée dessus. Omettez `props` pour hériter de chaque `default` et du texte du
pack de contenu.

## 8. Le composant de composition

Un seul composant rend n'importe quelle surface : on résout le document, puis on
rend chaque section via `InstanceView` avec un cache de lecture pour la page.

```astro
---
// src/theme/sections/Sections.astro
import InstanceView from "@wocart/theme/astro/InstanceView.astro";
import { createReadCache } from "@wocart/theme/astro";
import { resolveSurfaceDocument, type ThemeDefinition } from "@wocart/theme";

interface Props {
  theme: ThemeDefinition;
  surface: string;
  document: unknown;
  params?: Readonly<Record<string, string | undefined>>;
}

const { theme, surface, document, params = {} } = Astro.props;
const store = Astro.locals.store;

const { page, source, issues } = resolveSurfaceDocument(theme, surface, document, {
  content: store.content,
  locales: [store.locale, ...store.fallbackLocales],
});
if (import.meta.env.DEV) console.info(`[theme] ${surface}: ${source}`, issues);

const context = {
  store: store.config,
  content: store.content,
  locale: store.locale,
  fallbackLocales: store.fallbackLocales,
  isRTL: store.isRTL,
  url: store.url.pathname,
  params,
};
const reads = createReadCache();
---
{page.sections.map((section) => (
  <InstanceView
    instance={section}
    theme={theme}
    context={context}
    storefront={store.client}
    reads={reads}
  />
))}
```

`Astro.locals.store` est votre convention, pas celle du SDK : c'est ce que votre
middleware y place (§9). `InstanceView` n'a besoin que d'un `StoreClient`, du
`ThemeRenderContext` ci-dessus et d'un `ReadCache` limité à ce rendu.

## 9. Layout, zones et contexte de requête

Le layout porte les parties communes à toutes les pages. Une zone se compose
comme une page et s'édite une fois : l'en-tête est donc aussi un document.

```astro
---
// src/theme/layouts/StoreLayout.astro
import Sections from "../sections/Sections.astro";
import ThemeStyles from "@wocart/theme/astro/ThemeStyles.astro";
import { theme } from "../theme";

const store = Astro.locals.store;
const saved = await store.client.pageData.get("area:header");
---
<html lang={store.locale} dir={store.isRTL ? "rtl" : "ltr"}>
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <ThemeStyles />
  </head>
  <body>
    <header><Sections theme={theme} surface="area:header" document={saved} /></header>
    <main><slot /></main>
  </body>
</html>
```

`areaSurface("header")` renvoie la même chaîne `"area:header"` que le SDK
stocke : un littéral et l'aide ne peuvent pas diverger. Gardez la structure fixe
(le layout, le tiroir du panier) hors des données de page : un marchand édite des
sections, pas le cadre.

`<ThemeStyles />` sans props lie la feuille de style et n'écrit aucun schéma de
couleurs. Pour en offrir au marchand, déclarez un réglage `colorSchemes` et
passez
`schemes={resolveThemeSettings(theme, store.config.themeSettings, scope).values.colorSchemes}`
— voir [Style et couleur](/sdk/theme/style).

Le contexte de boutique est un travail de middleware, et c'est là que la langue
se décide :

```ts
// src/middleware.ts
import { defineMiddleware } from "astro:middleware";
import { localeRouting, resolveLocalePath } from "@wocart/storefront";
import { getStoreClient } from "./theme/sdk";
import { content } from "./theme/content";

export const onRequest = defineMiddleware(async (context, next) => {
  const config = await getStoreClient().config.get();
  if (config === null) return next();                 // config est une lecture dégradée

  const routing = localeRouting(config);
  const resolved = resolveLocalePath(context.url.pathname, routing);
  if (resolved.kind === "redirect") return context.redirect(resolved.location, 302);

  const language = config.locales.find((entry) => entry.code === resolved.locale);
  const pack = content[resolved.locale as keyof typeof content] ?? content.en;

  context.locals.store = {
    client: getStoreClient(resolved.locale),
    config,
    locale: resolved.locale,
    fallbackLocales: resolved.locale === routing.primary ? [] : [routing.primary],
    content: { ...pack, ...(config.contentOverrides[resolved.locale] ?? {}) },
    isRTL: language?.direction === "rtl",
    url: context.url,
    pathname: resolved.pathname,
  };
  return next();
});
```

`config.contentOverrides` ne contient les éditions du marchand que pour **cette**
langue (elles arrivent quand le client a passé `theme`) ; fusionner la carte
d'une autre langue est l'erreur qui affiche du français à un acheteur arabophone.
`localeRouting` et `resolveLocalePath` font de la langue principale celle sans
préfixe : c'est la configuration de la boutique qui décide de la forme des URL.

## 10. Les routes

```astro
---
// src/pages/index.astro
import StoreLayout from "../theme/layouts/StoreLayout.astro";
import Sections from "../theme/sections/Sections.astro";
import { theme } from "../theme/theme";

const saved = await Astro.locals.store.client.pageData.get("home");
---
<StoreLayout>
  <Sections theme={theme} surface="home" document={saved} />
</StoreLayout>
```

```astro
---
// src/pages/products/[handle].astro
import StoreLayout from "../../theme/layouts/StoreLayout.astro";
import Sections from "../../theme/sections/Sections.astro";
import { theme } from "../../theme/theme";

const store = Astro.locals.store;
const product = await store.client.products.get(Astro.params.handle!);
if (product === null) return Astro.rewrite("/404");

const saved = await store.client.pageData.get("product");
---
<StoreLayout>
  <Sections theme={theme} surface="product" document={saved} params={Astro.params} />
</StoreLayout>
```

Une surface gabarit lit sa ressource dans la route puis de nouveau dans le `load`
d'une section ; le cache de lecture de la page est ce qui en fait une seule
requête. Passez le cache quand la route a déjà lu la ressource :

```ts
import { createReadCache } from "@wocart/theme/astro";

const reads = createReadCache();
const product = await reads.get(`product:${handle}`, () => store.client.products.get(handle));
// rendre <Sections … reads={reads} />, et donner ce même cache aux sections
```

La section qui affiche le produit le lit avec la même clé :

```ts
load: async ({ storefront, context, reads }) => {
  const handle = context.params?.handle;
  if (handle === undefined) return { product: null };
  return { product: await reads.get(`product:${handle}`, () => storefront.products.get(handle)) };
},
```

Le retour de `load` est fusionné par-dessus les champs : un composant typé avec
`InferProps<typeof productMain>` voit `product` parmi ses props.

## 11. Points d'entrée de style et de manifeste

Deux points d'entrée prérendus complètent un thème éditable. Leurs chemins sont
des constantes, pas des choix :

```ts
// src/pages/wocart-styles.css.ts
import { themeStylesEndpoint } from "@wocart/theme/astro";
import { theme } from "../theme/theme";

export const prerender = true;
export const GET = themeStylesEndpoint(theme);
```

```ts
// src/pages/wocart-theme.json.ts
import { themeManifestEndpoint } from "@wocart/theme/astro";
import { theme } from "../theme/theme";

export const prerender = true;
export const GET = themeManifestEndpoint(theme);
```

`themeStylesEndpoint` sert les classes qu'une valeur `style` du marchand peut
nommer (`THEME_STYLES_PATH`, `/wocart-styles.css`), générées à partir des tailles
que le thème déclare. `themeManifestEndpoint` sert `THEME_MANIFEST_PATH`
(`/wocart-theme.json`) et **fait échouer le build** quand le manifeste est
invalide — volontairement : un manifeste cassé ne doit pas être publié.

Pour que les pas aient une taille, déclarez-les sur le thème :

```ts
style: { spacing: { s0: 0, s2: 8, s4: 16, s6: 32 }, widths: { wide: 1280, content: 960 } },
```

Un pas sans taille n'a aucune classe ; une valeur enregistrée qui le nomme est
rendue sans style et signalée. Voir [Style et couleur](/sdk/theme/style).

## 12. Valider et tester avant de faire confiance à un rendu

```ts
// src/theme/__tests__/contract.test.ts
import { describe, expect, it } from "vitest";
import {
  themeManifest,
  validatePageData,
  validateThemeDefinition,
  validateThemeManifest,
} from "@wocart/theme";
import { theme } from "../theme";
import { content } from "../content";

describe("the theme contract", () => {
  it("assembles without issues", () => {
    expect(validateThemeDefinition(theme, { contentKeys: Object.keys(content.en) })).toEqual([]);
  });

  it("round-trips its manifest", () => {
    const checked = validateThemeManifest(JSON.parse(JSON.stringify(themeManifest(theme))));
    expect(checked.manifest).not.toBeNull();
    expect(checked.issues).toEqual([]);
  });

  it("ships documents that validate in every language", () => {
    for (const language of theme.locales ?? []) {
      const pack = content[language as keyof typeof content];
      for (const surface of theme.surfaces ?? []) {
        if (surface.document === undefined) continue;
        const scope = { content: pack, locales: [language] };
        expect(validatePageData(theme, surface.document, scope)).toEqual([]);
      }
    }
  });
});
```

`contentKeys` est la vérification qu'aucune autre couche ne peut faire : une faute
de frappe dans un `contentKey` est invisible au rendu, parce que le champ
retombe silencieusement sur sa valeur par défaut. [Tester un thème](/sdk/theme/testing)
ajoute les vérifications de rendu et les cas de document enregistré.

## 13. Construire et déployer

```sh
npx astro check
npm test
npm run build
```

C'est le build qui échoue sur un import serveur dans un script navigateur, sur une
page prérendue qui lit des données de requête, ou sur un manifeste invalide.
Placez `COD_SERVER_URL` et `STORE_API_KEY` dans le coffre de secrets de
l'hébergeur (jamais dans le dépôt), et pointez l'URL sur l'origine API réelle de
la boutique : un Worker déployé ne peut pas joindre `localhost`.

Deux fonctions sont optionnelles et pilotées par la plateforme :

- **Aperçu** — CodFlow Studio envoie un jeton signé à `THEME_PREVIEW_PATH` ; le
  thème le vérifie avec `readPreviewRequest` et rend avec `preview` activé. Voir
  [Aperçu](/sdk/theme/preview).
- **Publication** — après une publication marchande, la plateforme demande au
  thème de vider ses pages en cache (`REVALIDATE_PATH`, vérifié avec
  `readRevalidateRequest`). Un thème qui cache ses rendus doit l'implémenter ; un
  thème qui ne cache pas n'en a pas besoin.
