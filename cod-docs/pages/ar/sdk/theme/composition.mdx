# التركيب

تخيّل الصفحة شجرة. تحتوي الصفحة على **أقسام**، ويمكن للقسم أن يحتوي على
**كتل** أصغر، ويمكن للكتلة أن تحتوي على كتل أيضًا. والمساحة المسماة التي
يقبل فيها المكوّن عناصر فرعية هي **فتحة**.

بعض الكتل يجب أن تكون موجودة دائمًا: فلا يمكن لصفحة منتج أن تفقد زر الشراء،
مثلًا. يطبّق SDK هذه القواعد عند تحرير المستند، فيثق محرّك العرض بالمستند الذي
يستقبله.

يمكنك تخطي هذه الصفحة إذا لم يكن قالبك يحتوي على أقسام قابلة للتحرير أو كتل
متداخلة. وإذا كنت مبتدئًا، فابدأ بالأقسام ولا تُضف الفتحات إلا عندما يحتاج
القسم فعلًا إلى كتل فرعية.

## الأقسام والكتل

| الموضع | أين يمكن أن يوجد |
| --- | --- |
| `"section"` | المستوى الأعلى لسطح أو منطقة |
| `"block"` | داخل فتحة فقط |
| `"both"` | في أي مكان |
| غائب | في أي مكان |

تفرض عمليات المستند الموضع. ولا يرفض محرّك العرض قسمًا محفوظًا لأنه في المكان
«الخاطئ»؛ بل يعرضه، ويبلّغ `validatePageData` بالمشكلة.

## إعلان فتحة

الفتحة مكان مسمّى يسمح فيه المكوّن بقبول العناصر الفرعية.

```ts
const productMain = defineComponent({
  // …
  slots: [
    {
      name: "info",
      allow: [
        "product-title",
        "product-rating",
        "product-price",
        "product-order",
      ],
      max: 16,
      required: [{ type: "product-order", max: 1 }],
    },
  ],
});
```

| القاعدة | الأثر |
| --- | --- |
| `name` | `"default"` أو اسم بحروف صغيرة بنمط kebab-case |
| `multiple: false` | يُبقي أول عنصر فرعي ويبلّغ بالباقي |
| `allow` | أنواع المكوّنات هذه فقط؛ وإذا غاب فالمعنى أي نوع |
| `max` | حد أقصى لعدد النسخ (حتى 50) |
| `required` | هذه الأنواع يجب أن تكون موجودة؛ ولكل منها `min` / `max` خاص |

يُطبَّق `allow` قبل `multiple: false`، فلا يزاحم عنصر فرعي غير مسموح عنصرًا
مسموحًا. وتضييق `allow` لاحقًا تغيير كاسر للصفحات المحفوظة: فالعناصر الفرعية
التي لم تعد مناسبة تُسقط بالرمز `disallowed-child`.

العنصر الفرعي في فتحة غير معلنة يُسقط بالرمز `unknown-slot`. والمكوّن الذي ليس
لديه فتحة `default` يُسقط العناصر الفرعية المدفوعة كافتراضي بالرمز
`undeclared-children`.

## عرض الكتل

يمنح محرّك العرض كل مكوّن خاصية `blocks`. ويضع المكوّن كل فتحة حيث يريد
التصميم، وكل كتلة ثابتة حيث تنتمي.

```astro
---
import Blocks from "@wocart/theme/astro/Blocks.astro";
import Block from "@wocart/theme/astro/Block.astro";
import { hasBlocks, type BlocksHandle } from "@wocart/theme/astro";

const { blocks } = Astro.props as { blocks: BlocksHandle };
---
<section>
  {hasBlocks(blocks, "info") && (
    <div class="info"><Blocks of={blocks} slot="info" /></div>
  )}
  <Block of={blocks} name="gallery" />
</section>
```

يعرض `<Blocks>` أبناء الفتحة عبر `InstanceView`، لذا تعمل `load` والمشكلات
والكتل المخفية وعلامات المعاينة في كل عمق. ويظل `<slot />` يعمل للعناصر
الفرعية الافتراضية؛ ويمكن للمكوّن استخدام أي من الآليتين.

`blocks` محجوز. ولا يجوز لأي حقل استخدام هذا المفتاح.

تكون `hasBlocks(blocks, slot)` صحيحة عندما تحتوي الفتحة على كتلة مرئية واحدة
على الأقل، ليتمكن المكوّن من تجنب غلاف فارغ. وتكون `isPreview(blocks)` صحيحة في
معاينة CodFlow Studio، حيث يمكن لقسم لا يملك ما يعرضه بعد أن يرسم عنصرًا
نائبًا. ولا يرى المتسوق ذلك العنصر النائب أبدًا.

## الكتل الثابتة

الكتلة الثابتة يضعها كود المكوّن نفسه. ويمكن للمحرر تغيير حقولها وملء فتحاتها،
لكنه لا يستطيع حذفها أو نقلها أو تكرارها أو إخفاءها.

```ts
const productMain = defineComponent({
  // …
  fixed: [{ name: "gallery", type: "product-gallery", label: "Gallery" }],
});
```

```astro
<Block of={blocks} name="gallery" />
```

تُعرض الكتلة حتى عندما لا يخزّنها المستند، باستخدام قيمها الافتراضية. ويُشتق
معرّفها من المالك والاسم (`fixedBlockId`). وتُزال القيم المخزّنة لكتلة ثابتة لم
يعد التعريف يعلنها بالرمز `unknown-fixed`؛ ويُستبدل النوع الخاطئ بقيمة
افتراضية ويُبلَّغ بالرمز `fixed-type-mismatch`.

## الكتل المطلوبة

يمكن للكتلة المطلوبة أن تتحرك، لكنها لا تستطيع أن تختفي. وتسردها الفتحة أو
السطح:

```ts
slots: [
  {
    name: "info",
    allow: ["product-order", "product-countdown"],
    required: [{ type: "product-order", max: 1 }],
  },
]
```

ترفض العمليات حذف آخر `min` من نوع مطلوب أو إخفاءه أو نقله خارج موضعه، أو
الإدراج بعد `max` الخاص به. والمستند الذي يفتقدها — مستند قديم، أو محفوظ قبل
تحديث القالب — يعرضها رغم ذلك، مضافةً في نهاية فتحتها، ويبلّغ القارئ بالرمز
`missing-required-block`.

**سطح المنتج يجب أن يضمن نموذج طلب.** أعطِ مكوّن نموذج الطلب
`role: "order-form"` واطلبه عبر قسم أو كتلة ثابتة أو فتحة. ويرفض التجميع سطح
منتج لا يفعل ذلك (`order-form-not-guaranteed`).

```ts
const productOrder = defineComponent({
  type: "product-order",
  role: "order-form",
  // …
});
```

حقول نموذج الطلب ليست حقول القالب: فنموذج إتمام الطلب في المتجر يُضبط في لوحة
تحكم التاجر ويفرضه الخادم. والقالب يوفّر ترميزه وتنسيقه.

## الإعدادات المسبقة

الإعداد المسبق تكوين جاهز يُعرض عند الإدراج: خصائص فوق القيم الافتراضية
للحقول، إضافةً إلى عناصر فرعية للفتحات.

```ts
presets: [
  {
    key: "with-grid",
    label: "Hero with products",
    props: { layout: "columns" },
    slots: { aside: [{ type: "product-grid", props: { limit: 2 } }] },
  },
]
```

تُتحقق الإعدادات المسبقة عند التجميع ببنائها. وتنشئ
`instantiatePreset(theme, type, key, newId)` النسخ، ولكل منها معرّف من `newId`.

## الحدود

| الحد | القيمة |
| --- | --- |
| النسخ لكل فتحة | 50 (`THEME_LIMITS.slotInstances`) |
| الأقسام لكل سطح أو منطقة | 50 (`THEME_LIMITS.sections`) |
| النسخ لكل مستند | 1000 (`THEME_LIMITS.documentInstances`) |
| التداخل تحت القسم | 6 (`THEME_LIMITS.depth`) |

يمكن لـ `max` في فتحة أو سطح أن يحدد عددًا أقل. ويعرض القارئ حتى الحد ويبلّغ
بالرمز `limit-exceeded`؛ وترفض العمليات تجاوزه. ويرفض التجميع كتلة ثابتة أو
مطلوبة تحتوي نفسها أو تتداخل أعمق من الحد.

## النسخ المخفية

```json
{ "id": "faq-1", "type": "faq", "hidden": true }
```

يتجاوز محرّك العرض النسخة و`load` وأبناءها. ومع ذلك يتحقق منها القارئ، فلا
يمكن لقسم مخفي أن يخفي خطأ في العقد. وتُعاد الكتلة المطلوبة أو الثابتة المخفية
إلى الظهور عبر `completePage`؛ فهذه ضمانات لا تفضيلات.
