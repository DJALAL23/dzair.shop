# الإنتاج والترقية

قالب يظهر ليس قالبًا جاهزًا للنشر. هذه الصفحة قائمة يجب أن يصمد لها القالب قبل
أن يعتمد متجر تاجر عليه: الوصولية، الاتجاه من اليمين إلى اليسار، التجاوب،
الحالات التي لا يصمّمها أحد، الأداء، الأمان، النشر، ومسار الترقية بين إصدارات
الـ SDK.

لا شيء هنا يغيّر العقد؛ بل يوضح كيف يُستخدم الاستخدام الصحيح.

## قبل النشر

| المجال | ما يجب إثباته |
| --- | --- |
| العقد | `validateThemeDefinition(theme)` فارغة؛ البيان يمرّ ذهابًا وإيابًا؛ كل مستند مشحون صالح في كل لغة |
| العرض | كل سطح يُعرض بلا `onIssue` غير متوقع |
| اللغات | العربية تُعرض RTL، والفرنسية والإنجليزية LTR، ولا لغة تعرض نصّ لغة أخرى |
| الحالات | البيانات الفارغة والمفقودة وغير الصالحة والفاشلة: كل حالة تعرض شيئًا معقولًا |
| الصور | لكل صورة `alt` (أو هي زخرفية بقصد) و`width`/`height` أو نسبة أبعاد |
| المال | المجاميع تأتي من الخادم؛ المتصفح لا يضيف رسمًا |
| الأسرار | لا مفتاح متجر يصل إلى حزمة المتصفح |
| البناء | `npx astro check` و`npm test` و`npm run build` تنجح |

## الوصولية

الـ SDK يوفّر القطع؛ والبنية مسؤوليتك.

- **النص البديل حقل، ولكل لغة.** قيمة حقل `image` هي `MediaReference` ويُحلّ
  `alt` فيها إلى اللغة المعروضة؛ مرّر `image.alt ?? ""` ودع الصورة الزخرفية
  تحمل alt فارغًا بدل اسم ملف.
- **النص الغني يُعرض HTML مُهرَّبًا.** `richTextToHtml` يهرّب كل عقدة نص وكل
  سمة ويُسقط الروابط غير الآمنة، فـ `set:html` آمن — لكن مستويات العناوين التي
  يمكنه إنتاجها من `h2` إلى `h4`. وعلى الصفحة أن تحتوي `h1` واحدًا فقط، غالبًا
  حقل عنوان القسم.
- **التباين قابل للفحص.** `contrastRatio(a, b)` يعطي نسبة WCAG؛ و4.5 هي الحد
  الأدنى للنص العادي، و3 للنص الكبير. نبّه التاجر في المحرّر بدل قبول نظام
  غير مقروء.
- **التركيز ولوحة المفاتيح.** كل عنصر تفاعلي هو `<a>` أو `<button>` أو حقل نموذج
  حقيقي. الـ SDK لا يضيف معالجات نقر؛ و`<div>` قابل للنقر خطأ في قالبك، ولا
  يعمل لمستخدم لوحة المفاتيح.
- **النماذج.** حقول نموذج الطلب والتحقق منها تأتي من إعدادات المتجر؛ اربط كل حقل
  بنص التسمية الذي يقدّمه التاجر، لا بنص مؤقت وحده.
- **الحركة.** الشريط المتحرك أو العرض الدوّار أو العدّ التنازلي يجب أن يحترم
  `prefers-reduced-motion`. الـ SDK لا يملك أي أدوات حركة ولا يضيفها.

## من اليمين إلى اليسار

العربية لغة أولى هنا، لا تعديلًا لاحقًا في ورقة أنماط.

- ضع `dir={isRTL ? "rtl" : "ltr"}` و`lang={locale}` على `<html>`، من سياق
  العرض. و`StoreConfig.locales[].direction` هو جواب المتجر لكل لغة.
- فئات الأنماط في الـ SDK مكتوبة على **خصائص CSS المنطقية** (`padding-inline`،
  `margin-block-start`)، فحقل `style` ينعكس بلا CSS إضافي. اكتب CSS بالطريقة
  نفسها: `margin-inline-start` لا `margin-left`.
- اعكس ما يحمل اتجاهًا فقط: الأسهم، أسهم «التالي»، شريط التقدّم. لا تعكس شعارًا
  ولا رقم هاتف ولا ساعة ولا صورة منتج.
- الأسعار وأرقام الهواتف وأرقام التتبّع تبقى LTR داخل نص RTL. ورقم الهاتف يمرّ
  عبر `normalizeAlgerianPhone` إلى الخادم، والخادم ينسّقه للعرض.
- اختبر بأطول نص عربي، لا الأقصر: النص العربي غالبًا أطول من أصله الإنجليزي،
  والزرّ بعرض ثابت يقصّه.

## التجاوب

- **نقاط التوقف هي نقاط الـ SDK**: `base` في كل عرض، و`md` من 768 بكسل، و`lg`
  من 1024 بكسل. وقيمة `style` تُكتب للهاتف أولًا — النقطة الأوسع ترث الأضيق،
  فلا تكرّر قيمة `base` داخل `md`.
- **الخطوات بكسلات اختارها القالب.** `s4` تساوي 16 بكسل لأن القالب هكذا قرّر؛
  والمكوّن الذي يكتب `16px` مباشرة ينكسر لحظة اختيار التاجر `s8`.
- **الصور**: استخدم `productImageSource` من SDK الواجهة، أو أدوات نطاق الوسائط مع
  `generateSrcSet`، كي لا ينزّل الهاتف صورة واجهة بمقاس سطح المكتب.
  و`mediaImageService` يفعل الأمر نفسه لـ `<Image>` في Astro عبر نطاق الوسائط.
- **المحتوى يحدّد الارتفاع.** القسم الذي يفترض سطرَي عنوان ينكسر بالعربية أو مع
  اسم منتج طويل. دع النص يلتف؛ استخدم `min-height` لا `height`.

## كل حالة يعرضها القسم

| الحالة | ما يجب أن يراه المتسوّق |
| --- | --- |
| البيانات فارغة (`[]`, `null`, `{}`) | حالة فارغة، لا تصميم مكسور: لا شبكة فارغة ولا «undefined» |
| فشل قراءة | الحالة الفارغة نفسها؛ والمشغّل يرى السبب عبر `onError` في العميل |
| رمى `load` استثناءً | خصائص الأساس تُعرض مع ذلك؛ ويبلّغ المُصيّر `load-failed` |
| النوع غير معروف | لا شيء يُعرض لتلك النسخة؛ وبقية الصفحة تنجو (`unknown-type`) |
| خاصية غير صالحة | تُطبَّق قيمة الحقل الافتراضية ويُبلَّغ `invalid-prop` — لا انهيار أبدًا |
| حقل مطلوب بلا قيمة | `missing-required-prop`؛ وعلى المكوّن ألّا يطبع عنوانًا فارغًا |
| لم يُضبط شيء بعد | في المعاينة فقط: عنصر بديل عبر `isPreview(blocks)`، ليتمكّن التاجر من اختيار القسم |
| المستند يخص قالبًا آخر | يُعرض المستند الافتراضي المشحون؛ ولا يرى التاجر صفحة فارغة |
| مسودة المحرّر فارغة | الصفحة الفارغة جواب حقيقي — التاجر أفرغها |

<Callout type="caution" title="التراجع صامت للمتسوّق بحكم التصميم">
لا يجوز أن تُطلق واجهة المتجر استثناءً لأن الكتالوج متوقف. وإذا أعادت صفحة خطأ
500 عند قراءة فاشلة، فتك القراءة كانت بلا قيمة بديلة — و`products.list()` يعيد
`[]` أصلًا.
</Callout>

## الأداء

- **ذاكرة قراءة واحدة لكل صفحة.** `createReadCache()` يشارك القراءة بين الأقسام
  (ويشارك رفضها). وذاكرة لكل قسم تضاعف الطلب نفسه بعدد الأقسام؛ وذاكرة على
  مستوى العملية تتسرّب بين الزوّار.
- **عميل واحد لكل طلب.** عميل الواجهة يحفظ ذاكرات صغيرة اختيارية (config،
  التصنيفات، البلديات) لكل نسخة؛ ومشاركة عميل بين الطلبات تشارك تلك الأجوبة بين
  المتسوّقين، بما فيها اللغة.
- **أبقِ Zod خارج المتصفح.** لا شيء في صفحة متسوّق يجب أن يستورد مُحقّقات SDK
  القالب أو وحدة مخطط. التحقق مكانه حيث تدخل البيانات: في مسار أو في البناء.
- **ابنِ مسبقًا ما لا يعتمد على الطلب.** البيان ونقطة نهاية الأنماط ملفات بناء
  (`prerender = true`).
- **الصور هي الوزن الأكبر.** غيّر المقاس على نطاق الوسائط، وأرسل `srcset`، وأعطِ
  كل صورة أبعادًا أصلية حتى لا يتزحزح التصميم.
- **الصفحة المركّبة ميزانية.** خمسون قسمًا تُعرض؛ وهذا لا يعني أنها يجب أن
  تُعرض. كل قسم هو قراءة وشجرة مكوّنات على الأقل.

## الأمان

- مفتاح API يعيش في وحدة خادم وفي متغيّر بيئة خادم. ومفتاح `PUBLIC_*` مفتاح منشور.
- حقول `url` تقبل مسارات الموقع والفواصل والاستعلامات و`http(s)://` و`mailto:`
  و`tel:` فقط؛ و`javascript:` و`data:` والعناوين النسبية للبروتوكول تُرفض عند
  التجميع ويُبلَّغ عنها عند القراءة. اعرضها في `href` لا في HTML خام.
- النص الغني صيغة مغلقة: لا توجد عقدة HTML لتُخزَّن، و`richTextToHtml` يهرّب ما
  يُخرجه. لا تستخدم `set:html` على حقل `text` أو `textarea` خام.
- قيمة الصورة **مفتاح** وسائط؛ والعنوان يُشتق عند العرض. فمستند محفوظ لا يستطيع
  توجيه `<img>` إلى مضيف آخر.
- القالب **يقرأ**؛ والمنصّة تكتب. لا توجد نقطة نهاية في قالب تحفظ مستندًا أو
  إعدادًا أو نصّ تاجر — هذا عمل CodFlow Studio، والقالب الذي يضيفها يكون قد اخترع
  حدًّا تصريحيًا لا يستطيع فرضه.
- رموز المعاينة يوقّعها المحرّر ويُتحقَّق منها بمفتاح المعاينة في النشر؛ وبلا
  مفتاح يعيد القالب 404 على مسار المعاينة. ولا تخزّن استجابة معاينة أبدًا.
- النمط المضمّن محدود بورقة أنظمة الألوان التي يكتبها `ThemeStyles.astro`؛ وفي
  صفحة بسياسة أمان محتوى يضيف بصمة تلك الورقة، فلا تحتاج `style-src` إلى
  `'unsafe-inline'`.

## النشر

1. **اختر مُهايئًا.** أي مُهايئ خادم لـ Astro يصلح. وTheme-00 يشحن مُهايئي
   Cloudflare وVercel؛ وكود التركيب واحد.
2. **اضبط الأسرار.** `COD_SERVER_URL` و`STORE_API_KEY` في خزنة أسرار المستضيف.
   ويجب أن يكون `COD_SERVER_URL` أصلًا عامًّا يصل إليه النشر — وقيمة loopback
   تعمل محليًا تُنتج متجرًا فارغًا في الإنتاج.
3. **بناء واحد لكل المتاجر.** بناء القالب ليس لكل متجر: المتجر يُحدَّد لكل طلب
   بالمفتاح والإعدادات. وإذا ربطت نطاق وسائط، اقرأه عبر دالة (`() => MEDIA_DOMAIN`)
   حتى لا يخبز البناء نطاق متجر واحد في الملف الناتج.
4. **اعرف أي الصفحات ثابتة.** `wocart-theme.json` و`wocart-styles.css` وأي صفحة
   مكتوبة يدويًا مبنية مسبقًا؛ وصفحة السطح تُعرض لكل طلب. والصفحة المبنية مسبقًا
   لا تستطيع قراءة `Astro.locals` — البناء بلا متجر.
5. **خزّن بوعي.** إذا خزّنت صفحة معروضة، ضع عليها وسمًا وأسقط الوسم على
   `REVALIDATE_PATH` بعد النشر؛ واستجابة المعاينة لا تُخزَّن أبدًا.
6. **تحقّق بعد النشر**: `/wocart-theme.json` يُقرأ وصالح، والورقة تُقدَّم بـ
   `text/css`، وصفحة منتج تُعرض في كل لغة منشورة.

## الإصدارات والترقية

تتبع الحزمتان الترقيم الدلالي: التصحيح يصلح السلوك، والنسخة الثانوية تضيف ميزات
متوافقة مع الإصدارات السابقة، والنسخة الرئيسية قد تحذف تصديرًا أو تغيّره. ويُعلَّم
أي تصدير بـ `@deprecated` لنسخة ثانوية واحدة على الأقل قبل أن تحذفه نسخة رئيسية.

| الحقيقة | القيمة وقت الكتابة | لماذا تهمّ |
| --- | --- | --- |
| `@wocart/theme` | `2.1.0` | `THEME_SDK_VERSION` في كل بيان |
| peers لـ `@wocart/theme` | `@wocart/storefront ^1.14.0`، و`astro ^7.0.0` (اختياري) | npm يرفض تثبيتًا خارج النطاق |
| `@wocart/storefront` | `1.19.0` | نقطة دخوله الجذرية آمنة في المتصفح؛ و`/server` ليست كذلك |
| peer لـ `@wocart/storefront` | `zod ^4.4.3` | مخططاته جزء من واجهته العامة |
| عقد البيان | `THEME_MANIFEST_CONTRACT_VERSION` = `1` | المحرّر يقرأ بيانات هذه النسخة |
| بروتوكول المعاينة | `PREVIEW_PROTOCOL_VERSION` = `1` | يجب أن يتفق المحرّر والجسر |

ثبّت نسخًا **محددة** في القالب (`npm install --save-exact`). فالقالب يُعرض بنشره
الخاص، والنطاق المرن يعني فقط أن بناءين من الالتزام نفسه قد يختلفان.

قائمة الترقية:

1. اقرأ `CHANGELOG.md` للحزمة في كل نسخة تعبرها، لا الأخيرة فقط.
2. غيّر التثبيت، ثم شغّل `npx astro check` و`npm test` و`npm run build`.
3. شغّل فحص الإصدار — `diffThemeManifests(previous, next)` ببيانَي النسختين —
   واقرأ كل بند يصنّفه كاسرًا.
4. أعد تشغيل `validateThemeDefinition`: قد تتحقق نسخة أحدث من أمور أكثر من
   السابقة (2.0 أضافت ضمان نموذج الطلب وحجز `blocks`).
5. أعد المعاينة وعرض متسوّق، بالعربية كما باللغة الأساسية.

ما غيّرته 2.0 إذا كنت قادمًا من 1.x:

- سطح `product` يجب أن يضمن نموذج طلب، وإلا يفشل التجميع.
- `blocks` اسم خاصية محجوز؛ ولا حقل يستخدمه.
- القارئ يُسقط ما يتجاوز `THEME_LIMITS` ويبلّغ `limit-exceeded`.
- محرّر على 1.x يرفض بيانًا يستخدم `style` أو `colorScheme` أو `colorSchemes` أو
  `productList` أو `collectionList`. رقِّ القالب والمحرّر معًا.

## أخطاء شائعة

| الخطأ | كلفته |
| --- | --- |
| تغيير `defineTheme({ key })` | كل تعديلات نصوص التاجر ومستندات صفحاته لهذا القالب تُيتَّم |
| تغيير `type` مكوّن | النسخ المحفوظة منه تتوقف عن الحل (`unknown-type`) |
| تضييق `slots[].allow` | الأبناء الذين لم يعودوا يناسبون تُسقطهم الصفحات المحفوظة (`disallowed-child`) |
| تغيير `id` في مستند مشحون | تعديل التاجر يبقى مرتبطًا بالمعرّف القديم |
| مفتاح حقل يتعارض مع مفتاح `load` | القيمة المحمّلة تفوز والحقل لا يفعل شيئًا بصمت |
| خطأ إملائي في `contentKey` | الحقل يعود إلى قيمته الافتراضية؛ ولا شيء يفشل قبل `validateThemeDefinition` مع `contentKeys` |
| كتابة لون أو خطوة تباعد أو خط بشكل ثابت | اختيار التاجر لـ `style` / `colorScheme` بلا أثر |
| تخزين عنوان URL في حقل `image` | الصورة لا تُحلّ أبدًا؛ الحقل ينتظر مفتاح وسائط |
| قراءة `Astro.locals.store` في صفحة مبنية مسبقًا | خطأ بناء، أو صفحة فارغة |
| ذاكرة قراءة لكل قسم | المنتج نفسه يُجلب مرة لكل قسم |
| مسار في القالب يحفظ مستندًا | القالب لا يملك سلطة الكتابة؛ CodFlow Studio يملكها |
| التعامل مع خيارات Theme-00 كعقد | كتالوجاته لكل سطح، وتخطيط محتواه، ونظام تصميمه قرارات ذلك القالب — راجع [تحليل المرجع](/sdk/theme/reference-implementation) |
