# التنفيذ المرجعي: Theme-00

`cod-astro/theme-00` هو واجهة متجر CodFlow الكاملة (Astro 7، وCloudflare وVercel،
وبالعربية والفرنسية والإنجليزية). وهو المثال العملي الذي بُني عليه الـ SDKان،
وأفضل مكان لرؤية وصلات قالب حقيقي.

إنه تنفيذ صحيح **واحد**، لا **المواصفة**. وهذه الصفحة ترسمه: ما يأخذه من الـ
SDKين، وما قرّره بنفسه، وما يجب أن ينسخه قالب جديد أو يتركه.

<Callout type="caution" title="الكود هو المرجع، لا هذا الملخص">
Theme-00 يتطور. وعندما تختلف هذه الصفحة والقالب، اقرأ
`cod-astro/theme-00/AGENTS.md` والملف نفسه. لا شيء هنا يتقدّم على إعلانات
الحزمتين.
</Callout>

## أين يقف

- **ليس workspace.** يثبّت `@wocart/storefront` و`@wocart/theme` من سجل npm
  بنسخ محددة ويحتفظ بملف قفل خاص به، تمامًا كقالب خارجي. وهذا مقصود: يثبت أن
  الحزمتين المنشورتين تعملان.
- **مثبّت على الـ SDKين قيد المراجعة**: `@wocart/storefront` 1.19.0،
  و`@wocart/theme` 2.1.0، وAstro 7.3، وTypeScript 6.
- **مُهايئان وكود تركيب واحد**: بناء Cloudflare وبناء Vercel لا يختلفان إلا في
  المُهايئ وبعض وصلات المنصّة.
- **أوامره الخاصة**: `npm run dev` و`npm test` و`npx astro check` و
  `npm run validate:all` و`npm run build`. ولا يوجد سكربت `typecheck` —
  فـ `astro check` هو فحص الأنواع.

## ما يستخدمه من الـ SDKين

| قدرة الـ SDK | Theme-00 |
| --- | --- |
| `createStoreClient` | `src/theme/sdk.ts` — المكان الوحيد الذي يُبنى فيه العميل |
| إعداد المتجر و`contentOverrides` | الوصلة نفسها تمرّر `theme: THEME_KEY`؛ والوسيط يبني سياق الطلب |
| التركيب | `src/theme/pages/*.astro` تعرض سطحًا عبر `resolveSurfaceDocument` و`InstanceView` |
| التعريفات والبيان | `src/theme/theme.ts` يجمّع الكتالوج؛ و`src/pages/wocart-theme.json.ts` يقدّمه |
| المناطق | `src/theme/pages/header.area.json` و`footer.area.json` |
| القوالب والوسائط | أسطح المنتج والتصنيف والمجموعة والصفحة تقرأ `Astro.params` |
| حقول الأنماط والأنظمة | `src/theme/appearance.ts` (المقاسات) و`src/pages/wocart-styles.css.ts` |
| الإعدادات | `src/theme/settings.ts` و`src/theme/runtime/settings.ts` |
| المعاينة | `src/pages/wocart-preview.astro` و`@wocart/theme/preview` |
| إعادة التحقق | `src/pages/wocart-revalidate.ts` و`readRevalidateRequest` |
| مسارات API من نفس الأصل | `src/theme/api-routes.ts` مبني على `createStorefrontRoutes`، ويُصدَّر بسطر واحد لكل `src/pages/api/*` |
| إجراء الطلب | `src/actions/` يغلّف `placeOrderInput` و`executePlaceOrder` |
| الصور | `src/theme/utils/images.ts` يربط `createImageHelpers(MEDIA_DOMAIN)`؛ و`src/theme/utils/image-service.ts` يربط `mediaImageService` |
| النصوص والجمع | حزم `src/theme/content/` و`formatMessage` عبر `src/theme/content/messages.ts` |

كل واحد من هذه هو الـ SDK مستخدمًا كما هو موثّق — وهذا ما يجعل القالب مقروءًا
كمثال.

لغة**.

## ما هو عقد ويجب نسخه

| القاعدة | لماذا ليست اختيارية |
| --- | --- |
| وحدة واحدة تبني عميل المتجر، وتمرّر `theme: THEME_KEY` | وإلا لا تصل تعديلات النصوص ولا مستندات الصفحات أبدًا |
| المستند المحفوظ يفوز؛ وإن كان غائبًا أو غير صالح أو لقالب آخر أو بلا تقاطع، يُعرض المستند المشحون | تغيير القالب أو حفظ خاطئ يجب ألّا يُفرغ المتجر |
| `createReadCache()` واحد لكل عرض صفحة | القراءة نفسها من الكتالوج تتشاركها كل الأقسام |
| سياق العرض يحمل `locale` **و**`fallbackLocales` | القيمة المترجمة الغائبة للغة تعود قيمة بقيمة |
| البيان ملف بناء على `/wocart-theme.json` | البيان غير الصالح يُفشل البناء بدل أن يُنشر |
| المعاينة لا تُخزَّن أبدًا، وكل صفحة مخزّنة تحمل وسم `pages` | النشر يجب أن يصل للمتسوّقين، والمسودة يجب ألّا تتسرّب |
| القالب لا يكتب مستندًا ولا إعدادًا ولا نصّ تاجر أبدًا | الكتابة للمنصّة، بتصريحها |
| نصوص المتسوّق تعيش في حزم لكل لغة | لا نصّ ثابت في الكود، ولا لغة تُكتشف وقت التشغيل |
| كل رابط داخلي مُعرَّب ومُوطَّن | المتسوّق الفرنسي يبقى بالفرنسية |

لكل قاعدة من هذه اختبار في Theme-00 — راجع قائمة الحُرّاس أدناه.

## ما هو قرار Theme-00 لا قرار الـ SDK

هذه خيارات جيدة، وقالب جديد حرّ في اختيار غيرها:

- **كتالوجات لكل سطح.** `catalog/families/home.ts` يعلن كتالوجًا يحوي فقط أقسام
  الرئيسية، ومسار الرئيسية يعرض به؛ و`theme.ts` يجمّع الكتالوج الكامل للبيان
  والمحرّر. وكلاهما `ThemeDefinition` بالمفتاح نفسه. الفائدة سطح عرض أصغر؛
  والكلفة أن مستندًا محفوظًا يشير إلى قسم من عائلة أخرى يعود إلى الافتراضي
  (`no-overlap`). ونمط الـ SDK الأبسط هو كتالوج واحد للكل.
- **المكوّنات تقرأ حزمة المحتوى كاملة.** بعضها يأخذ `content: StoreFrontContent`
  ويُطبّق `copyOverrides(content, props)` بدل خاصية لكل `contentKey`. الـ SDK
  يقبل الحالين؛ والخصائص لكل حقل هي الطريق الأقصر.
- **مفاتيح قراءة كثوابت** (`catalog.products`، `catalog.categories`،
  `collectionRead(handle, limit)`). الـ SDK يطلب فقط مفتاحًا ثابتًا داخل العرض
  نفسه.
- **نظام تصميم** (`styles/`، `appearance.ts`، خطوط، مجموعة أيقونات). لا يعرف
  الـ SDK أن للقالب رموزًا؛ وخطوات الأنماط يجب أن تقابل *شيئًا*، والبكسلات
  قرار القالب.
- **جزر الخادم واختيارات `copy`** (`bridges/island-props.ts`). تحسين على مستوى
  Astro بقيد على مستوى Astro (خصائص الجزيرة تسافر في رابط)، لا ميزة في الـ SDK.
- **ملفات مسار رفيعة تعيد تصدير `src/theme/api-routes.ts`.** المسارات نفسها هي
  مسارات الـ SDK (`createStorefrontRoutes`)؛ والملف ذو السطر الواحد تفصيل توجيه
  ملفات.
- **حُرّاسه ومُحقّقاته** (`__tests__/guards/` و`scripts/validate-*.js`). قوية
  وخاصة بعاداته — انسخ الفكرة لا القواعد.

## حُرّاس يستحقّون النسخ

Theme-00 يحوّل حدوده إلى اختبارات تفشل. وعلى قالب جديد أن يملك مكافئًا لما يلي
على الأقل:

| الحارس | ما يثبّته |
| --- | --- |
| `sdk-boundary.test.ts` | وصلة SDK واحدة؛ لا استيراد عميق؛ ولا استيراد `cod-shared` |
| `store-context.test.ts` | مكان واحد يبني سياق الطلب؛ وكل رابط داخلي يمرّ عبر `href` الخاص بالمتجر |
| `no-validator-in-browser.test.ts` | لا Zod في أي سكربت متصفح |
| `page-paths.test.ts`, `page-contracts.test.ts` | كل نوع صفحة على مسار المنصّة، مع سكربته المطلوب |
| `localized-links.test.ts` | لا رابط داخلي غير مُوطَّن |
| `manifest-artifact.test.ts` | نقطة نهاية البيان مبنية مسبقًا وتحمل كل الأسطح |
| `preview-route.test.ts`, `revalidate-route.test.ts`, `cache-contracts.test.ts` | ترويسات المعاينة، ووسم `pages`، وخطاف النشر |
| `home-editor-sections.test.ts`, `editor-coverage-contracts.test.ts` | كل كلمة معروضة قابلة للتعديل؛ ولا نصّ مجمّد |
| `home-languages-contracts.test.ts`, `packs.test.ts` | تساوي اللغات الثلاث، والنص المحفوظ يتبع لغة المتجر |
| `sdk-boundary-contracts.test.ts` | الـ SDKان يُستوردان فقط عبر نقطتَي دخولهما |

## كيف تقرأ قسمًا في Theme-00

1. **اعثر على التعريف** — `src/theme/catalog/<family>/<type>.def.ts`. سلسلة
   `type` هي هوية القسم؛ والحقول سطحه القابل للتعديل.
2. **اعثر على المكوّن** — استيراد `component:` في ذلك التعريف.
3. **اعثر على مدخل المستند** — `src/theme/pages/<surface>.page.json`، بـ `type`
   و`id`.
4. **اعثر على اختباره** — الملف المقابل تحت `__tests__/contracts/`.
5. **تحقّق مما هو سلوك الـ SDK** في هذا التوثيق قبل افتراض أن النمط يعمّم.

## ما لا يثبته Theme-00

- ليس حزمة بداية. لا يوجد مولّد ولا CLI؛ وبناؤه عُرف لا API.
- نصوصه وتصميمه وخطوطه وقائمة أقسامه قرارات منتج لواجهة متجر واحدة.
- ليس مجموعة اختبارات الـ SDK. اختبارات الحزمتين في
  `wocart-sdk/{storefront,theme}/src` هي التي تعرّف العقد؛ وTheme-00 يستهلكه.
- ملف `AGENTS.md` فيه يسجّل قرارات وحلولًا مؤقتة بتواريخها. بعضها تاريخي؛
  والكود و`CHANGELOG.md` للحزمتين يحسمان ما هو حالي.
