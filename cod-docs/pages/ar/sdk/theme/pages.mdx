# الصفحات والعرض

**السطح** مكان يمكن فيه استخدام مستند. فـ `home` يملأ الصفحة الرئيسية،
و`product` يملأ كل صفحة منتج، و`area:header` يملأ الترويسة في كل صفحة. لا
تحتاج إلى كلها دفعة واحدة؛ فمعظم القوالب تبدأ بـ `home` و`product`.

لكل سطح **مستند**: قائمة JSON بالأقسام التي يعرضها ذلك السطح والقيم التي
تحتفظ بها تلك الأقسام. ويشحن القالب مستندًا افتراضيًا؛ ويمكن للمتجر حفظ
مستنده الخاص. ويختار SDK أي مستند يُعرض ويصلح الأجزاء التي لم تعد تطابق
القالب.

## الأسطح

```ts
const productSurface: SurfaceSpec = {
  key: "product",
  label: "Product",
  pageType: "product",
  document: productDocument,
  required: [{ type: "product-main", min: 1, max: 1 }],
};
```

| الحقل | المعنى |
| --- | --- |
| `key` | مفتاح السطح المخزّن في المستند |
| `label` | اسم يظهر للمحرر |
| `pageType` | نوع صفحة المنصة الذي يعرضه السطح |
| `document` | القيمة الافتراضية التي يشحنها القالب |
| `required` | أقسام المستوى الأعلى التي يجب أن توجد |
| `max` | حد أقصى لعدد أقسام المستوى الأعلى (حتى 50) |

أنواع الصفحات هي `home` و`catalog` و`category` و`collection` و`product` و`page`
و`landing` و`checkout` و`thankYou`.

### قوالب الصفحات

نوع الصفحة الذي يملك موردًا — `product` و`category` و`collection` و`page`
و`landing` — يجعل السطح قالب صفحة. فمستند واحد يعرض كل منتج أو فئة أو صفحة من
ذلك النوع. ويقرأ المسار المورد أولًا ويمرّر معاملات المسار:

```ts
const context: ThemeRenderContext = {
  // …
  params: { handle: "robe-kabyle" },
};
```

تقرأ الأقسام المورد عبر `context.params` ومفتاح قراءة يتضمنه، فتتشارك الصفحة
وأقسامها قراءة واحدة.

### البدائل

يمكن أن يكون سطح بديلًا لآخر: فـ `product.compact` تصميم منتج ثانٍ. ويجب إعلان
قاعدته (`product`) وأن تعرض نوع الصفحة نفسه.
و`capabilities.surfaces: ["product"]` تغطي البديل أيضًا.

## المناطق

المنطقة جزء تشترك فيه كل الصفحات — الترويسة والتذييل. وتُركَّب من أقسام مثل
الصفحة وتُحرَّر مرة واحدة للمتجر كله.

```ts
areas: [
  {
    key: "header",
    label: "Header",
    document: headerDocument,
    required: [{ type: "header", max: 1 }],
    max: 4,
  },
  { key: "footer", label: "Footer" },
],
```

مستند المنطقة هو السطح `area:<key>`؛ وتبني `areaSurface("header")` تلك
السلسلة. ويبقى المكوّن في الترويسة بإعلان
`capabilities: { surfaces: ["area:header"] }`.

## المستند

مستند الصفحة JSON:

```json
{
  "version": 1,
  "surface": "home",
  "sections": [
    { "id": "hero-1", "type": "hero", "props": { "title": "Bienvenue" } },
    { "id": "faq-1", "type": "faq", "hidden": true }
  ]
}
```

`version` هي `1`. و`surface` هو مفتاح السطح أو المنطقة. و`sections` هو المستوى
الأعلى. وللنسخة `id` و`type`، واختياريًا `props` و`children` و`slots` و`fixed`
و`hidden`.

ويمكن للمستند أن يذكر أيضًا مصدره:

```json
{ "theme": { "key": "my-theme", "version": "1.0.0" } }
```

المستند الذي يسمّي قالبًا آخر يُبلَّغ عنه (`theme-mismatch`) وتُعرض القيمة
الافتراضية المشحونة بدلًا منه.

المفاتيح **العليا** المجهولة تُمرَّر كما هي. أما المفاتيح المجهولة داخل نسخة
فتُزال. والغلاف متوافق مع الإصدارات المستقبلية؛ أما النسخة فليست كذلك.

## ما يُعرض

تطبّق `resolveSurfaceDocument(theme, surface, saved, scope)` السياسة:

| الحالة المحفوظة | ما يُعرض |
| --- | --- |
| لا مستند محفوظ | القيمة الافتراضية التي يشحنها القالب |
| غلاف غير صالح (`page: null`) | القيمة الافتراضية المشحونة |
| السطح أو القالب لا يطابق | القيمة الافتراضية المشحونة |
| لا قسم محفوظ يطابق نوعًا في الفهرس | القيمة الافتراضية المشحونة |
| تداخل جزئي | ما يطابق؛ والأنواع المجهولة لا تعرض شيئًا |
| مستند محفوظ فارغ | فارغ — التاجر أفرغه |

وتعيد المستند ومصدره وسبب التراجع:

```ts
const { page, source, reason, issues } = resolveSurfaceDocument(
  theme,
  "home",
  await store.client.pageData.get("home"),
  { content: store.content, locales: [store.locale, ...store.fallbackLocales] },
);
```

يُكمَّل الناتج بالكتل المطلوبة والثابتة (`completePage`)، فما تعرضه هو ما
يقتضيه العقد.

## عرض صفحة

مكوّن `InstanceView` واحد لكل قسم، وذاكرة قراءة واحدة لكل عرض صفحة:

```astro
---
import type { ThemeRenderContext } from "@wocart/theme";
import InstanceView from "@wocart/theme/astro/InstanceView.astro";
import { createReadCache } from "@wocart/theme/astro";
import { resolveSurfaceDocument } from "@wocart/theme";
import { theme } from "../theme/theme";

const store = Astro.locals.store;
const { page } = resolveSurfaceDocument(
  theme,
  "home",
  await store.client.pageData.get("home"),
  { content: store.content, locales: [store.locale, ...store.fallbackLocales] },
);
const context: ThemeRenderContext = {
  store: store.config,
  content: store.content,
  locale: store.locale,
  fallbackLocales: store.fallbackLocales,
  isRTL: store.isRTL,
  url: store.pathname,
};
const reads = createReadCache();
---
{page.sections.map((section) => (
  <InstanceView
    instance={section}
    theme={theme}
    context={context}
    storefront={store.client}
    reads={reads}
  />
))}
```

`InstanceView` هو محرّك العرض المرجعي. ولنسخة واحدة فهو:

1. يتجاوز النسخة المخفية،
2. يجد التعريف عبر `type`،
3. يحل القيم الافتراضية والترجمات والحقول والتركيب،
4. يشغّل خطاف `load` الاختياري،
5. يعرض مكوّن القالب مع `props` ومقبض `blocks`.

النوع المجهول لا يعرض شيئًا؛ ويبقى بقية الصفحة. و`load` الذي يرمي استثناءً
يُبلَّغ عنه بالرمز `load-failed` وتُعرض الخصائص الأساسية رغم ذلك.

## المشكلات

للصفحة قناتا تقرير:

- **مشكلات بيانات الصفحة** تأتي من التحليل والحل: `unknown-type` و`unknown-prop`
  و`invalid-prop` و`missing-required-prop` و`unknown-slot` و`disallowed-child`
  و`duplicate-id` و`limit-exceeded` و`theme-mismatch` وغيرها.
- **مشكلات محرّك العرض** تضيف `missing-component` و`load-failed`
  و`multiple-slots-unsupported`.

مرّر `onIssue` لجمعها في الاختبارات أو السجلات:

```astro
<InstanceView
  instance={section}
  theme={theme}
  context={context}
  storefront={store.client}
  reads={reads}
  onIssue={(issue) => issues.push(issue)}
/>
```

المراسل الافتراضي هو `console.warn` ببادئة ثابتة. والمشكلة تدهور مع تقرير، لا
خطأ يُرمى.

## فتحة مسماة واحدة لكل نسخة

يملأ محرّك العرض المرجعي **فتحة مسماة واحدة** على الأكثر لكل نسخة. فلا يستطيع
مترجم Astro رفع سوى أول خاصية فتحة ديناميكية إلى كائن الفتحات. والفتحة المسماة
الثانية التي تحمل محتوى تُبلَّغ بالرمز `multiple-slots-unsupported` ولا تُعرض.
ويمكن للمكوّن إعلان عدة فتحات؛ ويمكنه أيضًا نقل فتحات Astro نفسها داخله عندما
يحتاج إلى ملء أكثر من واحدة.
