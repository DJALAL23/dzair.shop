# اختبار قالب

القالب القابل للتحرير يقطع أربعة وعود: تعريفاته صالحة، وبيانه يمكن حفظه وقراءته
مجددًا، وصفحاته الافتراضية تجتاز التحقق، وتلك الصفحات تُعرض. وهذه الفحوص الأربعة
تثبت تلك الوعود في مجموعة اختباراتك. أضف فحوصًا لسلوكك الخاص بعد نجاحها.

## 1. تعريف القالب صالح

```ts
import { validateThemeDefinition } from "@wocart/theme";
import { theme } from "../theme/theme";

expect(validateThemeDefinition(theme)).toEqual([]);
```

مع حزم المحتوى المعلنة، يفحص التجميع أيضًا كل مستند افتراضي وكل إعداد مسبق.
والمصفوفة الفارغة هي النجاح الوحيد.

## 2. يُعاد تحميل البيان بنظافة

```ts
import { themeManifest, validateThemeManifest } from "@wocart/theme";

const manifest = themeManifest(theme);
const checked = validateThemeManifest(JSON.parse(JSON.stringify(manifest)));

expect(checked.manifest).not.toBeNull();
expect(checked.issues).toEqual([]);
```

يكشف هذا قيمة غير قابلة للتسلسل، أو عدم توافق مفتاح/نوع، وأي قاعدة علائقية
يختلف فيها التجميع والتحقق. وإصدار قالب غير semver هو المشكلة الاستشارية
الوحيدة؛ أصلحها بدلًا من قبولها.

## 3. الصفحات الافتراضية صالحة

```ts
import { validatePageData } from "@wocart/theme";

for (const surface of theme.surfaces ?? []) {
  if (surface.document === undefined) continue;
  expect(
    validatePageData(theme, surface.document, {
      content: theme.content?.["fr"],
      locales: ["fr"],
    }),
  ).toEqual([]);
}

for (const area of theme.areas ?? []) {
  expect(
    validatePageData(theme, area.document, {
      content: theme.content?.["fr"],
      locales: ["fr"],
    }),
  ).toEqual([]);
}
```

شغّلها لكل لغة معلنة، لا للغة الأساسية فقط. فالقيمة المترجمة التي تحلها لغة
واحدة فقط قد تخفي مفتاح محتوى مفقودًا.

## 4. الصفحات الافتراضية تُعرض

اعرض كل قسم عبر `InstanceView` مع حاوية Astro، وذاكرة قراءة واحدة لكل صفحة،
و`StoreClient` بديل:

```ts
import { experimental_AstroContainer as AstroContainer } from "astro/container";
import { createReadCache, type RendererIssue } from "@wocart/theme/astro";
import InstanceView from "@wocart/theme/astro/InstanceView.astro";
import type { ThemeRenderContext } from "@wocart/theme";
import type { StoreClient } from "@wocart/storefront/server";
import type { StoreConfig } from "@wocart/storefront";

const container = await AstroContainer.create();
const issues: RendererIssue[] = [];
const page = theme.surfaces?.find((surface) => surface.key === "home")?.document;
if (page === undefined) throw new Error("the home surface ships no document");

const products: unknown[] = [];
const storefront = {
  products: { list: async () => products },
} as unknown as StoreClient;

const context = {
  store: {} as StoreConfig,
  content: {},
  locale: "en",
  isRTL: false,
  url: "/",
} satisfies ThemeRenderContext;

const reads = createReadCache();

for (const section of page.sections) {
  await container.renderToString(InstanceView, {
    props: {
      instance: section,
      theme,
      context,
      storefront,
      reads,
      onIssue: (issue) => issues.push(issue),
    },
  });
}

expect(issues).toEqual([]);
```

ذاكرة واحدة لكل عرض صفحة هي المقصود: فالأقسام الشقيقة تتشارك موردًا، والصفحات
المنفصلة لا. تحقق من `issues` لا من غياب استثناء — فمحرّك العرض يتدهور ولا
يرمي.

لا يُستدعى `load` إلا عندما يُعرض قسمه. أعطِ العميل البديل الطرق التي يستخدمها
`load`، واجعله يفشل عمدًا في اختبار منفصل:

```ts
const failingIssues: RendererIssue[] = [];
const failing = {
  products: { list: async () => { throw new Error("offline"); } },
} as unknown as StoreClient;

await container.renderToString(InstanceView, {
  props: {
    instance: page.sections.find((section) => section.type === "best-sellers")!,
    theme,
    context,
    storefront: failing,
    reads,
    onIssue: (issue) => failingIssues.push(issue),
  },
});

expect(failingIssues).toContainEqual(
  expect.objectContaining({ code: "load-failed" }),
);
```

تُعرض خصائص القسم الأساسية رغم ذلك؛ ويغيب الجزء المحمّل فقط.

## اختبارات المستندات المحفوظة

تغطي الفحوص الأربعة مستندات القالب نفسه. أضف اختبارات للمستندات التي تصل من
متجر:

```ts
import { resolveSurfaceDocument } from "@wocart/theme";

const saved = {
  version: 1,
  surface: "home",
  sections: [
    { id: "gone-1", type: "removed-layout" },
    { id: "hero-1", type: "hero", props: { title: "Bonjour" } },
  ],
};

const result = resolveSurfaceDocument(theme, "home", saved, { locales: ["fr"] });

expect(result.page.sections).toHaveLength(1);
expect(result.issues).toContainEqual(
  expect.objectContaining({ code: "unknown-type", path: "sections[0].type" }),
);
```

| الحالة المطلوب تغطيتها | المتوقع |
| --- | --- |
| لا مستند محفوظ | القيمة الافتراضية المشحونة |
| غلاف غير صالح | القيمة الافتراضية المشحونة، مع `page: null` من `parsePageData` |
| مستند لقالب آخر | القيمة الافتراضية المشحونة، `theme-mismatch` |
| نوع قسم مجهول | يزول ذلك القسم، ويُعرض الباقي |
| `sections` فارغة | صفحة فارغة — التاجر أفرغها |
| كتلة مطلوبة مخفية | تُعاد بواسطة `completePage` |
| قائمة تتجاوز `max` | تُعرض حتى `max`، `limit-exceeded` |

## فحوص الإصدار

قبل إصدار، قارن البيانين:

```ts
import { diffThemeManifests } from "@wocart/theme";

const { breaking, additive } = diffThemeManifests(previous, next);
expect(breaking).toEqual([]);
```

إذا كان التغيير الكاسر مقصودًا، فارفع الإصدار الرئيسي للقالب وبيّن ما سيتدهور.
وشغّل أيضًا `pluralFormIssues(pack, locale)` على كل حزمة: فهي تبلّغ عن صيغة جمع
تحتاجها اللغة وتنقص الحزمة، أو صيغة لا تستخدمها اللغة أبدًا.

## ما يجب اختباره في المتصفح

الفحوص الأربعة لا تنفّذ سكربتات المتصفح. اختبر بشكل منفصل:

- قسمًا يربط سلوكًا على `PREVIEW_SECTION_LOAD_EVENT` يُركَّب مجددًا بعد رقعة أو
  استبدال،
- استبدال معاينة لصفحة كاملة يطلق `astro:page-load`،
- سكربتات السلة وإتمام الطلب تظل تعمل بعد تحديث معاينة،
- صفحة المتسوق لا تحوي أي تعليق `wocart:start` / `wocart:end`.

## إبقاء محرّك العرض خارج اختبارات المتصفح

`@wocart/theme` وZod تبعيتان للخادم/البناء. ويمكن لسكربت متصفح استيراد مساعدات
SDK الآمنة للمتصفح، لكن لا محرّك العرض ولا المدققات أبدًا. ويحرس ذلك
`browser-bundle.test.ts` في SDK و`no-validator-in-browser.test.ts` في القالب؛
فأبقِ هذين الاختبارين ناجحين.
