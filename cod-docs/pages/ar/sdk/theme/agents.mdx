# استخدام الذكاء الاصطناعي لبناء قالب

يستطيع الذكاء الاصطناعي كتابة قالب بسرعة، لكن للقالب قواعد يسهل تخمينها خطأً.
هذه الصفحة مكتوبة للطرفين في المحادثة:

- **إذا كنت المطوّر:** أعطِ هذه الصفحة لمساعدك مع بيان القالب والمستند الذي
  تريد تغييره. وتبقى أنت من يقرر شكل القالب.
- **إذا كنت المساعد:** اعمل من البيان وعمليات المستندات. ولا تخترع حقلًا أو نوع
  مكوّن أو id أبدًا.

الهدف ليس منع المساعد من كتابة الكود. الهدف هو إبقاؤه داخل العقد، كي تُعرض
الصفحة للمتسوقين بعد كل تغيير.

## أعطِ المساعد هذه الأشياء الثلاثة

| أعطِه | لماذا |
| --- | --- |
| بيان القالب | يسرد أنواع المكوّنات الحقيقية والحقول والفتحات والأسطح |
| المستند أو السطح الهدف | يبيّن أي صفحة تُغيَّر |
| النتيجة التي تريدها بكلمات بسيطة | تحل محل التخمين من لقطة شاشة |

إذا غيّر المساعد تعريفًا، فأعطِه أيضًا أمر التحقق أو أمر الاختبار الذي يستخدمه
القالب.

`.agents/skills/wocart-theme/`. وهي مكتوبة لوكيل لا لك، وهي أقصر طريق لجعل
المساعد يلتزم:

| الملف | ما يجده الوكيل فيه |
| --- | --- |

## اقرأ هذه أولًا

| إذا احتجت إلى… | اقرأ |
| --- | --- |
| معرفة الحقول الموجودة | `manifest.components[type].fields` |
| معرفة الفتحات والكتل الموجودة | `manifest.components[type].slots`، `fixed`، `placement` |
| معرفة الأسطح والمناطق الموجودة | `manifest.surfaces`، `manifest.areas` |
| معرفة إعدادات المتجر | `manifest.settings` |
| تغيير مستند | [البيان والتحرير](/ar/sdk/theme/manifest) |
| فهم رفض | `DocumentIssue.code` و`PageDataIssue.code` |

يُولَّد البيان من القالب الحي. لا تستنتج حقلًا من وسوم المكوّن أو لقطة شاشة أو
README قديم.

## الثوابت

هذه هي القواعد التي يجب أن يتبعها المساعد. لا يحتاج المطوّر إلى حفظها، لكنها
تشرح سبب رفض بعض التغييرات.

1. **التعريفات كود؛ والمستندات بيانات.** لا تضع دوال أو نسخ فئات أو قيم
   undefined في مستند أبدًا.
2. **`type` هو الهوية.** لا تُعِد تسميته. فالنسخ المحفوظة تشير إليه.
3. **مفتاح المكوّن يساوي `type` الخاص به.** يجب أن يحتوي
   `components["best-sellers"]` على تعريف يكون `type` الخاص به `"best-sellers"`.
4. **`id` فريد في المستند.** استخدم `newInstanceId()`، أو احتفظ بالمعرّف الذي
   أعطته أداة أخرى للنسخة؛ ولا تخترع واحدًا قد يتعارض.
5. **القيم الافتراضية تُجسَّد عند الإنشاء فقط.** يملأ `createInstance` القيم
   الافتراضية؛ ويعود قارئ لاحق أيضًا إلى المحتوى والقيم الافتراضية.
6. **مخرجات `load` تتغلب على props الحقول.** إذا استخدم حقل ونتيجة `load`
   المفتاح نفسه، تفوز القيمة المحمّلة.
7. **المخفي يعني غير معروض، لا محذوف.** يبقى في المستند، ولا يمكن إخفاء كتلة
   مطلوبة.
8. **الكتل المطلوبة والثابتة مضمونة.** يضيفها `completePage` عندما يفتقدها
   المستند.
9. **الصور مفاتيح وسائط، لا URLs.** قيمة `image` هي `MediaReference`؛ حلّها عند
   العرض.
10. **لا CSS في المستندات.** قيم `style` خطوات وخيارات؛ وقيم `colorScheme`
    معرّفات مجموعات ألوان.
11. **المستند المحفوظ غير موثوق.** تحقق عند القراءة وتدهور مع تقارير؛ ولا تطرح
    الصفحة أبدًا بسبب قسم سيئ واحد.
12. **كود القالب يقرأ؛ والمنصة تكتب.** لا تضف نقاط نهاية تحفظ مستندات صفحات أو
    إعدادات أو نصوص تاجر. فالقالب يتلقى البيانات المحفوظة.

## بروتوكول التغيير

1. **حدّد السطح.** `home` أو `product` أو `collection` أو `category` أو `catalog`
   أو `page`، أو منطقة مثل `area:header`.
2. **افتح المستند.** يعطيك `resolveSurfaceDocument(theme, surface, saved)`
   المستند الذي سيُعرض، مكتملًا بالفعل. وإذا كنت تحرّر، فابدأ من
   `completePage(theme, page).page`.
3. **اختر المكوّن.** استخدم نوعًا من البيان يسمح `placement` و
   `capabilities.surfaces` الخاصان به باستخدامه في هذا الموضع.
4. **أنشئ النسخة.**
   ```ts
   import { createInstance, manifestCatalog, newInstanceId } from "@wocart/theme";
   const definition = manifestCatalog(manifest).components["best-sellers"];
   const instance = createInstance(definition!, newInstanceId(), { limit: 4 });
   ```
   `limit` حقل في تعريف `best-sellers` في هذا المثال. وفي قالب حقيقي، مرّر فقط
   المفاتيح التي يعلنها البيان. ويرفع `createInstance` خطأً عند المفاتيح غير
   المعروفة والأنواع الخاطئة والحقل المطلوب الذي لا شيء يملؤه.
5. **طبّق التغيير.** استخدم `insertInstance` أو `moveInstance` أو
   `duplicateInstance` أو `setInstanceProps` أو `setInstanceHidden` أو
   `removeInstance`. تعيد `{ ok: true, page }` أو `{ ok: false, issue }`.
6. **افحص المستند كله.** يعيد `checkPageData(theme, page)` كل مشكلة قبل الحفظ.
7. **تحقق من القالب** بعد تغيير تعريف: `validateThemeDefinition(theme)`.
8. **عاين واختبر.** اعرض الصفحة، أو استخدم مسار المعاينة والجسر؛ وشغّل اختبارات
   عقد القالب.

## واجهات API التي تستخدمها

| الهدف | API |
| --- | --- |
| تسلسل قالب | `themeManifest(theme)` |
| تحويل بيان إلى كتالوج قابل للتحرير | `manifestCatalog(manifest)` |
| التحقق من شكل المستند وقيم الحقول | `validatePageData(theme, input, scope)` |
| فحص صارم من جانب الكاتب | `checkPageData(theme, page)` |
| إضافة الكتل المطلوبة والثابتة | `completePage(theme, page)` |
| اختيار المستند الذي يُعرض | `resolveSurfaceDocument(theme, surface, saved, scope)` |
| إنشاء نسخة جديدة | `createInstance(definition, id, props)` |
| توليد id | `newInstanceId()` |
| تحرير مستند | `insertInstance`، `moveInstance`، `duplicateInstance`، `setInstanceProps`، `setInstanceHidden`، `removeInstance` |
| مقارنة إصدارين | `diffThemeManifests(previous, next)` |

ينشئ `manifestCatalog(manifest)` كائن `ThemeDefinition` مع `component: null`.
وهو للتحرير والتحقق فقط؛ لا تعرضه.

## حالات الرفض التي تعالجها

| الرمز | المعنى |
| --- | --- |
| `unknown-type` | النوع ليس في هذا الكتالوج؛ لا يُعرض شيء |
| `unknown-prop` | prop غير معلنة؛ وتُتجاهل |
| `invalid-prop` | القيمة تفشل في قواعد الحقل؛ وتُستخدم القيم الافتراضية |
| `missing-required-prop` | حقل مطلوب بلا قيمة أو محتوى أو قيمة افتراضية |
| `unknown-slot` / `disallowed-child` | العنصر التابع المحفوظ لم يعد يناسب الفتحة |
| `duplicate-id` | نسخة لاحقة تكرر id؛ وتفوز الأولى |
| `limit-exceeded` | تم تجاوز حد فتحة أو سطح أو عمق |
| `theme-mismatch` | رُكّب المستند لقالب آخر |
| `not-available` / `not-placeable` | المكوّن غير معروض على هذا السطح أو هذا الموضع |
| `slot-full` / `required-block` / `fixed-block` | العملية ستخرق قواعد التركيب |
| `load-failed` | أطلق `load` خطأً؛ ولا تزال props الأساسية تُعرض |
| `missing-component` | تعريف بلا مرجع مكوّن صالح للاستخدام |
| `multiple-slots-unsupported` | يستطيع العارض المرجعي ملء فتحة مسمّاة واحدة لكل نسخة |

فشل مستوى الصفحة يختلف عن فشل مستوى القسم. فقط غلاف غير صالح (شكل `version` أو
`surface` أو `sections`) يجعل `page` فارغًا؛ وكل مشكلة أخرى تُعدّ تدهورًا مع تقرير.

## تعريف الإنجاز

- [ ] يعيد `validateThemeDefinition(theme)` قائمة فارغة.
- [ ] ينجو `themeManifest` من دورة تحويل JSON ذهابًا وإيابًا ويتحقق.
- [ ] كل مستند مُضمَّن مع القالب يجتاز `validatePageData`.
- [ ] الصفحة المعدّلة تُعرض دون تقارير `onIssue` غير متوقعة.
- [ ] لا يُظهر `diffThemeManifests` تغييرًا كاسرًا عرضيًا.
- [ ] تعرض المعاينة والعرض العادي للمتسوق المحتوى نفسه، ناقص علامات المعاينة.

لسير عمل المستندات والبيان الكامل، تابع مع
[البيان والتحرير](/ar/sdk/theme/manifest).
