# المراجعات

المراجعات بيانات منتج. تُقرأ على الخادم، وتُكتب عبر مسار صغير في المتصفح يثبت
أن المتسوّق اشترى المنتج.

يمكن للمتجر إيقاف المراجعات عبر `config.reviewsEnabled`. وعندما تكون متوقفة، لا
تعرض قسم المراجعات ولا تستدعِ كتابات المراجعات.

## قراءة المراجعات

```ts
const { rows, total } = await store.products.reviews.list(product.id, {
  limit: 20,
  offset: 0,
});
```

`rows` صفحة من المراجعات، و`total` العدد الكامل. كلاهما يأتي من ظرف واحد؛ لا
تستنتج الإجمالي من طول الصفحة.

القراءة الفاشلة هي `{ rows: [], total: 0 }`. اعرض الحالة الفارغة، لا صفحة خطأ،
عندما لا يكون للمنتج مراجعات أو تكون القراءة متدهورة مؤقتًا.

تحتوي المراجعة على:

```ts
type Review = {
  id: string;
  customerName: string;
  rating: number;              // 1–5
  title: string | null;
  body: string;
  createdAt: string;
  verified: boolean;           // the order reached the customer
  media: ReviewMedia[];        // photos first, then a voice note
};
```

`verified: true` تعني أن المراجعة تستند إلى طلب مُسلَّم. اعرضها كشراء موثّق. ولا
تستخدم الاسم الكامل للعميل كمعرّف.

قد تكون `media` فارغة على الخوادم الأقدم. وعنصر الوسائط هو:

```ts
type ReviewMedia = {
  id: string;
  kind: "image" | "audio";
  url: string;
  thumbUrl: string | null; // photos only
  width: number | null;
  height: number | null;
  durationMs: number | null; // voice only
};
```

`url` و`thumbUrl` عنوانان عامان بالفعل. لا تبنِ عنوان وسائط من مفتاح كائن.

## مسار المراجعة

لكتابة مراجعة أربع خطوات:

1. **العثور على الشراء.** يدخل المتسوّق رقم الطلب والهاتف المستخدم في الطلب.
2. **اختيار منتج.** يسرد الطلب المؤهل منتجاته، وكل منتج منها معلَّم بأنه
   مُراجَع أو غير مُراجَع.
3. **إرفاق الوسائط (اختياري).** تُرفع الصور ورسالة صوتية قبل إرسال المراجعة.
4. **إرسال المراجعة.** يقرر الخادم ما إذا كانت تُنشر الآن أو تنتظر تحقق المتجر.

الخادم يملك القواعد: يجب أن يكون الطلب مُسلَّمًا، ويجب أن يطابق الهاتف، ولا يمكن
مراجعة المنتج إلا مرة واحدة، وإشراف المتجر يقرر الظهور.

## 1. إثبات الشراء

```ts
const response = await fetch("/api/review-eligibility", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    orderNumber,
    phone,
    ...(turnstileToken ? { turnstileToken } : {}),
  }),
});

const eligibility = await response.json();
if (!eligibility.success) {
  // ORDER_NOT_FOUND or REVIEW_ORDER_NOT_DELIVERED
  return;
}

eligibility.data;
// {
//   orderNumber,
//   customerName,
//   products: [{ productId, name, imageSrc, reviewed }],
//   media: {
//     maxPhotos,
//     voiceMaxSeconds,
//     grant,
//     expiresAt,
//   } | null,
// }
```

`media: null` تعني نصًا فقط. لا تعرض منتقي صور أو زر تسجيل عندما يكون التصريح
غائبًا.

`grant` قصير العمر. أرسله مع كل رفع ومع المراجعة. وإذا انتهت صلاحيته، اطلب من
المتسوّق إثبات الشراء مجددًا؛ ولا تعِد استخدام تصريح قديم.

إذا فعّل المتجر Turnstile، فمرّر رمز الودجة في `turnstileToken`. ويتحقق منه
الخادم مع بقية الطلب.

## 2. عرض ما يمكن مراجعته

```ts
for (const product of eligibility.data.products) {
  renderProductChoice({
    name: product.name,
    image: product.imageSrc,
    disabled: product.reviewed,
  });
}
```

يبقى المنتج المُجرى مراجعته ظاهرًا لكن لا يمكن مراجعته مجددًا. لا تحذفه بصمت؛
فالمتسوّق يحتاج إلى رؤية أن المراجعة موجودة.

## 3. رفع الوسائط

تُرفع الوسائط **قبل** إرسال المراجعة. وكل رفع يردّ بـ`uploadId`؛ وتحمل المراجعة
جميعها.

### الصور

`prepareReviewPhoto` مخصّصة للمتصفح وتعيش في نقطة دخول مستقلة:

```ts
import { prepareReviewPhoto } from "@wocart/storefront/review-media";

const prepared = await prepareReviewPhoto(photoFile);
```

ترسم الصورة بالاتجاه الصحيح، وتحدّ أطول ضلع فيها بـ1,600 px، وتعيد ترميزها
بصيغة WebP (أو JPEG). وإذا تعذر على المتصفح ذلك، تعيد الملف الأصلي؛ ولا يزال
الخادم يحوّله ويزيل EXIF.

ارفع الملف المُجهَّز كما هو:

```ts
const uploaded = await fetch("/api/review-upload", {
  method: "PUT",
  headers: {
    "Content-Type": prepared.type,
    "X-Review-Grant": grant,
  },
  body: prepared,
});

const { data } = await uploaded.json();
// { uploadId, kind: "image", bytes }
```

لا ترسل سلسلة base64 أو data URL. فالمسار يمرّر الملف كتدفّق، ويقرأ الخادم
نوعه من بايتاته.

### الرسائل الصوتية

```ts
import {
  canRecordVoice,
  createVoiceRecorder,
} from "@wocart/storefront/review-media";

const media = eligibility.data.media;
if (canRecordVoice() && media?.voiceMaxSeconds) {
  const recorder = createVoiceRecorder({
    maxSeconds: media.voiceMaxSeconds,
    onTick: (elapsedMs) => updateTimer(elapsedMs),
    onLimit: (voice) => uploadVoice(voice),
  });

  await recorder.start();
  const voice = await recorder.stop();
  await uploadVoice(voice);
}
```

يسجّل المسجّل صوتًا أحادي القناة بمعدل 32 kb/s تقريبًا ويتوقف عند حد المتجر.
ويرسل الرفع الملف ومدته:

```ts
async function uploadVoice(voice: { blob: Blob; durationMs: number; mimeType: string }) {
  const response = await fetch("/api/review-upload", {
    method: "PUT",
    headers: {
      "Content-Type": voice.mimeType,
      "X-Review-Grant": grant,
      "X-Media-Duration-Ms": String(voice.durationMs),
    },
    body: voice.blob,
  });
  return response.json();
}
```

تعيد `canRecordVoice()` القيمة false على المتصفحات التي لا تدعم التسجيل
بالميكروفون؛ أخفِ زر التسجيل بدلًا من عرض زر لا يمكن أن يعمل.

تُحفظ الصورة على الخادم بصيغة WebP؛ وهذا التحويل هو أيضًا ما يزيل بيانات EXIF
وGPS. لا تضف خطوة ثانية في العميل «لإزالة البيانات الوصفية».

## 4. الإرسال

```ts
const response = await fetch("/api/submit-review", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    orderNumber,
    phone,
    productId,
    rating,               // 1–5
    title: title || undefined,
    body,
    grant,
    uploads: uploadIds,   // every uploadId, or omit for text only
  }),
});

const result = await response.json();
if (!result.success) {
  if (result.domainError?.category === "validation") {
    // Show result.domainError.fieldIssues.
  }
  return;
}

result.data;
// { id, visibility: "published" | "after_review" }
```

هذا المسار هو مسار الأصل نفسه الموضح أدناه؛ ولا يستورد المتصفح عميل الخادم
أبدًا. وقد تكون `visibility` غائبة على الخوادم الأقدم. اعامل غيابها كإشراف
المتجر المعتاد، لا كدليل على أن المراجعة عامة.

لا تفرّغ النموذج عند الفشل. يجب أن يستطيع المتسوّق تصحيح النص أو التقييم أو
المرفقات والمحاولة مجددًا.

## جلسة المراجعة

الخطوات من 1 إلى 4 كائن واحد في المتصفح. تتولى `createReviewSession`، من
`@wocart/storefront/review-media`، إثبات الشراء، وإرسال كل صورة أو رسالة صوتية
لحظة إضافتها — مع تقدّمها، وإعادة المحاولة عند انقطاع الاتصال، وتصغير الصورة
أولًا — ثم الإرسال. كل رفض يعود كرمز، لا كخطأ مرمي أبدًا:

```ts
import { createReviewSession } from "@wocart/storefront/review-media";

const session = createReviewSession({
  routes: { eligibility: "/api/review-eligibility", upload: "/api/review-upload", submit: "/api/submit-review" },
});

const found = await session.find({ orderNumber, phone });
if (found.status === "refused") return say(found.code);

const upload = session.upload(file, { kind: "image", onProgress: (share) => showProgress(share) });
const sent = await upload.result; // "sent" with its uploadId, "refused" with a code, or "cancelled"

const review = await session.submit({ productId, rating, body, title, uploads });
```

ترفض `find` رقم طلب غير صحيح الشكل قبل السؤال (`VALIDATION_FAILED`)، وتنسى
`reset()` الطلب وتلغي ما يزال قيد الإرسال حين يغيّر المتسوق الطلب. صُغ عبارة لكل
رمز في `REVIEW_REFUSAL_CODES` — ‏`Record` عليها يُفشل فحص الأنواع حين تضيف المنصة
رمزًا جديدًا — واقرأ `VALIDATION_FAILED` عند الإرسال على أنه مراجعة أقصر من
اللازم. وتعطي `REVIEW_TEXT_LIMITS` أطوال العنوان والنص لحقولك وتلميحاتك.

## مسارات الأصل نفسه

لا يحمل المتصفح مفتاح المتجر. اربط مسارات المراجعة في SDK مرة واحدة:

```ts
// src/theme/api-routes.ts
import type { APIContext } from "astro";
import { createStorefrontRoutes } from "@wocart/storefront/astro";

export const routes = createStorefrontRoutes<APIContext>({
  client: (context) => context.locals.store.client,
});
```

ثم صدّر المعالجات التي تحتاجها:

```ts
// src/pages/api/review-eligibility.ts
import { routes } from "../../theme/api-routes";
export const POST = routes.reviewEligibility;
```

```ts
// src/pages/api/review-upload.ts
import { routes } from "../../theme/api-routes";
export const PUT = routes.reviewUpload;
```

```ts
// src/pages/api/submit-review.ts
import { routes } from "../../theme/api-routes";
export const POST = routes.reviewSubmit;
```

وللقائمة:

```ts
// src/pages/api/product-reviews/[productId].ts
import { routes } from "../../../theme/api-routes";
export const GET = routes.reviewsList;
```

تضيف المسارات فحص الأصل المختلف، وحدود الإدخال، ورأس `X-Review-Grant`، ومعالجة التدفّق.
لا تعد تنفيذها في مكوّن.

<Callout type="caution" title="وسائط المراجعة كود متصفح">
`@wocart/storefront/review-media` تلمس canvas والميكروفون وDOM. لا تستوردها أبدًا
من frontmatter صفحة أو middleware أو action أو مسار API.
</Callout>

## الحالات الفارغة وغير المتاحة

- `reviewsEnabled: false` — لا تعرض أي واجهة مراجعات ولا تستدعِ أي نقطة نهاية
  للمراجعات.
- `rows: []` — «لا توجد مراجعات بعد»؛ وقد يظل النموذج متاحًا.
- `media: null` — نموذج مراجعة نصي فقط.
- `maxPhotos: 0` — لا منتقي صور.
- `voiceMaxSeconds: null` — لا مسجّل صوتي.
- `reviewed: true` — اعرض المنتج، وعطّل الإجراء.
- `eligibility.success === false` — أبقِ النموذج واعرض سبب الخادم.

لا تحوّل رقم طلب خاطئًا إلى «لا مراجعات». فهو رفض للإثبات، لا قائمة مراجعات
فارغة.
