# اختبار واجهة المتجر

لاختبار واجهة المتجر مهمتان: إثبات أن الصفحة تُعرض عندما يكون الخادم سليمًا،
وإثبات أنها ما تزال تقول شيئًا مفيدًا عندما لا يكون كذلك.

يجعل عقد القراءة في SDK المهمة الثانية قابلة للاختبار: فالقراءة الفاشلة تُحل إلى
قيمة فارغة بدل أن ترمي خطأ.

## اختبر العقود، لا الترميز

ابدأ بخادم وهمي. وجّه العميل إلى أصل اختبار واستبدل `globalThis.fetch`:

```ts
import { afterEach, describe, expect, it, vi } from "vitest";
import { createStoreClient } from "@wocart/storefront/server";

function serve(body: unknown, status = 200) {
  const fetch = vi.fn(async () => new Response(JSON.stringify(body), {
    status,
    headers: { "Content-Type": "application/json" },
  }));
  vi.stubGlobal("fetch", fetch);
  return fetch;
}

const store = () => createStoreClient({
  serverUrl: "https://api.test",
  apiKey: "test-key",
});

afterEach(() => vi.unstubAllGlobals());

describe("catalogue degradation", () => {
  it("lists nothing instead of throwing", async () => {
    serve({ error: "down" }, 503);
    await expect(store().products.list()).resolves.toEqual([]);
  });

  it("reports the failure once", async () => {
    const onError = vi.fn();
    serve({ error: "down" }, 503);
    await createStoreClient({
      serverUrl: "https://api.test",
      apiKey: "test-key",
      onError,
    }).products.list();

    expect(onError).toHaveBeenCalledWith(
      expect.objectContaining({ operation: "products.list" }),
    );
  });
});
```

يثبت الاختبار الأول أن الحالة الفارغة في الصفحة يمكن الوصول إليها. ويثبت
الثاني أن المشغّل يرى التدهور الذي لا يراه المتسوق.

افعل الشيء نفسه للقراءات التي تعتمد عليها كل صفحة:

| القراءة | قيمة الفشل التي تتحقق منها |
| --- | --- |
| `config.get` | `null` |
| `products.get` | `null` |
| `products.page` | `{ items: [], hasNext: false }` |
| `categories.list` | `[]` |
| `collections.get` | `null` |
| `menus.get` | `null` |
| `pages.get` | `null` |
| `shipping.rates` | `{}` |
| `geo.communes` | `[]` |
| `orders.tracking` | `null` |

ثم يتحقق اختبار الصفحة من النتيجة المرئية: إعادة كتابة 404 لمنتج غير موجود،
وإعادة محاولة لبلديات فارغة، ونموذج مراجعة مخفي، ولا حدث تحويل.

## اختبر الكتابات

الكتابة تعيد نتيجة؛ ولا ترمي خطأ. وغطِّ ثلاثة فروع:

```ts
it("keeps the form on a refusal", async () => {
  serve({
    error: "Out of stock",
    domainError: {
      category: "business",
      code: "OUT_OF_STOCK",
      message: "Out of stock",
      retryable: false,
      operation: "orders.create",
      sideEffect: "rejected",
    },
  }, 422);

  const result = await store().orders.create({
    // the minimum valid order
  } as never);

  expect(result.success).toBe(false);
  if (!result.success) {
    expect(result.domainError.category).toBe("business");
  }
});
```

وغطِّ أيضًا:

- فشل تحقق مع `fieldIssues`؛
- رفض كوبون (`couponRefusalOf(result)` لا يعيد `null`)؛
- فشل نقل (يرفض `fetch`)، حيث تبقى النتيجة `ClientResult`، لا استثناء.

يجب أن يتحقق اختبار واجهة إتمام الطلب من أن الإرسال الفاشل يحتفظ بإدخال
المتسوق.

## اختبر الدوال المساعدة في المتصفح مباشرة

المساعدات النقية لا تحتاج خادمًا:

```ts
import {
  buildWhatsAppHref,
  formatMoney,
  resolvePrefillText,
  servedLanguage,
} from "@wocart/storefront";

expect(formatMoney(5000, { symbol: "دج", locale: "ar-DZ" })).toContain("دج");

expect(
  resolvePrefillText({
    template: "{product} — {url}",
    storeName: "Shop",
    productName: "Robe",
    url: "https://shop.test/products/robe?utm_source=ads",
  }),
).toBe("Robe — https://shop.test/products/robe");

expect(
  servedLanguage(
    {
      lang: "ar",
      locales: [
        { code: "ar", nativeName: "العربية", direction: "rtl" },
        { code: "fr", nativeName: "Français", direction: "ltr" },
      ],
    },
    "fr",
  )?.direction,
).toBe("ltr");
```

واختبر مسارات التراجع أيضًا: لا منتج، ولا طلب، وملء مسبق طويل جدًا، ولغة
مجهولة، وصورة بلا نطاق وسائط.

تقبل `createBasketStore` محوّل ذاكرة، لذا تُختبر من دون متصفح:

```ts
import {
  createBasketStore,
  createMemoryStorageAdapter,
} from "@wocart/storefront";

const basket = createBasketStore({
  storage: createMemoryStorageAdapter(),
});

basket.addLine(line);
basket.addLine({ ...line, quantity: 2 });
expect(basket.getLines()).toHaveLength(1);
expect(basket.getCount()).toBe(3);
```

## اختبر المسارات

أسهل طريقة لاختبار مصنع المسارات هي اعتباره حدًا HTTP: استدعِ المعالج المصدَّر
بـ `APIContext` وعميل وهمي، ثم تحقق من الحالة والجسم.

على الأقل، تحقق من:

- طلب POST من أصل مختلف يعيد 403؛
- جسم غير صالح يعيد 400؛
- رفع مراجعة بلا `X-Review-Grant` يُرفض؛
- رفض تجاري من الخادم يُعيّن إلى 422؛
- حد معدل يُعيّن إلى 429؛
- مسار قراءة فاشل يحافظ على شكل غلافه.

تعيين حالات المسار جزء من العقد العام. ويجب ألا يتغير بين الاختبار والإنتاج.

## تحققات وقت البناء

شغّل هذه في القالب قبل الشحن:

```sh
npm run typecheck
npm run test
npm run build
```

وفي إعداد القالب نفسه، `astro check` إذا كان المشروع يستخدمه.

يلتقط البناء الإخفاقات التي لا تستطيع اختبارات الوحدة التقاطها:

- استيراد خاص بالخادم في جزيرة متصفح؛
- إجراء Astro أو تصدير مسار API مفقود؛
- صفحة تُولَّد مسبقًا بينما تقرأ بيانات الطلب؛
- مخطط بيئة معطوب.

<Callout type="caution" title="قد ينجح البناء مع متجر فارغ">
غياب `STORE_API_KEY` يجعل العميل يرمي خطأ عند الإنشاء؛ والخادم غير القابل
للوصول يجعل القراءات فارغة. ولا يفشل أي منهما بناءً ساكنًا. شغّل بناءً واحدًا
على الأقل أو معاينة مقابل متجر حقيقي قبل اعتبار القالب منتهيًا.
</Callout>

## اختبار دخان حي

استخدم متجرًا تجريبيًا، لا الإنتاج، من أجل:

1. الرئيسية والكتالوج والفئة والمجموعة وصفحة منتج.
2. منتج بخيارات متعددة: اختر كل خيار وتأكد من تغيّر السعر.
3. أضف إلى السلة، وغيّر الكمية، واحذف سطرًا.
4. اطلب عرض سعر بولاية، ثم غيّر الولاية وتأكد من تغيّر الرسوم.
5. طبّق كوبونًا صالحًا وآخر غير صالح.
6. أرسل طلب منتج وطلب سلة.
7. صفحة هبوط بمنتج مرتبط.
8. صفحة متجر وقائمة.
9. مراجعة: رقم طلب خاطئ، وطلب صحيح، وصورة، وملاحظة صوتية.
10. إتمام الطلب مع OTP مفعّلًا ومعطّلًا.
11. صفحة الشكر: يظهر الطلب؛ ويُطلق البكسل مرة واحدة مع
    `eventID = orderId`.

لا تشغّل هذه المجموعة في CI مقابل متجر مشترك؛ فهي تكتب طلبات.

## تعريف الإنجاز

تكون واجهة المتجر التي تستخدم SDK جاهزة عندما:

- كل صفحة تعرض حالتها الفارغة وحالة الخطأ لديها دون استثناء؛
- كل رابط داخلي يمر عبر `localizeHref`؛
- اللغة الأساسية بلا بادئة واللغات الأخرى لها بادئة؛
- لا يوجد مفتاح متجر ولا مخطط Zod في حزمة المتصفح؛
- كل الكتابات تمر عبر مسارات Astro أو إجراءاته؛
- يُعاد تسعير الطلب من الخادم، لا من المتصفح؛
- السلة محدودة السعة وعرض السعر هو المرجع؛
- صفحة الشكر لا تطلق أي حدث عندما تعيد `orders.tracking` القيمة `null`؛
- المعاينة مستثناة من التخزين المؤقت وإعادة التحقق تُسقط وسم الصفحة؛
- نجاح `npm run typecheck` و`npm run test` و`npm run build`.

## التوافق

يتبع SDK الترقيم الدلالي:

- إصدار patch يصلح السلوك دون تغيير API؛
- إصدار minor يضيف ميزات متوافقة مع الإصدارات السابقة؛
- إصدار major قد يزيل صادرات أو يغيّرها.

ثبّت الإصدار الدقيق في القالب. واقرأ `CHANGELOG.md` قبل الترقية؛ فقد يفترض
قالب أحدث تصديرًا جديدًا من SDK بينما ما يزال بناء واجهة متجر أقدم يعمل.

مفتاح القالب جزء من العقد. يجب أن يتوافق `defineTheme({ key })` مع خيار
`theme` في العميل؛ وتغيير المفتاح يترك تعديلات نص التاجر ومستندات صفحاته لذلك
القالب بلا مالك.

<Callout type="info" title="الاستيرادات العميقة ليست عامة">
استورد فقط من `@wocart/storefront` و`/server` و`/astro` و`/review-media`.
والمسار العميق إلى `dist/` أو `src/` قد يتغيّر في أي إصدار. وإذا كان السطح
العام يفتقد شيئًا تحتاجه واجهة المتجر، فذلك تغيير في SDK، لا استيراد عميق.
</Callout>
