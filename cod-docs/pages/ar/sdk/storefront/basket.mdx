# السلة وعروض السعر

السلة هي نية المتسوق. تعيش في المتصفح، لا في D1 أبدًا. والخادم هو من يملك
الأسعار.

لذا لواجهة المتجر قاعدة واحدة يجب تذكّرها: **سلة المتصفح للعرض والتفاعل؛
و`cart.validate` للمال**.

## سلة المتصفح

```ts
import { createBasketStore } from "@wocart/storefront";

const basket = createBasketStore();

basket.addLine({
  productId: product.id,
  productName: product.name,
  variantId: variant?.id ?? null,
  variantLabel: variantLabel(variant),
  quantity: 1,
  unitPrice: view.basePrice, // display only
  href: `/products/${product.handle}`,
  ...(cardImageUrl ? { image: cardImageUrl } : {}),
});
```

يستخدم `createBasketStore` `localStorage` عندما يكون متاحًا، ومهايئًا في الذاكرة
في SSR أو الاختبارات، ويفشل بهدوء عندما يكون التخزين محظورًا.
والمتصفح الذي لا يستطيع التخزين تظل لديه سلة في الذاكرة للصفحة الحالية؛
وتخبرك `isPersistent()` هل تصمد بعد إعادة التحميل.

الطرق هي:

| الطريقة | النتيجة |
| --- | --- |
| `getLines()` | السطور الحالية |
| `getCount()` | إجمالي الكمية |
| `getSubtotal()` | مجموع فرعي تفاؤلي للعرض |
| `addLine(line)` | يدمج حسب المنتج + المتغير |
| `setQuantity(key, quantity)` | محدودة؛ و`<= 0` يحذف |
| `removeLine(key)` | يحذف سطرًا واحدًا |
| `clear()` | يفرغ السلة |
| `toOrderItems()` | `items[]` جاهزة للخادم |
| `subscribe(listener)` | التغييرات المحلية وبين التبويبات |
| `isPersistent()` | هل يصمد التخزين بعد إعادة التحميل |

الحدود هي `MAX_BASKET_LINES` (20) و`MAX_BASKET_LINE_QUANTITY` (100). هوية
السطر هي المنتج + المتغير، لذا يكون للمنتج نفسه بمتغيرين سطران.

`unitPrice` ليست إلا ما يعرضه الدرج أثناء انتظار عرض السعر. لا ترسلها كسعر،
ولا تستخدم `getSubtotal()` كإجمالي الطلب.

### اشترك مرة واحدة

```ts
const unsubscribe = basket.subscribe((lines) => {
  renderBadge(lines.reduce((total, line) => total + line.quantity, 0));
  scheduleQuote();
});
```

يبلّغ مخزن السلة عن التغييرات المحلية ويعيد قراءة التخزين عندما يغيّر تبويب
آخر السلة. أبقِ المستمع خفيفًا؛ فعرض السعر مؤجَّل بشكل مستقل.

### اختيار عرض

إذا عرض المنتج شرائح كمية أو «اشترِ X واحصل على Y»، فاحفظ اختيار المتسوق في
السطر:

```ts
basket.addLine({
  // …
  offerId: selectedTier.offerId,
});
```

الاختيار الصريح اللاحق يحل محله؛ أما الإضافة العادية فتبقي الاختيار الحالي.
ولا يطبّق الخادم العرض إلا عندما تستوفي الكمية الشرط.

### بناء السطر من منتج

```ts
import { getProductView, productImageSource } from "@wocart/storefront";

const view = getProductView(product);
const image = productImageSource(product);

basket.addLine({
  productId: product.id,
  productName: product.name,
  variantId: view.defaultVariant?.id ?? null,
  variantLabel: view.defaultVariant
    ? Object.values(view.defaultVariant.variations).join(" / ")
    : null,
  quantity,
  unitPrice: view.basePrice,
  href: `/products/${product.handle}`,
  ...(image ? { image } : {}),
  ...(offerId ? { offerId } : {}),
});
```

### عرض يُختار قطعةً قطعة

قد يسمح عرض من عدة قطع للمتسوق باختيار متغيّر لكل قطعة — ثلاث بيجامات بمقاسين.
أضف هذا الاختيار كما يحمله نموذج الطلب: نداء واحد، وسطر لكل متغيّر يضم قطعه،
وكل سطر يحمل العرض، والكل أو لا شيء — السلة التي لا تتسع لكل الأسطر الجديدة لا
تضيف شيئًا.

```ts
basket.addSelections(
  { productId, productName, unitPrice, offerId, href, image },
  [
    { variantId: "6m", variantLabel: "6 mois" },
    { variantId: "12m", variantLabel: "12 mois" },
    { variantId: "6m", variantLabel: "6 mois" },
  ],
);
```

### ما أضافته الإضافة

`addedLines(before, after)` هو ما وضعته نقرة واحدة في السلة: كل سطر زاد، بمقدار
ما زاد. أرسل ذلك كحدث Meta ‏`AddToCart` — لا السلة كلها أبدًا — واقرأ الجواب
الفارغ على أنه سلة لم يبق فيها مكان، ويجب إخبار المتسوق بذلك.

```ts
import { addedLines, buildMetaAddToCartPayload } from "@wocart/storefront";

const before = basket.getLines();
const added = addedLines(before, basket.addLine(line));
if (added.length === 0) showBasketFull();
else tracker.track("AddToCart", buildMetaAddToCartPayload(added));
```

## طلب عرض سعر للسلة

عرض السعر قراءة من الخادم. في المتصفح، اطلبه عبر مسارك ذي الأصل نفسه باستخدام
`createQuoter`: يرسل السطور مع ما أدخله المتسوق حتى الآن ولا يحتفظ إلا بآخر جواب،
فلا يحل جواب بطيء لنقرة سابقة محل جواب أحدث أبدًا.

```ts
import { createQuoter } from "@wocart/storefront";

const quoter = createQuoter({ endpoint: "/api/cart/validate" });

const result = await quoter.quote({ items: basket.toOrderItems() }, { destination, couponCode, phone });
if (result.status === "fresh") show(result.quote);
// "stale": a newer question was asked meanwhile — keep what is shown.
// "failed": no usable answer — keep the optimistic basket.
```

نموذج طلب المنتج يسأل بالطريقة نفسها، بمنتج واحد كما يرسله النموذج
(`{ productId, productName, quantity, variantSelections, offerId }`). ويُقرأ الجواب
دون Zod ‏(`readCartQuote`)، فلا يصل أي schema إلى متصفح المتسوق.

على الخادم، الاستدعاء نفسه هو `cart.validate`:

```ts
const result = await store.cart.validate(items, {
  destination: {
    wilayaId: 16,
    communeId: "c-16-001",
    deliveryType: "home",
  },
  couponCode: "RAMADAN10",
});

if (!result.success) {
  // The quote is read-only; show the reason or keep the optimistic basket.
  return;
}

result.data;
```

`cart.validate` للقراءة فقط: لا يُكتب شيء ولا يُحجز مخزون. ويمكن عرض الفشل
بأمان مع الاحتفاظ بالسلة.

لنموذج طلب منتج لم يدخل السلة بعد، استخدم `cart.quote` بدلًا من ذلك. يقبل إما
سلة أو منتجًا واحدًا كما يرسله النموذج:

```ts
const result = await store.cart.quote({
  productId: product.id,
  productName: product.name,
  quantity: 3,
  variantSelections: [{ variantId: variant.id, variantLabel }],
  offerId,
});
```

يستخدم عرض السعر والطلب القواعد نفسها لبناء السطور، لذا يكون عرض السعر هو ما
ينبغي أن يكلّفه الطلب.

## ما يعيده عرض السعر

```ts
type CartValidation = {
  lines: CartValidationLine[];
  subtotal: number;
  rewards: CartReward[];
  freeDelivery: {
    fromOffer: boolean;
    threshold: number | null;
    qualified: boolean;
    remaining: number;
  };
  delivery?: { available: true; fee: number; total: number }
    | { available: false; fee: null; total: null };
  coupon?: CouponOutcome | null;
};
```

### السطور

يحمل كل سطر إجابة الكتالوج الحالية:

```ts
type CartValidationLine = {
  productId: string;
  variantId: string | null;
  variantLabel: string | null;
  productName: string;
  quantity: number;
  unitPrice: number;
  lineTotal: number;       // offers and coupon share applied
  offerId?: string | null;
  offerName?: string | null;
  discount?: number | null;
  maxQuantity: number | null;
  blocker: "missing" | "unlisted" | "out_of_stock" | null;
};
```

يُستبعد السطر المحظور من المجموع الفرعي والعروض وحساب التوصيل المجاني. اعرض
السبب وعطّل إتمام الطلب ما دام أي سطر محظورًا. ولا تحذف السطر نيابة عن المتسوق
إلا إذا كانت واجهتك تعرض هذا الإجراء صراحة.

تكون `maxQuantity` بقيمة `null` عندما لا يخضع المنتج لتتبع المخزون.

### المكافآت

تسرد `rewards` الهدايا التي حصلت عليها السلة. وهي ليست سطورًا في السلة؛ اعرضها
في صف «هدية مجانية» منفصل.

### التوصيل المجاني

```ts
const free = quote.freeDelivery;
if (free.qualified) {
  // Delivery is free: from the threshold or an offer.
} else if (free.threshold !== null) {
  // free.remaining is how much more the subtotal needs.
}
```

الحد الأدنى إعداد خاص بالمتجر؛ ويظل عرض السعر هو المرجع، لأن عرضًا ما قد يجعل
التوصيل مجانيًا قبل بلوغ الحد.

### التوصيل

لا توجد `delivery` إلا عندما يُمنح عرض السعر وجهة:

```ts
if (quote.delivery?.available) {
  showDelivery(quote.delivery.fee, quote.delivery.total);
} else if (quote.delivery) {
  showNotDeliverable();
}
```

وعندما تكون غائبة، لا تخترع رسومًا. الأسعار الافتراضية في
[التوصيل والجغرافيا](/ar/sdk/storefront/delivery) مجرد قيمة مؤقتة؛ وعرض السعر
هو ما يحدد ما يفرضه الطلب.

## الكوبونات

يحمل عرض السعر نتيجة الكود:

```ts
type CouponOutcome =
  | { code: string; applied: true; discount: number; freeShipping: boolean }
  | { code: string; applied: false; reason: string; shortBy?: number; startsAt?: string };
```

اعرض الخصم والتوصيل المجاني المطبّقين، أو السبب. `reason` مفتوح؛ والسبب الذي
لا تتعرّف عليه واجهتك ينبغي استبداله بجملة عامة.

يمكن أن يحمل رابط قابل للمشاركة الكود:

```ts
import { couponFromUrl } from "@wocart/storefront";

const code = couponFromUrl(new URL(location.href));
```

يمكن للمتصفح أيضًا قراءة قيمة عرض سعر وصلت إليه دون تشغيل المخطط:

```ts
import { readCouponOutcome } from "@wocart/storefront";

const coupon = readCouponOutcome(value);
```

استخدمه عندما تُخزَّن صفحة مؤقتًا منفصلة عن سكربتاتها وقد تحمل شكل إصدار
آخر. ولا تستخدم مخططًا في المتصفح.

### تلميح أم رفض

بعض حالات الرفض تخص الرمز — غير معروف، أو خارج تواريخه، أو نفد، أو ليس لهذا
المتسوق — وبعضها يخص السلة التي لم تستوفِ الرمز بعد: حد أدنى لم يُبلغ، أو منتج
تحت عرض آخر، أو هاتف لم يُكتب بعد. تميّز `couponRefusalTone(reason)` بينها،
ليصوغ القالب التلميح بلطف والرفض بوضوح:

```ts
import { COUPON_REFUSAL_REASONS, couponRefusalTone } from "@wocart/storefront";

const tone = couponRefusalTone(outcome.reason); // "hint" or "refused"
```

اكتب أنواع عباراتك على `COUPON_REFUSAL_REASONS` (‏`Record` عليها)، فيفشل فحص
الأنواع عند سبب جديد تضيفه المنصة بدل أن يصل إلى المتسوق كجملة عامة.


## ظهور السلة

`config.cartEnabled` هو المفتاح:

```astro
{config.cartEnabled && <CartDrawer />}
```

المتجر الذي تكون فيه السلة متوقفة يجب ألا يرسل أي وسوم HTML للسلة ولا جزيرة Astro
للسلة ولا طلبًا للسلة. ويظل نموذج الطلب المباشر للمنتج يعمل؛ فالسلة سطح
إضافي.

## حلقة آمنة للدرج

1. اعرض `getLines()` فورًا، مع المجموع الفرعي التفاؤلي.
2. أخّر عرض السعر قليلًا بعد تغيير سطر.
3. استبدل العرض بسطور الخادم ومكافآته وإجمالياته عندما يجيب.
4. أبقِ العرض التفاؤلي إذا فشل عرض السعر؛ فإتمام الطلب سيطلب عرضًا جديدًا.
5. عطّل إتمام الطلب ما دام سطر محظورًا أو التوصيل غير متاح.
6. أرسل `basket.toOrderItems()` مع الطلب، ولا ترسل سعرًا مبنيًا يدويًا أبدًا.

<Callout type="caution" title="إجمالي المتصفح ليس إجمالي الطلب">
يمكن لأي شخص تعديل `localStorage` وتغيير `unitPrice`. قد يعرض الدرج ذلك الرقم
على نحو تفاؤلي، لكن الخادم يعيد تسعير كل سطر ويحسم التوصيل مجددًا عند إنشاء
الطلب. لا تعرض أبدًا إجماليًا محسوبًا في العميل كمبلغ سيُحصَّل.
</Callout>
