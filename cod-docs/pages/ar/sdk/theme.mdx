# SDK القوالب

قالب CodFlow هو واجهة متجر Astro. يمنحه `@wocart/storefront` المنتجات والمجموعات
والسلال وإتمام الطلب. و`@wocart/theme` طبقة اختيارية تتيح أيضًا للتاجر تغيير
نصوص القالب وصوره وتنسيقاته وترتيب أقسامه دون لمس الكود.

**لا** تحتاج إلى `@wocart/theme` لبناء قالب. استخدمه عندما تريد أن يكون القالب
قابلًا للتحرير أو لإعادة الاستخدام أو جاهزًا للمشاركة مع متاجر أخرى.

إنها حزمة مساعدة صغيرة، لا إطار عمل. يبقى مشروع Astro ومكوّناتك وCSS ملكًا لك؛
ويضيف SDK القواعد التي تجعل تغييرات التاجر المحفوظة آمنة للقراءة والعرض.

## لمن هذا الدليل

| إذا كنت… | ما تقرأه |
| --- | --- |
| جديدًا على قوالب CodFlow، أو مطوّرًا بأسلوب «vibe coding»، أو تبني بالذكاء الاصطناعي | [بناء قالب](/ar/sdk/theme/build)، ثم [تخصيص قالب](/ar/sdk/theme/customize) |
| تبني واجهة متجر Astro مخصّصة لمتجر واحد، بلا تحرير بدون كود | يمكنك تجاوز هذه الحزمة. استخدم [`@wocart/storefront`](/ar/sdk/storefront) وAstro |
| تجعل قالبًا قابلًا لتحرير التاجر في CodFlow Studio | [بناء قالب](/ar/sdk/theme/build)، ثم [الحقول](/ar/sdk/theme/fields) و[التركيب](/ar/sdk/theme/composition) و[الصفحات](/ar/sdk/theme/pages) |
| تجهّز قالبًا للسوق، أو للمشاركة أو البيع | المسار القابل للتحرير أعلاه، مع [البيان](/ar/sdk/theme/manifest) و[الإعدادات والنصوص](/ar/sdk/theme/settings-copy) و[الاختبار](/ar/sdk/theme/testing) |
| مساعد ذكاء اصطناعي يعمل على قالب | [استخدام الذكاء الاصطناعي لبناء قالب](/ar/sdk/theme/agents) |

يبدأ الدليل بسيطًا ويضيف التفاصيل صفحة بعد صفحة. يمكنك التوقف بمجرد أن يؤدي
قالبك ما تحتاجه.

## طريقتان للبناء

| | واجهة متجر مخصّصة | قالب قابل للتحرير |
| --- | --- | --- |
| من يغيّر التصميم | أنت، في الكود | أنت في الكود؛ والتاجر يغيّر المحتوى والتخطيط |
| ما تكتبه | صفحات ومكوّنات Astro | مكوّنات Astro، مع التعريفات والمستندات الافتراضية |
| ما تحتاجه | `@wocart/storefront` | `@wocart/storefront` و`@wocart/theme` |
| أين تعيش الإعدادات | كودك أو البيئة | إعدادات محفوظة ومستندات صفحات JSON |
| مناسب لـ | متجر واحد بتصميم ثابت | قوالب تُعاد استخدامها بين المتاجر، أو تُباع كمنتج |

واجهة المتجر المخصّصة هي الخيار الأبسط. والقالب القابل للتحرير يكلّف إعدادًا
أكثر لأن كل خيار قابل للتحرير يجب أن يُعلَن ويُحفظ ويُتحقق منه. وبقية هذا
الدليل عن المسار الثاني.

<Callout type="info" title="متجر واحد أم متاجر؟">
إذا كان القالب يخص متجرًا واحدًا وتتحكم في كل تغيير في الكود، فواجهة متجر Astro
مخصّصة تكفي. ولا تحتاج إلى محرر أو بيان أو معاينة.

وإذا كان متجر آخر سيستخدم القالب — عبر السوق أو عميل أو تاجر يحرّره في CodFlow
Studio — فابنِ المسار القابل للتحرير. هذا ما يجعل القالب قابلًا للنقل دون أن
تغيّر كوده لكل متجر.
</Callout>

## كلمات ستراها

تظهر هذه الكلمات في كل مكان في الدليل. لا تحتاج إلى حفظها الآن؛ عُد إليها
عندما تستخدمها إحدى الصفحات.

| الكلمة | المعنى المبسّط |
| --- | --- |
| **المكوّن** | جزء قابل لإعادة الاستخدام من صفحة، مثل قسم الواجهة الرئيسية (hero) أو شبكة منتجات أو تذييل |
| **الحقل** | شيء واحد يستطيع التاجر تغييره في مكوّن، مثل عنوان أو صورة أو حد |
| **النسخة** | نسخة موضوعة من مكوّن، بقيمها المحفوظة |
| **المستند** | القائمة المرتبة من الأقسام والكتل التي تصنع صفحة |
| **السطح** | موضع يملأه مستند: الصفحة الرئيسية أو قالب منتج أو الترويسة |
| **الفتحة** | مساحة مسمّاة داخل مكوّن يمكن أن تذهب إليها الكتل الفرعية |
| **الإعداد** | خيار للمتجر كله، مثل خط أو مجموعات الألوان |
| **البيان** | وصف JSON لكل ما يجعل القالب قابلًا للتحرير |
| **مفتاح القالب** | المعرّف الدائم لقالب؛ تُحفظ تعديلات التاجر ضمنه |

في القالب القابل للتحرير، الصفحة ليست ملف Astro ثابتًا. يعرض Astro **مستندًا**
— بيانات تقول أي المكوّنات تظهر وأي القيم تحمل. ويوفّر القالب المكوّنات وقيمها
الافتراضية.

## النصفان

يفصل SDK بين ما يعرفه الكود فقط وما يستطيع المتجر حفظه.

| | مملوك للكود | مملوك للبيانات |
| --- | --- | --- |
| ما هو | تعريفات المكوّنات والحقول والقيم الافتراضية والفتحات ودوال `load` الاختيارية | مستندات صفحات JSON وإعدادات المتجر |
| من يكتبه | مطوّر القالب | التاجر أو المحرر أو CLI أو مساعد |
| متى يُتحقق منه | وقت البناء وعند تحميل القالب | كل مرة يُقرأ فيها مستند محفوظ |
| ما يقرأه | العارض والبيان | `parsePageData` و`validatePageData` |

يربط **البيان** بين النصفين. يحوّل نصف الكود إلى JSON بسيط، لتتمكن أداة من
عرض الحقول الصحيحة دون تشغيل Astro أو كود القالب.

## ما تمنحك الحزمة إياه

- **كتالوج مكوّنات مُعرّف الأنواع.** عرّف مكوّنًا مرة واحدة؛ واحصل على أنواع
  حقوله وprops من التعريف نفسه.
- **قراءات آمنة.** المستند المحفوظ التالف أو القديم يُصلَح حيث أمكن، ويُبلَّغ
  عنه حيث لم يمكن، ولا يُسقط الصفحة كلها أبدًا.
- **قواعد التخطيط.** تُطبَّق الفتحات والكتل المطلوبة والكتل الثابتة والحدود عند
  تحرير المستند، لا تُترك لكل مكوّن.
- **عارض واحد.** يملأ `InstanceView.astro` القيم الافتراضية، ويشغّل خطافات
  `load` الاختيارية على الخادم، ويعرض الكتل الفرعية، ويستدعي مكوّن `.astro`
  الخاص بك.
- **بيان JSON.** يستطيع المحررون والأدوات الأخرى قراءة القالب دون استيراد
  ملفات `.astro`.
- **البنية التحتية للتحرير.** عمليات المستندات وعلامات المعاينة وجسر المعاينة
  والنص الغني والإعدادات والترجمات.

## ما لا يفعله

لا تجلب الحزمة بيانات التجارة، ولا ترفع الصور، ولا تكتب في قاعدة البيانات، ولا
تستبدل Astro. إنها تتحقق من ما يُعطى لها وتعرضه. وتأتي قراءات التجارة من
[`@wocart/storefront`](/ar/sdk/storefront)؛ أما الحفظ فيخص المنصة.

<Callout type="info" title="هذا عقد القالب، لا محرك واجهة المتجر">
لقراءات الكتالوج والسلال وإتمام الطلب والمراجعات وسياق المتجر، استخدم
[`@wocart/storefront`](/ar/sdk/storefront). ويتلقى خطاف `load` كائن
`StoreClient` من تلك الحزمة على الخادم.
</Callout>

## التثبيت

```bash
npm install @wocart/theme @wocart/storefront
```

`@wocart/storefront` اعتماد نظير مطلوب: يستخدم سياق العرض `StoreConfig` الخاص
به، وتتلقى خطافات `load` كائن `StoreClient` الخاص به. وAstro 7 اعتماد نظير
اختياري، لا يلزم إلا لعارض `./astro`. والحزمة ESM فقط وتحتاج Node 22.12 أو أحدث
للأدوات.
