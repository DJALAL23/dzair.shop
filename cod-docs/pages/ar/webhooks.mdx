# Webhooks

يرسل الـ webhook أحداث الأعمال (Business Events) الخاصة بمتجرك إلى عنوان على خادمك لحظة وقوعها: طلب جديد، طلب مؤكَّد، تسليم إلى شركة توصيل، توصيل ناجح. يُرسَل كل حدث بطلب `POST` بصيغة JSON، موقَّعًا وفق مواصفة [Standard Webhooks](https://www.standardwebhooks.com/)، وتُعاد المحاولة إلى أن يقبله خادمك.

أما شركات التوصيل التي تبلّغ متجرك عن التسليمات فهي الاتجاه الآخر: اقرأ [Webhooks شركات التوصيل](/ar/carrier-webhooks).

## إضافة webhook

في لوحة التحكم افتح **التكاملات** من القائمة الجانبية واختر **إضافة webhook**، وأعطه اسمًا وعنوان URL لخادمك والأحداث التي يستقبلها. وعبر الـ API، `POST /api/event-consumers` بصلاحية `integrations:manage` (وتعرض `integrations:read` الـ webhooks وعمليات تسليمها):

```bash
curl -X POST http://localhost:8787/api/event-consumers \
  -H "X-API-Key: cod_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{"kind":"webhook","name":"Order system","url":"https://erp.example.dz/hooks/codflow","subscription":["order.*","shipment.delivered"]}'
```

يحتوي الرد على الـ webhook و**مفتاح التوقيع** الخاص به، `whsec_…`. لا يُعرض إلا هذه المرة: احفظه ضمن أسرار خادمك. وكل رد بعده يعرضه مُقنَّعًا.

- يجب أن يكون العنوان `https`، عامًا على الإنترنت (لا عنوان خاصًا أو محليًا أو محجوزًا)، بلا اسم مستخدم ولا كلمة مرور.
- للمتجر 10 webhooks على الأكثر.
- يستقبل الـ webhook الأحداث المسجَّلة بعد إضافته. ولإرسال أحداث أقدم إليه استعمل إعادة الإرسال (Replay، انظر أدناه).

يسمّي الاشتراك أنواع الأحداث بدقة (`order.confirmed`)، أو حسب الموضوع (`order.*`، `shipment.*`)، أو كلها (`*`). والموضوع أو `*` يشمل أيضًا الأنواع التي تُضاف إلى الكتالوج لاحقًا.

## ما يستقبله خادمك

كل إرسال هو طلب `POST` واحد إلى عنوانك:

| الترويسة | القيمة |
| --- | --- |
| `content-type` | `application/json` |
| `user-agent` | `CodFlow-Webhooks/1` |
| `webhook-id` | معرّف الحدث. هو نفسه في كل محاولة وكل إعادة إرسال. |
| `webhook-timestamp` | وقت إرسال هذه المحاولة، بثواني Unix. |
| `webhook-signature` | `v1,<signature>`، واحد لكل مفتاح توقيع، تفصل بينها مسافات. |

## التحقق من التوقيع

تحقّق من كل طلب قبل أن تتصرف بناءً عليه. التوقيع هو HMAC-SHA256 بترميز base64 للنص `<webhook-id>.<webhook-timestamp>.<الجسم الخام>`، ومفتاحه البايتات التي يرمّزها مفتاح التوقيع: الجزء الذي بعد `whsec_` بعد فكّ ترميز base64.

1. اقرأ الجسم **الخام** كما وصل. تحليل الـ JSON ثم إعادة كتابته يغيّر البايتات فلا يطابق التوقيع.
2. ارفض أي `webhook-timestamp` يبعد أكثر من خمس دقائق عن ساعتك، حتى لا يُعاد إرسال طلب مُعترَض لاحقًا.
3. اقبل الطلب إذا طابق أحدُ توقيعات `v1,` المفصولة بمسافات، بمقارنة ثابتة الزمن.

### Node.js

```js
import { createHmac, timingSafeEqual } from "node:crypto";

const TOLERANCE_SECONDS = 5 * 60;

/** Whether a request came from your store, signed with this Signing Secret. */
export function verifyWebhook(secret, headers, rawBody) {
  const id = headers["webhook-id"];
  const timestamp = Number(headers["webhook-timestamp"]);
  const signatures = headers["webhook-signature"];
  if (!id || !signatures || !Number.isInteger(timestamp)) return false;
  if (Math.abs(Date.now() / 1000 - timestamp) > TOLERANCE_SECONDS) return false;

  const key = Buffer.from(secret.slice("whsec_".length), "base64");
  const expected = createHmac("sha256", key).update(`${id}.${timestamp}.${rawBody}`).digest();
  return signatures.split(" ").some((entry) => {
    const [version, signature = ""] = entry.split(",");
    const given = Buffer.from(signature, "base64");
    return version === "v1" && given.length === expected.length && timingSafeEqual(given, expected);
  });
}
```

مرّر الجسم الخام نصًّا، مثلًا عبر `express.text({ type: "application/json" })`.

### PHP

```php
<?php

const TOLERANCE_SECONDS = 5 * 60;

/** Whether a request came from your store, signed with this Signing Secret. */
function verify_webhook(string $secret, array $headers, string $rawBody): bool
{
    $id = $headers['webhook-id'] ?? '';
    $timestamp = $headers['webhook-timestamp'] ?? '';
    $signatures = $headers['webhook-signature'] ?? '';
    if ($id === '' || $signatures === '' || !ctype_digit($timestamp)) return false;
    if (abs(time() - (int) $timestamp) > TOLERANCE_SECONDS) return false;

    $key = base64_decode(substr($secret, strlen('whsec_')), true);
    if ($key === false) return false;
    $expected = base64_encode(hash_hmac('sha256', "$id.$timestamp.$rawBody", $key, true));
    foreach (explode(' ', $signatures) as $entry) {
        [$version, $signature] = array_pad(explode(',', $entry, 2), 2, '');
        if ($version === 'v1' && hash_equals($expected, $signature)) return true;
    }
    return false;
}
```

الجسم الخام هو `file_get_contents('php://input')` (وفي Laravel ‏`$request->getContent()`)؛ ومرّر الترويسات بأسماء بأحرف صغيرة.

### Python

```python
import base64
import hashlib
import hmac
import time

TOLERANCE_SECONDS = 5 * 60


def verify_webhook(secret: str, headers: dict, raw_body: bytes) -> bool:
    """Whether a request came from your store, signed with this Signing Secret."""
    msg_id = headers.get("webhook-id", "")
    timestamp = headers.get("webhook-timestamp", "")
    signatures = headers.get("webhook-signature", "")
    if not msg_id or not signatures or not timestamp.isdigit():
        return False
    if abs(time.time() - int(timestamp)) > TOLERANCE_SECONDS:
        return False

    key = base64.b64decode(secret.removeprefix("whsec_"))
    signed = f"{msg_id}.{timestamp}.".encode() + raw_body
    expected = base64.b64encode(hmac.new(key, signed, hashlib.sha256).digest()).decode()
    return any(
        version == "v1" and hmac.compare_digest(expected, signature)
        for version, _, signature in (entry.partition(",") for entry in signatures.split(" "))
    )
```

الجسم الخام هو `request.get_data()` في Flask، أو `await request.body()` في FastAPI.

وتتحقق أي مكتبة Standard Webhooks من هذه الطلبات أيضًا، مثل `new Webhook(secret).verify(rawBody, headers)` مع حزمة `standardwebhooks`.

### تغيير مفتاح التوقيع

**تغيير مفتاح التوقيع** في لوحة التحكم، أو `POST /api/event-consumers/{id}/rotate-secret`، يعطي مفتاحًا جديدًا مرة واحدة. ولمدة 24 ساعة يحمل كل طلب توقيعًا بكل مفتاح، فانقل خادمك إلى الجديد خلالها ولن يُرفض شيء. بعدها لا يوقّع إلا المفتاح الجديد.

## أجب بسرعة

جوابك يحدّد ما يحدث بعد ذلك:

| يجيب خادمك | ما يفعله المتجر |
| --- | --- |
| أي `2xx` خلال 15 ثانية | تمّ التسليم. |
| `410 Gone` | يوقف هذا الـ webhook ولا يرسل إليه شيئًا حتى تعيد تشغيله. |
| غير ذلك: حالة أخرى، أو إعادة توجيه، أو لا جواب في الوقت، أو تعذّر الاتصال | يعيد المحاولة لاحقًا وفق الجدول أدناه. |

أجب بـ `2xx` بمجرد حفظ الحدث، ثم أنجز العمل. لا تُتَّبع إعادات التوجيه: أعطِ العنوان النهائي. وتُحترَم ترويسة `Retry-After` في الرفض، حتى يوم واحد.

## إعادة المحاولة والتكرار والترتيب

يُحاوَل تسليم كل إرسال 8 مرات. تنطلق المحاولة الأولى بعد ثوانٍ من الحدث، وكل فشل ينتظر قبل التالية:

| المحاولة | الانتظار بعد السابقة |
| --- | --- |
| 1 | لا انتظار: بعد ثوانٍ من الحدث |
| 2 | 5 دقائق |
| 3 | 30 دقيقة |
| 4 | ساعتان |
| 5 | 6 ساعات |
| 6 | 12 ساعة |
| 7 | 24 ساعة |
| 8 | 24 ساعة |

بعد آخر فشل يصير الإرسال **متخلًّى عنه**: يبقى في لوحة التحكم حيث يمكنك إعادة محاولته. تجري إعادات المحاولة كل خمس دقائق، فقد يطول الانتظار حتى خمس دقائق إضافية. والـ webhook الذي تفشل كل محاولاته طوال ثلاثة أيام يُوقَف؛ أعد تشغيله من لوحة التحكم بعد إصلاح خادمك.

التسليم **مرة واحدة على الأقل** وبلا **ترتيب مضمون**:

- قد تستقبل الحدث مرتين. احفظ `webhook-id` ما عالجته وتجاهله في المرة الثانية.
- قد يصل حدثان بغير ترتيبهما. رتّبهما حسب `sequence`، أو حسب `occurredAt` لوقت وقوعهما.

## الإرسال من جديد

من **التكاملات ← الإرسالات** في لوحة التحكم، أو عبر الـ API:

- **أعد المحاولة** لإرسال واحد: `POST /api/event-deliveries/{id}/retry`.
- **أعد الإرسال…** لمجال من الأحداث: `POST /api/event-consumers/{id}/replay` مع `fromSequence` و`toSequence`، بحد أقصى 1000 حدث في كل مرة. وتُشمل الأحداث المسجَّلة أثناء توقف الـ webhook.

الحدث المُرسَل من جديد يحتفظ بمعرّفه، فيتعرّف عليه خادمك.

## الأحداث التجريبية

**إرسال حدث تجريبي** في لوحة التحكم، أو `POST /api/event-consumers/{id}/test` مع `type` اختياري، يرسل فورًا إلى خادمك مثالًا لنوع حدث، موقَّعًا كغيره، ويعرض ما أجاب به خادمك. للحدث التجريبي `sequence` يساوي `0` و`id` يبدأ بـ `test_`؛ وهو ليس في سجل أحداثك.
